## 2. CCC는 무엇인가, 목표는 어디에 끼는가

**CCC(Case Context Companion)**는 비영리 기관의 금전 지원 사업에서 당사자(지원 대상자) 상담을 인테이크부터 종결까지 기록하고, AI가 정리한 누적 맥락을 **상담 5분 전에 한 화면(15초 페이지)으로** 보여주는 웹앱이다. 핵심 가치는 기록이 아니라 브리핑이다.

상담 워크플로우: ① 당사자 등록(동의 2종, 개인정보는 암호화 금고 격리) → ② 인테이크(고정 질문지 4부로 첫 면담 기록) → ③ 본 상담 회기 반복(일정 등록 → 15초 페이지로 준비 → 상담 → 상담 기록 작성 → 녹음이 있으면 AI 정리를 실무자가 검토·승인) → ④ 종결.

**AI 불변 규칙**: AI는 판단하지 않는다(R5). 목표 문구를 정하는 것은 실무자와 당사자이고 AI는 재료로 쓰거나 근거를 발췌해 제안할 뿐이다. 실무자가 직접 쓴 것(목표 포함)은 저장 즉시 공식 기록이다(승인 절차 없음, D5·R2).

## 3. 확정된 목표 모델

### 3-1. 위계: 전체 > 세부 > 세션

구 결정 D33의 위계(전체 > 세션 > 세부)를 뒤집어 **전체 > 세부 > 세션**으로 확정했다. 세부 목표가 케이스 수준에 지속되고, 회기의 세션 목표가 거기 연결된다. DB의 연결 방향(`schedule_session_goals.case_goal_id` → `goals.id`)은 이미 이 모양이라 **구조 변경이 없다.**

층은 3층, 이름은 용어집 정본(전체 목표·세부 목표·세션 목표) 유지. Q의 실무 표현(총괄·상위 / 하위·실행 / 과정·과제)은 유의어로 등록.

### 3-2. 층 정의 (확정, 2차 검수의 빈 행 5개 반영)

| | 1층: 전체 목표 | 2층: 세부 목표 | 3층: 세션 목표 |
|---|---|---|---|
| 뜻 | 이 당사자와 무엇을 향해 가는지 한 문장 | 그 방향을 이루기 위한 구체 실행 목표 | 이번 회기에서 다룰 것 |
| 붙는 곳 | 케이스 | 케이스 | 회기(일정) |
| 개수 | 1개 | 활성 1~3개 | 회기당 여러 개 |
| 수립 시점 | 인테이크 | 본 상담 1회차 | 매 회기(일정 등록 때) |
| 권한 | 담당 실무자, 기관 관리자 | 담당 실무자, 기관 관리자 | 담당 실무자, 기관 관리자 |
| 수정 | 언제든 (케이스 활성 동안) | 언제든 (케이스 활성 동안) | **일정 시작 시각 전까지.** 미루면 다시 열림, 취소된 일정은 잠긴 기록 |
| 이력 | 있음 (최초 작성 포함, 이전 문구·수정자·시각) | 있음 (동일) | 없음 (회기 전 자유 수정) |
| 연결 | 해당 없음 (케이스당 1개라 암묵) | 전체 목표 아래 (같은 케이스면 자동) | **활성** 세부 목표에만 연결 가능 (복수·미연결 허용). 부모가 닫혀도 기존 연결 유지 |
| 닫기 | 해당 없음 (문구 교체로 충분) | 종료 + 사유(달성/중단/재설정). **재개 불가**, 필요하면 새로 만들기 | 해당 없음 (회기와 함께 지나감) |
| 점수 | 없음 | 없음 (GAS 계속 보류) | 없음 |
| 필수 | 강제하지 않음 | 강제하지 않음 | 강제하지 않음 |

경계 규칙: 방향이 같고 표현만 다듬는 것은 **수정**, 목표 자체가 바뀌는 것은 **닫고(재설정) 새로 만들기**. 운영 지침과 화면 도움말에 넣는다. 케이스가 종결되면 세 층 모두 다른 기록과 같이 잠긴다(전체 목표는 이미 코드로 강제 중).

### 3-3. DB 매핑

| 층 | 저장 | 변경 |
|---|---|---|
| 전체 목표 | `support_cases.overall_goal` | 없음 |
| 세부 목표 | `goals` 표 (`closed_reason` 칸 재사용) | **수정 금지 트리거(goals_title_immutable) 제거 마이그레이션 1건** |
| 세션 목표 | `schedule_session_goals` | 없음 (수정 기능은 게이트웨이 함수 신설) |
| 세션 목표 폴백 | `record_details.sessionGoalNote` | 없음 |

새 표 0건, 트리거 제거 1건. 단 **수정 이력의 저장 방식에 따라 표 1건이 더해질 수 있다**: 감사 기록(audit_log) detail 확장이 1후보(추가 표 없음), 감사 조회 접근 규칙과 충돌하면 전용 이력 표(새 표 1건). 이 선택은 구현 첫 티켓에서 맨 앞에 확정한다(2차 검수 반영). 감사 기록이 이미 수정자·시각·칸 단위 기록을 남기고 있어, 추가로 필요한 것은 이전 문구 보존뿐이다.

### 3-4. AI 연결

- 목표는 AI 제안(15초 페이지 영역 ①)의 재료다. 전체 목표 미설정이어도 제안을 차단하지 않고 안내 한 줄만 붙인다(닫을 수 있게, 케이스 단위로 닫힘 상태 저장).
- 재료 우선순위: 전체 목표가 있으면 으뜸 재료. 인테이크의 지원욕구·지원방향(선택값이라 마스킹 부담 없음)은 기본으로 깐다.
- 자유 글 목표는 마스킹 스냅샷 게이트(D57)를 거친 것만 AI 사업자로 나간다. **워크인 회차의 폴백 자유 글도 같은 조건으로 포함한다** (빠지면 워크인 상담만 AI 맥락에서 빠진다). **수정 이력의 이전 문구는 AI 재료에서 제외한다** (바뀐 시각 정보만 준다).
- 목표 문장은 짧아 마스킹이 어긋나기 쉬우므로 마스킹 품질 검사에 '짧은 목표 문장' 유형을 추가한다.
- AI는 목표 문구를 만들지 않는다(R5).

## 4. 단계별 화면 설계 (확정)

| 화면 | 변화 |
|---|---|
| **인테이크 기록** | 전체 목표 칸 신설 + 안내 문구 "첫 상담에서 합의가 어려우면 비워 두세요. 본 상담에서 채워도 됩니다". 질문지의 지원욕구·지원방향을 칸 옆에 참고 표시. 칸은 질문지 항목이 아니라 화면 기능이므로 "전 항목 필수"의 예외. 목표 합의 거부는 4부 자유 글에 적는 운영 지침 |
| **상담 기록 작성** | 세부 목표 구획 신설: 입력(1회차), 수정(이후 회기), 닫기(종료+사유). 세션 목표 읽기와 '이번 상담에서 확인할 것' 자유 글은 현행 유지. PR #91의 목표 연결 선택창은 만들지 않음 |
| **일정 등록 위저드** | 세션 목표 입력 유지. 라벨 "케이스 목표 연결"을 "세부 목표 연결"로 교체, 선택창에는 활성 세부 목표만. 인테이크 경로에 목표 입력을 되살리지 않음(PR #89 유지) |
| **세션 목표 수정** | 일정 시작 시각 전까지 고칠 수 있는 수정 기능 신설(현재는 등록 후 수정 불가) |
| **15초 페이지** | 전체 목표 카드 유지(보조 입력·수정 자리). 카드 아래 활성 세부 목표 기본 펼침 최대 3줄(말줄임 규칙은 티켓에서). 영역 ①에서 부모가 닫힌 세션 목표는 부모 이름 흐리게 병기. AI 안내 한 줄(전체 목표 미설정 시) |
| **당사자 정보 (허브)** | 목표 트리 전체(전체 > 세부 > 세션) 구획 신설, 케이스별 구분. 닫힌 세부 목표는 흐리게 + '이력 보기' |

경계 확정: 상담 1건 = 케이스 1개 유지. 한 자리에서 두 사업 이야기가 나오면 사업별로 기록을 따로 남긴다(운영 지침).

## 7. 구현 티켓 초안 (발행 순서대로)

1. **이력 저장 방식 확정 + 마이그레이션**: 감사 기록 확장 vs 전용 이력 표 결정(맨 앞, 뒤 티켓들이 걸려 있음) + `goals_title_immutable` 트리거 제거
2. **게이트웨이 정비**: `createGoal`/`closeGoal` 재사용(사유 선택값 달성/중단/재설정 검증 추가, 승계 파라미터 제거, 재개 불가), 세부 목표 수정 함수 신설(이력 보존, 종결 케이스 잠금), 세션 목표 수정 함수 신설(일정 시작 시각 잠금, 활성 세부 목표만 연결), 전체 목표 수정에 이력 보존 추가
3. **인테이크 기록 화면**: 전체 목표 칸 + 참고 표시 + 안내 문구
4. **상담 기록 작성 화면**: 세부 목표 구획(입력·수정·닫기 + 수정/재설정 경계 도움말)
5. **일정 위저드**: 라벨 교체, 활성 목표만 선택창에, 세션 목표 수정 진입점, 미래 회기 연결된 목표 닫기 알림
6. **15초 페이지**: 세부 목표 3줄(말줄임 규칙 포함) + AI 안내 한 줄(케이스 단위 닫힘 저장) + 부모 닫힘 흐리게 병기
7. **당사자 허브**: 목표 트리 구획 + 이력 보기 (티켓 1의 저장 방식 확정에 의존)
8. **정리**: 죽은 '종료+신설' 저장 코드·API 제거
9. **파이프라인**: AI 재료 우선순위 배선(워크인 폴백 포함, 이전 문구 제외) + 마스킹 품질 검사 '짧은 목표 문장' 유형
10. **운영 지침**: 목표 합의 거부 기록법, 두 사업 겹칠 때 기록 분리, 수정 vs 재설정 경계
