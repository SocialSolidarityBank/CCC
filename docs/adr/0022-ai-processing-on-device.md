# AI 처리는 전부 처리 장비에서 돈다

브리핑(D45)이 요구하는 AI 산출물을 실제로 만들려면 LLM 사업자를 부르는 코드가 필요한데, 그 자리를 R3(개인정보 2단 방어)가 정한다. 2차 마스킹(대화 속 제3자 인명·질병명 NER)은 **처리 장비에만** 있고(`apps/pipeline/ccc_pipeline/masking.py`), Workers 안의 마스킹은 1차(금고 등록값 결정론 치환, `maskRegisteredPii`)뿐이다. 내용 불일치 검출은 **수기 메모 저장 시점**에도 돌아야 하는데 그 경로에는 녹음도 파이프라인 작업도 없다 — 그리고 수기 메모에는 금고에 등록되지 않은 제3자 이름("아들 김철수가…")이 적힐 수 있어 1차 치환으로는 잡히지 않는다. 그래서 **오디오가 없는 텍스트 작업도 처리 장비가 맡는다**(2026-07-31 Q 결정). Workers가 Claude를 직접 부르는 길은 R3를 "수기 메모는 1차만"으로 완화해야 성립하므로 택하지 않았다.

## 착수 전 실측 — 껍데기는 이미 다 있었다

레포 전체에 **LLM 사업자를 부르는 코드가 0건**이다(`anthropic` 문자열 0건, API 워커의 `fetch` 는 Access 인증서 조회와 알림 웹훅 둘뿐). 반면 그 주변 장치는 전부 구현돼 있다 — 마스킹된 원문 스냅샷(`ai_masked_source_snapshots`), AI 사업자 등록·활성화(`ai_provider_configs`·`ai_provider_activations`), 초안 버전·승인·근거 검증(`ai_draft_versions`·`ai_review_events`·`grounding_status`), 핵심 한 줄(0025), 구조화 제안(0026), 내용 불일치 저장·처리 3종(0027). **빠진 것은 어댑터 하나**다. `purge_due`·`consent_text_ai_at` 때와 같은 모양 — 그릇은 있고 붓는 사람이 없다.

## 함께 정한 것

**일감 큐를 하나 더 둔다.** 지금 일감 목록은 `audio_r2_key IS NOT NULL` 로 걸러서(`gateway.ts` `listPipelineJobs`) 수기 메모 회차가 장비 눈에 보이지 않는다. 기존 녹음 큐는 그대로 두고 **텍스트 일감 표를 신설**해, 기록이 공식화될 때마다(수기 메모 저장·AI 정리 승인) 한 행씩 쌓는다. 장비는 같은 폴링에서 두 큐를 함께 가져간다. 오디오 큐의 상태(`ai_status`)를 재사용하지 않는 이유는 불일치 재검출이 **이미 승인된 회차도 다시 일감으로 만들기** 때문이다 — 그 회차를 '대기 중'으로 되돌리면 승인 이력과 상태가 부딪힌다. `ai_work_items` 를 큐로 쓰지 않는 이유는 `UNIQUE (session_id, kind)` 가 같은 회차의 재검출을 막고, 그 제약이 지금 승인 경계의 안전장치이기 때문이다. 무폴링 감시(D8)는 두 큐 합산으로 넓힌다.

**동의 배선을 잇는다.** 지금 동의 확인 장치가 서로 모르는 채 둘 있다 — 화면에서 받는 D49 동의 2종(`support_cases.consent_*_at`)은 **녹음 업로드만** 막고(`gateway.ts` `assertRecordingRegistrationAllowed`), AI 초안 생성을 막는 것은 별도 표 `pilot_text_ai_consent_evidence`(0026 트리거가 생성 초안마다 최신 행을 요구)다. 지금 상태로 LLM 호출을 붙이면 동의를 다 받은 케이스에서도 트리거가 초안 저장을 거부한다. **부품은 끝까지 있는데 화면만 없다** — API 경로(`request-handler.ts` `pilot-text-ai-consent`)도, 서버 액션(`actions.ts` `recordPilotTextAiConsentAction`)도 구현돼 있으나 **어떤 화면도 그 액션을 호출하지 않는다**(실측: 액션 이름이 `actions.ts` 밖에서 0건). 게다가 그 액션은 문안 버전·해시·근거 참조·근거 해시·효력 시각 5개를 요구하는데, 지금 동의 등록 화면은 그중 어느 것도 만들지 않는다. **화면에서 ②(AI를 활용한 녹취기록)를 체크하는 순간 근거 표에 한 행이 자동으로 쌓이게** 잇는다 — 그 시점의 동의 문안 버전·해시를 함께 남기므로, 법률 검토가 재개될 때(D46 동결) "어느 문안에 동의했는가"에 답할 수 있다. 화면 변경도, 실무자가 새로 할 일도 없다.

**AI 호출은 승인 단위로 둘로 나눈다.** 승인 대상(핵심 한 줄 + AI 제안 3개)이 한 호출, 내용 불일치가 한 호출이다. 재료 범위가 다르고(한 회차 vs 전 회차 대조), 한쪽이 실패해도 다른 쪽은 나오며, 프롬프트 버전(`ai_draft_versions.prompt_version`)을 따로 굴릴 수 있다. 불일치는 어느 쪽이 맞는지 판단하지 않으므로(R5) 승인 대상이 아니고, 저장 즉시 브리핑에 뜬다.

## 결과

- 처리 장비가 꺼져 있으면 수기 메모의 AI 정리도 다음 영업일까지 안 나온다(D8 SLA 안이며, 브리핑은 수기 메모 폴백으로 계속 동작한다 — D5).
- `docs/api-contract-pipeline.md` 에 텍스트 작업 상태·엔드포인트를 추가해야 한다. 마이그레이션 1개(텍스트 일감 표) 추가.
- LLM 호출 코드가 장비 한 곳에만 생기므로, 사업자를 바꿀 때 고칠 자리도 한 곳이다.
