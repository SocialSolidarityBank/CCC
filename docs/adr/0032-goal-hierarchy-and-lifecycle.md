# ADR-0032: 목표 위계·수립 흐름 재정의 (D62)

- 상태: 승인 (2026-08-09 그릴링, 외부 검수 2회 반영)
- 결정자: Q
- 관련: D33(ADR-0013) · D43 · D45(ADR-0018) · D42 · D12 · D47(ADR-0019) · D57(ADR-0027) · PR #89 · PR #91
- 검수 기록: 설계안 `PRD/goal-model-design-review-2026-08-09.md`, 검수 핸드오프 1·2차 `artifacts/goal-model-review-2026-08-09/`

## 결정 요약

목표는 3층(전체 > 세부 > 세션)이고, 상담 단계에 맞춰 세 번에 나눠 수립한다. 인테이크에서 전체 목표, 본 상담 1회차에서 세부 목표, 매 회기 세션 목표. 어느 층도 입력을 강제하지 않는다. 전체·세부 목표는 언제든 수정할 수 있되 이전 문구를 이력으로 남기고, 세션 목표는 회기 전까지만 고칠 수 있다. 세부 목표 층은 문구·연결·상태 범위로 부활하고 GAS(목표달성척도)는 계속 보류한다.

배경: 2026-08-08~09에 화면에서 목표 입력을 걷어내는 변경 2건(PR #89, PR #91 보류)이 들어가 "목표를 만들 경로"가 앱에 거의 없어졌고, 목표 층을 건드리는 결정들(D33·D42·D43·D45·D47)이 서로 어긋난 채 쌓여 있었다. 이 ADR이 그 어긋남을 한 번에 정리한다.

## 세부 결정

### 1. 위계 재정렬: 전체 > 세부 > 세션 (D33 층 순서 대체)

구 D33의 위계는 전체 > 세션 > 세부(세부 목표가 세션 목표 아래)였다. 새 위계는 **전체 > 세부 > 세션**이다. 세부 목표는 케이스에 붙어 여러 회기 지속되는 구체 실행 목표이고, 회기의 세션 목표가 거기에 연결된다.

DB는 이미 이 방향이다. 세션 목표 표(`schedule_session_goals`)의 `case_goal_id`가 케이스 수준의 `goals` 표를 가리키고 있어 **구조 변경이 없다**. 문서(D33, 용어집)만 어긋나 있었다. 용어집의 "세션 목표는 전체 목표의 하위로 연결" 서술을 "세부 목표의 하위로 연결"로 바로잡았다.

전체 목표는 케이스당 1개라 세부 목표와 명시 연결이 필요 없다(같은 케이스면 자동으로 그 아래다).

용어는 기존 정본을 유지한다(전체 목표·세부 목표·세션 목표). Q의 실무 표현(총괄·상위 / 하위·실행 / 과정·과제 목표)은 용어집에 유의어로 등록했다. 4층 분리(하위 목표와 실행 목표를 가르는 안)는 구조만 깊어지고 15초 훑기와 멀어져 기각.

### 2. 수립 시점 3단계와 입력 화면

| 층 | 수립 시점 | 입력 화면 |
|---|---|---|
| 전체 목표 | 인테이크(당사자와 대화로 합의) | **인테이크 기록 화면에 칸 신설**. 15초 페이지의 전체 목표 카드는 보조 입력·수정 자리로 유지 |
| 세부 목표 | 본 상담 1회차 | **상담 기록 작성 화면에 세부 목표 구획 신설**. 이후 회기에도 같은 자리에서 수정 |
| 세션 목표 | 매 회기(일정 등록 때) | 일정 등록 위저드(현행 유지) |

- D42("인테이크 화면에서 목표 입력 전부 제거")의 부분 개정이다. 전체 목표 1칸만 되살리고, 세부 목표·GAS 기준 입력은 계속 없다.
- D45("첫 상담에서 정한 뒤 15초 페이지 카드에 적는다")의 개정이다. 주 입력 자리가 인테이크 기록으로 옮겨 가고 카드는 보조가 된다. 15초 페이지는 상담 전에 여는 준비 화면이라 "첫 상담에서 정한 뒤 바로 적는" 흐름을 지원하지 못했다.
- 인테이크의 전체 목표 칸은 질문지(D41 정본) 항목이 아니라 화면 기능이다. "전 항목 필수" 원칙의 예외이며 무응답 선택지도 없다(비워 두면 그냥 빈 것). 칸 옆에 "첫 상담에서 합의가 어려우면 비워 두세요. 본 상담에서 채워도 됩니다" 안내를 붙인다(검수 반영: 첫 만남이 위기 상황인 경우가 많아 확정 문장 압박을 줄인다).
- 질문지의 '1·2순위 지원욕구'(3-1)와 '주요 지원방향'(4-3)은 그대로 두고 역할을 가른다. 지원욕구는 당사자가 말한 필요(선택값), 지원방향은 실무자의 다음 단계 판단(선택값), 전체 목표는 당사자와 합의한 방향(문장). 전체 목표 칸 옆에 두 선택값을 참고로 표시해 같은 것을 다시 묻지 않는다.
- 일정 위저드의 인테이크 경로에 목표 입력을 되살리지 않는다(PR #89 유지). 일정을 잡는 시점은 당사자를 만나기 전이다.
- 목표 합의를 당사자가 거부한 경우는 별도 입력칸 없이 인테이크 4부(상담 정리) 자유 글에 적는 운영 지침으로 처리한다(검수 반영).
- 권한은 세 층 모두 **담당 실무자와 기관 관리자**다. 현행 게이트웨이의 검사(전체 목표 `setSupportCaseOverallGoal`, 세부 목표 `createGoal`/`closeGoal`의 케이스 접근 검사)와 동일해 코드 변경이 없다(2차 검수 확인 5 반영).

### 3. 세부 목표 부활 범위: 문구·연결·상태만, GAS는 계속 보류 (D43 부분 해제)

`goals` 표를 다시 쓰되 제목·상태·종료 사유·연결만 쓴다. GAS 점수( `session_goal_scores`, `ai_gas_evidence`, `scale_criteria`)는 D43 보류 그대로다. 구현 시 점수 관련 칸·제약이 빈 값 저장을 막지 않는지 확인하고, 화면에 점수의 흔적이 보이지 않아야 한다(검수 반영). 활성 개수 상한은 케이스당 3개(`MAX_ACTIVE_GOALS`) 유지.

### 4. 수정 규칙: 수정 금지 폐지, 이력 보존 (D12 대체)

- D12의 "세부 목표 문구 수정 금지, 종료+신설만"을 폐지한다. 수정 금지의 근거는 GAS 점수 이력의 연속성 보존이었는데, GAS가 보류인 동안 점수가 안 붙는 문구는 고쳐도 깨질 이력이 없다. DB 트리거 `goals_title_immutable`을 제거한다(**마이그레이션 1건**. 설계안 초안의 "마이그레이션 0건"은 "새 표 0건, 트리거 제거 1건"으로 정정. 검수 반영). GAS를 재개하는 시점에 수정 금지 재도입 여부를 다시 정한다.
- **전체 목표와 세부 목표는 수정 시 이전 문구·수정자·시각을 보존한다**(덧붙이기 전용, 쌓인 줄은 고치거나 지우지 않는다). 최초 작성도 이력의 첫 줄로 남겨 "누가 처음 정했는지"가 함께 남는다(2차 검수 반영). 세션 목표는 이력이 없다(회기 전 자유 수정이므로). 이유 셋(검수 반영): 지원금이 걸린 사업에서 목표 변경은 책임 소재가 걸린 정보다 / 인테이크에서 합의한 원문이 사라지면 안 된다 / 내용 불일치 감지가 목표 변경 시점을 알아야 헛짚지 않는다. 화면에는 기본으로 숨기고 '이력 보기'로만 연다. 케이스 이관 시 새 담당이 "누가 언제 정했고 고쳤는지"를 볼 수 있게 된다.
- 이력 저장 방식은 **구현 첫 티켓(마이그레이션)과 함께 맨 앞에서 확정한다**(2차 검수 반영. 뒤 티켓들이 이 선택에 걸려 있다). 감사 기록(audit_log)이 이미 수정자·시각을 남기므로 detail에 이전 문구를 담는 확장이 1후보, 감사 조회 접근 규칙과 충돌하면 전용 이력 표(이 경우 새 표 1건이 더해진다).
- **'수정'과 '닫기(재설정)'의 경계**(2차 검수 반영): 방향이 같고 표현만 다듬는 것은 수정, 목표 자체가 바뀌는 것은 닫고(사유 '재설정') 새로 만든다. 운영 지침과 화면 도움말에 넣는다.
- **케이스 종결 후에는 수정할 수 없다.** 전체 목표는 이미 코드가 활성 케이스에서만 수정을 허용하고, 세부 목표도 같은 규칙을 따른다(2차 검수 반영).

### 5. 세부 목표를 닫는 절차 (신설. 검수가 찾은 빈 곳)

활성 1~3개 상한이 있는데 닫는 절차가 없으면 상한이 찬 뒤 새 목표를 만들 수 없다.

- 상태는 DB 그대로 **활성/종료 2종** + 닫을 때 **사유 선택(달성/중단/재설정)**. 사유는 기존 `closed_reason` 칸에 저장하므로 마이그레이션이 없다(2차 검수 확인 1: 칸 존재를 코드로 확인). 상태 3종(활성/달성/중단) 안은 같은 정보를 상태 값 추가로 얻는 것이라 기각. 화면에서는 사유를 배지로 보여줘 3종처럼 읽힌다.
- 바꾸는 자리는 상담 기록 작성 화면의 세부 목표 구획.
- **닫은 목표는 다시 열지 않는다**(2026-08-09 Q 확정). 같은 목표가 다시 필요해지면 같은 문구로 새로 만든다. 되돌리기를 허용하면 닫은 사유가 지워지거나 상태 변경 이력이 따로 필요해져 단순함이 깨진다.
- 닫힌 목표는 당사자 정보 허브에서 흐리게 보여주고, 15초 페이지에는 활성만 올린다.
- **닫힌 목표에 연결된 세션 목표**(2차 검수 반영): 기존 연결은 그대로 둔다(그날 계획의 기록이다). 연결 선택창에는 활성 세부 목표만 올린다. 아직 오지 않은 회기가 연결된 목표를 닫으려 하면 알림 한 줄을 띄운다. 15초 페이지 영역 ①에서 부모가 닫힌 세션 목표는 부모 이름을 흐리게 병기한다.
- 구 '종료+신설' 특수 흐름은 만들지 않는다. 수정이 자유로워져 "문구를 바꾸려고 닫는" 경우가 사라지므로, 닫기는 순수하게 달성·중단·재설정의 기록이다. D47 이후 죽어 있던 '목표 종료+신설' 저장 코드와 API, `closeGoal`의 승계(successor) 파라미터는 제거한다. 재설정으로 닫은 옛 목표와 새 목표 사이에 승계 연결을 두지 않는 것은 단순함을 위한 선택이며 알고 감수한다(2차 검수 반영).

### 6. 세션 목표: 회기 전까지 수정, 후 잠금

- 상담 전에는 자유롭게 고치고(일정 잡을 때 대충 적었다가 상담 직전에 다듬는 흐름), **일정 시작 시각이 지나면** 그날의 계획 기록으로 잠근다(2026-08-09 Q 확정). 일정을 미루면 새 시각까지 다시 열리고, 취소된 일정의 세션 목표는 잠긴 기록으로 남는다. 현재는 등록 후 수정 기능 자체가 없으므로 **수정 기능 신설**이 따라온다. 무기한 수정 안은 계획 기록의 사후 수정이라 기각.
- 세부 목표 연결 선택창은 유지하고 라벨 "케이스 목표 연결"을 "세부 목표 연결"로 바로잡는다. 세부 목표 층이 살아나므로 항상 비어 있던 선택창 문제가 해소된다.
- **소급 연결 불가를 알고 감수한다**(검수 반영): 세션 목표를 먼저 만들고 세부 목표를 나중에 만든 경우, 회기가 지난 세션 목표를 새 세부 목표에 소급 연결할 수 없다.
- 이원 구조 유지: 일정에 붙는 세션 목표가 정본, 일정 없이 쓴 회차(워크인)는 기록지의 '이번 상담에서 확인할 것' 자유 글이 폴백. 폴백 칸 라벨은 목표가 아닌 현행 문구를 유지해 층 혼동을 막는다.

### 7. AI 연결: 재료이지 게이트가 아니다

- 목표는 AI 제안(15초 페이지 영역 ①)의 재료다. **전체 목표 미설정이어도 제안을 차단하지 않고** "전체 목표를 설정하면 제안이 더 정확해집니다" 안내 한 줄을 붙인다(닫을 수 있게, 매번 뜨지 않게). Q 원문 "설정을 해야만 정확한 AI의 조언"의 '해야만'은 차단이 아니라 이 안내로 확정했다(2026-08-09 Q). 차단 안은 입력 강제 없음 원칙과 수기 폴백으로도 서비스가 도는 D8의 정신과 충돌해 기각.
- 재료 우선순위: 전체 목표가 있으면 으뜸 재료로 삼고, 인테이크의 지원욕구·지원방향(선택값이라 마스킹 부담 없음)을 기본으로 깐다. 셋이 서로 다른 말을 할 때 AI 제안이 흔들리지 않게 한다.
- 자유 글 목표는 다른 자유 글과 똑같이 마스킹 스냅샷 게이트(D57)를 거친 것만 AI 사업자로 나간다. **일정 없이 쓴 워크인 회차의 폴백 자유 글('이번 상담에서 확인할 것')도 같은 조건으로 AI 재료에 포함한다**(2차 검수의 정본 누락 지적 반영. 빠지면 워크인 상담만 AI 맥락에서 빠진다). 목표 문장은 짧아 앞뒤 맥락이 없고 마스킹이 어긋나기 쉬우므로, **마스킹 품질 검사에 '짧은 목표 문장' 유형을 추가한다**(검수 반영).
- **수정 이력의 이전 문구는 AI 재료에 넣지 않는다**(2차 검수 반영). 내용 불일치 감지에는 목표가 바뀐 시각 정보만 주면 충분하고, 이전 문구까지 주려면 그것도 마스킹을 거쳐야 해서 일이 커진다.
- AI는 목표 문구를 만들지 않는다(R5의 연장). 정하는 것은 실무자와 당사자다.

### 8. 노출 규칙

- 당사자 정보 허브: 목표 트리 전체(전체 > 세부 > 세션)를 케이스별로 보여주는 구획 신설.
- 15초 페이지: 전체 목표 카드 아래 활성 세부 목표를 **기본 펼침 압축 한 줄씩, 최대 3줄**. 눌러야 펼쳐지는 접힘은 금지(15초 훑기에서 한 번 더 눌러야 보이는 정보는 없는 정보다. 검수 반영). 긴 문구의 말줄임 규칙은 구현 티켓에서 정한다. 화면이 실측으로 길어지면 그때 당사자 정보로 물린다.
- 각 단계 화면은 그 단계의 목표 중심으로: 인테이크 기록은 전체 목표, 상담 기록 작성은 세부 목표 구획과 세션 목표(읽기), 일정 위저드는 세션 목표.

### 9. 경계: 상담 1건 = 케이스 1개 유지

한 번의 상담이 두 사업(케이스)에 걸치는 실무는 없거나 드물다(2026-08-09 Q 확인). 혹시 그런 자리가 생기면 사업별로 기록을 따로 남기는 운영 지침으로 처리한다. 구조 변경 없음.
