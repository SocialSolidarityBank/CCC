# ADR-0030: 아웃라인 카드 전면 통일 — 그림자 폐지·전면 컴포넌트화·여백 3단·호버 테마 반전 (D60)

- 상태: 채택 (2026-08-05 Q 지시)
- 관련: D60 · DESIGN.md §3-2·§3-4·§5 개정 · ADR-0029(D59 결정 1 대체) · ADR-0028(D58)

## 배경

2026-08-05 Q 가 트랙 B(본문 카드 정비) 진행 중 방향을 바꿨다. 레퍼런스는
Infisical·Cloudflare·Vercel·Supabase 대시보드 — 전부 **그림자가 아니라 선(아웃라인)으로
경계를 만드는** 화면이다.

1. 카드(그림자 상자)와 플랫 구획(D59)이 섞여 "강조는 되는데" **컴포넌트화가 안 돼
   여백 관리가 어려웠다** — 화면마다 손 마크업(인라인 스타일 상자·복사한 카드 CSS)이
   제각각의 패딩·간격을 가졌다.
2. 선택/비선택의 구분이 카드마다 다르게 읽혔다.
3. 라이트/다크 테마에서 호버·선택의 색 관계가 규칙 없이 갈렸다.

## 결정 1 — 아웃라인 카드 계약 (그림자 폐지)

- `.surface-card` 에서 `--shadow-soft` 를 뺀다. 본문 흐름 안의 모든 표면(카드·HERO·
  리스크 배너·안내줄·리스크 항목 행)은 **선 2종**만으로 선다:
  - **비선택 = 회색 `--line` 1px**
  - **선택·활성 = `--gradient-brand` 1px** (기존 `[data-selected]`·`[aria-current]`·`[open]` 어휘 그대로)
- `--shadow-soft` 는 **본문 흐름 밖으로 떠 있는 층**(팝오버·드롭다운·스티키 헤더)에만 남는다.
  모달은 `--shadow-modal` 그대로. 본문 카드가 그림자를 나눠 가지면 정작 떠 있는 층이 뜨지 않는다.
- 프라이머리 버튼의 그림자는 버튼 규칙 구간(트랙 C 범위)이라 이번에 건드리지 않았다 — 후속 검토.
  **후속 종결(2026-08-06)**: 프라이머리 버튼 그림자도 뺐다. 버튼도 본문 흐름이고, 일반과
  강조의 구분은 면(채운 그라데이션 vs 흰 면 + 아웃라인)이 이미 만든다.

## 결정 2 — 전면 카드 컴포넌트화 (D59 결정 1 대체)

- **D59 의 "읽기 구획은 플랫" 규칙을 대체한다.** 브리핑 3영역·미해결 액션·전체 목표 줄
  (브리핑·기록)·설정 구획·전체 일정 날짜 묶음이 전부 카드로 돌아온다. D59 가 잡던 답답함의
  원인(그림자 상자 나열)은 결정 1 이 제거했으므로 아웃라인 카드 나열은 상자 더미로 읽히지 않는다.
- **본문 구획은 전부 컴포넌트를 거친다**: 일반 카드 = `WireCard`, 접힘 구획 = `WireCardDetails`
  (신설 — 네이티브 details 위에 카드 계약, 펼침 = 활성 그라데이션 테두리, D47 과 같은 어휘),
  안내줄 = `WireCard tone="info"`(블루 tint 면). 손으로 카드 div 를 그리지 않는다.
- 이번에 걷어낸 손 카드: 브리핑 HERO 손 마크업(→ ParticipantHeroCard 공통 부품), 안내줄 2종
  인라인 스타일(draft-notice·intake-saved-notice), 인테이크 위저드 소절 상자(panelStyle 6곳),
  카드 계약 CSS 복사 3벌(`.panel`/`.schedule-form`·`.record-sticky` 3종 — 마크업 `.surface-card` 로 통일).
- **유지되는 D59 항목**: 카드 안 카드 금지(하위 묶음은 `--line` 구분선) · 가명 ID 화면 표시
  폐지 · 당사자 허브 HERO 개편. 회차 카드 안 '기록 오류' 안내(muted 상자)는 카드 안 카드라
  플랫 한 줄로 바꿨다.

## 결정 3 — 카드-섹션 여백 3단

간격을 세 값으로 닫는다. **이 밖의 카드 간격을 새로 만들지 않는다**:

| 단 | 값 | 자리 |
| --- | --- | --- |
| ① 페이지 세로 스택 | 24 (`--section-gap`) | 구획 카드·HERO·배너 사이 |
| ② 목록 안 카드 사이 | 20 (`--space-5`) | 카드 그리드·카드 스택 |
| ③ 행 카드 스택 | 12 (`--space-3`) | 접힌 회차 줄·당사자 행 |

카드 안 패딩은 §3-4 의 3종(본문 24 · 머리/행 16/24 · 좁은 보조 패널 16/20) 그대로다.
설정 화면의 구획 간격 32 는 ①로 모았다.

## 결정 4 — 호버·선택 테마 규칙 (색 반전)

| 어휘 | 라이트 | 다크 |
| --- | --- | --- |
| 면 호버 (카드·행) | `--gradient-hover` (tint 쌍) | 같은 토큰 — 다크 tint 쌍 (tokens.css) |
| 선택 (카드) | `--gradient-brand` 아웃라인 | 같음 (base 쌍은 두 테마에서 선다) |
| 선택 (행·컨트롤) | `--gradient-action` 면 + `--on-action` 글자 | 같음 — 채움이 두 테마 공통의 밝은 파스텔이라 글자도 늘 어두운 잉크 |
| **반전 호버** (내비류 강조 호버) | **어두운 면(`--ink`) + 그라데이션 글자** | **그라데이션 면(`--gradient-brand`) + `--on-action` 글자** |

핵심은 마지막 줄이다(Q: "컬러 반전을 잘해야 함") — 테마가 바뀌면 **면과 글자가 서로 자리를
바꾼다**. 구 다크 규칙(`--canvas` 면 + `--ink` 글자)은 그라데이션이 사라져 라이트와 어휘가
갈렸다. 다크의 글자·아이콘이 `--ink` 가 아니라 `--on-action` 인 이유: 다크의 `--ink` 는 밝은
색이라 밝은 그라데이션 위에서 읽히지 않는다.
