# ADR-0039: 일정 화면 통합 — 다가오는 일정과 전체 일정을 `일정` 하나로

- 상태: 승인 (2026-08-23, Q 그릴링 6문 + 시각 시안 1회, 2026-08-24 주차·상태 후속 개정). 결정 번호 **D75**.
- 관계: **D21 의 2섹션 화면 내용과 D54 의 별도 전체 일정 화면이라는 "두 화면" 전제를 대체**한다. D35(사이드바=장소 / 우상단=행동)와 D7(권한은 게이트웨이), CCC-66(오늘 묶음 상태 유지), CCC-57(미래 날짜 예정만), D47·D54 의 이동 규칙은 불변이다.
- 스펙 원문: `docs/superpowers/specs/2026-08-23-schedule-unification-design.md`

## 배경

일정 메뉴가 '다가오는 일정'(8일 창)과 '전체 일정'(월 창) 둘로 갈려 있었다. 두 화면은 2026-08-06 카드 통일 이후 같은 당사자 카드를 쓰고, 차이는 창 크기와 상태 포함 범위뿐이라 실무자는 "오늘 걸 보려면 어느 메뉴지"를 다시 판단해야 했다. Q 지시로 하나로 합쳤다.

## 결정

1. **첫 답은 오늘과 다음 상담이다.** 지난 일정은 보조다. 이 제품의 핵심이 상담 직전 준비이기 때문이다.
2. **현재 ISO 주간 범위와 별도 월 선택을 상시 나란히 둔다.** ISO 주차는 월요일-일요일이며 연도에 따라 52주 또는 53주다. 범위는 URL 쿼리 `?range=` 에 남고 고른 쪽만 '지금 정한 것' 어휘를 입는다.
3. **이름은 `일정` 하나다.** 사이드바 메뉴와 페이지 제목 모두. 한 화면으로 합쳤는데 이름이 둘이면 여전히 두 장소로 읽힌다.
4. **ISO 주차 → 날짜 → 카드로 묶고 일정이 있는 날짜만 그린다.** 주차 제목은 `2026년 35주 · 2026년 8월 24일(월)-30일(일)` 형식이다. 현재 주차와 오늘을 최상단에 두고 미래를 그다음, 지난 주차를 마지막에 둔다.
5. **오늘 상담 카드 전부 그라데이션 아웃라인**을 입힌다. 완료 카드는 오늘 아웃라인을 유지하되 흐리게 표시한다. 768px 이상은 고정 2열이고 홀수 마지막 칸은 비우며, 모바일은 1열이다.
6. **미래는 펼치고 지난 날짜는 접는다.** 지난 날짜는 날짜·당사자 이름·건수만 남는 아코디언이며, 펼친 카드와 완료 카드는 흐리게 표시한다. 월 선택과 달 이동은 주간 범위 옆에 상시 선다.

## 유지·정리

- 상태 규칙 불변: 오늘 묶음은 끝난 상담도 배지와 함께 남고(CCC-66), 내일 이후 묶음은 예정만 남는다(CCC-57). 월 범위는 지난 일정의 상태를 전부 보여준다(D54).
- 이동 불변: 완료 회차는 그 회차가 펼쳐진 상담 기록으로, 그 외는 브리핑으로(D47 ① · D54).
- **시간순 정렬 토글 삭제** — 날짜 묶음 제목이 순서를 이미 말하고, 역순 토글은 묶음 제목과 충돌한다. 이로써 화면에 클라이언트 상태가 없어져 전부 서버 컴포넌트가 됐다(`schedule-cards.tsx` 삭제).
- `/programs/:type/schedule/all` 은 `?range=month`(month 쿼리 보존) 리다이렉트만 남는다 — 북마크와 과거 링크를 살린다.
- 데이터는 현행 `getUpcomingSchedules` 와 `getMonthSchedules` 재사용. 새 SQL·마이그레이션·새 색·새 그라데이션 0.
- 필터는 여전히 없다(D54 — 범위 전환이 곧 필터다).

## 고려한 대안과 기각 이유

- **한 달 시간순 목록 하나(구획 없음)**: Q 기각 — 지나간 일정이 앞에 서서 정작 중요한 빠른 일정 확인이 늦어진다.
- **지난 | 오늘 | 예정 3구획**: 카드에 날짜가 이미 있어 구획이 정보를 반복한다.
- **제목이 범위 따라 바뀌는 안**: 이름이 둘로 남아 통합의 뜻이 죽는다.

## 결과

- 사이드바 메뉴가 3개에서 2개(일정·당사자)가 됐다. 활성 판정의 "가장 긴 href 하나만" 규칙(2026-08-03)은 그대로 두었다 — 하위 경로가 다시 생겨도 안전하다.
