# ADR-0010: 보관 기간 경과 시 파기가 아니라 아카이브 (D32)

- 상태: 승인 (2026-07-24, Q)
- 대체 관계: D10(ADR 없음, CLAUDE.md 9장)의 실행 방식 중 "유예기간 경과 시 pii_vault 파기"를 "아카이브 전환 후 별도 파기"로 바꿨다. 당시 유지한 금고 값만 파기와 사례별 가명 기록 보존은 아래 2026-09-13 후속 결정이 대체한다.
- 구현: 아카이브/금고 보존·파기는 Linear `CCC-121`, 마이그레이션 `0041_pii_retention_lifecycle.sql`로 구현했다(2026-08-22). 아래 원문과 파생자료까지의 파기 범위 확장은 정책 확정이며 아직 구현 완료가 아니다.

## 배경

docs/ 전수 대조 리뷰(2026-07-24)에서 3자 충돌 발견: CONTEXT.md 용어집("파기 예정일 도래만으로 파기하지 않는다 — 파기 검토 선행")과 실제 구현(`db/gateway.ts purgeExpiredParticipantPii` — 매일 03:00 cron이 `purge_due` 경과 시 사람 검토 없이 자동 파기)이 정면 충돌. 파기는 되돌릴 수 없는 쓰기이므로 정책 확정이 필요했다.

## 결정

1. **트리거 2종 분리.**
   - 정기(보관 기간 경과): 기본 1년(조직 설정, 내부 규정 확인 후 확정 — Q 액션). 경과 시 **자동 아카이브 전환** — PII를 파기하지 않고 보존하되 열람 권한을 축소한다.
   - 원천 파기(즉시): 동의 철회·본인 삭제 요청·법적 요청, 또는 아카이브 이후 파기 검토를 거친 실행. 기존 관리자 단건 경로(`purgeParticipantPii`)를 유지한다.
2. **아카이브 상태**: 일반 조회 경로에서 제외되고, 예외 열람은 전건 감사(D14). 열람 가능 역할의 정확한 범위는 미결(구현 전 확정).
3. **오프라인 반출 기본 불가.** 보관 기간 중(아카이브 전환 전)에는 다운로드 가능하되, 다운로드 행위자를 전건 감사 기록으로 남겨 문제 발생 시 책임을 추적한다. 아카이브 전환 후에는 다운로드도 불가.
4. 자동 파기 cron은 자동 아카이브 전환으로 교체한다.

## 이유

- 파기는 비가역이라 무인 자동 실행이 위험하다. 아카이브는 가역(권한 복원 가능)이므로 자동화해도 안전하다.
- "기록 보존" 요구는 시스템 밖 반출(출력·로컬 파일)이 아니라 서버 안 분리 보관으로 푼다 — 반출물은 암호화·접근 통제·감사(D14) 밖으로 나가 유출 추적이 불가능하다.
- 개인정보보호법의 "다른 법령상 보존 의무 시 분리 보관" 구조와도 서버 내 아카이브가 부합한다.

## 미결 (법률 검토·Q 확인)

- 아카이브 보존 상한과 최종 파기 시점 — 법 제21조(보유기간 경과 시 파기 원칙)와의 정합. 동의서 문안 법률 검토에 포함.
- 아카이브 열람 가능 역할 범위.
- 보관 기간 기본 1년의 내부 규정 근거.

## 영향

- 코드: cron은 암호문을 `participant_pii_archives`로 옮기고 기존 금고에서는 비운다. 일반 조회는 아카이브 당사자를 제외하며 새 케이스가 시작되면 가역 복원한다.
- 파기: 기관 관리자가 보존 사유를 검토한 한 건만 최종 파기할 수 있다. `PII_PURGE_ENABLED`는 이 비가역 단계만 잠근다.
- 감사: 아카이브, 보존, 재검토, 파기 승인, 최종 파기 전이를 각각 남긴다.
- 문서: `docs/ops.md`와 `docs/policy/deferred-blockers-v1.md`를 구현 상태로 갱신했다.

## 구현 시 미결 처리 (2026-08-22)

- 보존 상한은 D46의 종결 후 총 5년을 적용했다. 연장 동의와 진행 중 업무는 상한 안에서만 보존할 수 있고, 더 긴 보존은 법적 사유와 설명을 요구한다.
- 아카이브 예외 열람 화면은 만들지 않았다. 역할 범위가 별도로 확정될 때까지 모든 일반 조회를 서버에서 차단하는 fail-closed 구현이다.

## 2026-09-13 후속 결정: 원문과 연결 가능한 파생자료까지 파기한다

Q는 보존기간이 끝났고 정당한 보존 사유가 없어 기관 관리자가 최종 파기를 결정한 대상에 대해, **원문과 연결 가능한 파생자료를 지우고 집계만 남기는 안**을 선택했다. 금고 8칸을 지워도 본문에 건강·피해 경험이나 특정인을 알아볼 단서가 남을 수 있으므로, 이를 상담 자료 전체의 파기로 보지 않는다.

- 파기 범위에는 해당 대상의 금고 값과 아카이브 사본뿐 아니라 수기 메모, 전사, 인테이크 자유 글, 목표 문장, 인용, AI 결과, 상담 기억 등 연결 가능한 원문과 파생자료가 포함된다.
- 남길 수 있는 것은 재식별 위험을 점검한 집계 통계와 내용 없는 감사 기록뿐이다. 원문을 가리거나 사례 ID만 바꾼 개별 기록을 집계 통계로 간주하지 않는다. 개별 사례의 경과를 다시 분석하기 위한 가명 기록 보존안은 선택하지 않았다.
- 기존 보존기간, 보존 사유 검토와 관리자 승인 절차는 이 결정에서 변경하지 않는다. 이 문서의 확정은 실데이터 파기를 실행하라는 승인이 아니다.
- 파기 승인 범위, 공유 자료의 귀속과 다른 활성 케이스의 보존 경계를 구현 전에 명시한다. 한 대상의 파기를 다른 기관이나 활성 케이스의 자료 삭제로 확대하지 않는다.
- Q는 후속 그릴링에서 오래된 백업도 사용하되 최신 파기 내역을 먼저 반영·검증한 뒤 업무를 여는 A안을 확정했다. 내역을 확보하거나 검증하지 못하면 업무 재개와 복구 완료 판정을 허용하지 않는다. 정본은 [S10 §6.1](../specs/S10-cccx-format.md#61-최신-파기-내역을-반영하는-복원)이다. 이미 내려받은 업무 반출물의 처리 절차와 공급자 백업의 물리적 삭제는 이 복구 개방 결정과 구별한다.

코어/DB와 Agent의 실제 삭제 경로, 파생자료의 계보 및 늦은 작업 결과 거부, 집계 통계의 비식별 기준과 삭제 증거가 함께 구현·검증돼야 이 범위를 완료로 보고할 수 있다. 기존 migration을 고치거나 원문 삭제가 없는 현재 경로를 문안만으로 확장 완료라고 부르지 않는다.
