# ADR-0010: 보관 기간 경과 시 파기가 아니라 아카이브 (D32)

- 상태: 승인 (2026-07-24, Q)
- 대체 관계: D10(ADR 없음, CLAUDE.md 9장)의 **실행 방식** 일부 대체 — "유예기간 경과 시 pii_vault 파기"를 "아카이브 전환 후 별도 파기"로. 가명 기록 통계 보존·값만 파기 규약은 불변.
- 구현: 이슈 CCC-archive#52

## 배경

docs/ 전수 대조 리뷰(2026-07-24)에서 3자 충돌 발견: CONTEXT.md 용어집("파기 예정일 도래만으로 파기하지 않는다 — 파기 검토 선행")과 실제 구현(`db/gateway.ts purgeExpiredParticipantPii` — 매일 03:00 cron이 `purge_due` 경과 시 사람 검토 없이 자동 파기)이 정면 충돌. 파기는 되돌릴 수 없는 쓰기이므로 정책 확정이 필요했다.

## 결정

1. **트리거 2종 분리.**
   - 정기(보관 기간 경과): 기본 1년(조직 설정, 내부 규정 확인 후 확정 — Q 액션). 경과 시 **자동 아카이브 전환** — PII를 파기하지 않고 보존하되 열람 권한을 축소한다.
   - 원천 파기(즉시): 동의 철회·본인 삭제 요청·법적 요청, 또는 아카이브 이후 파기 검토를 거친 실행. 기존 관리자 단건 경로(`purgeParticipantPii`)를 유지한다.
2. **아카이브 상태**: 일반 조회 경로에서 제외되고, 예외 열람은 전건 감사(D14). 열람 가능 역할의 정확한 범위는 미결(구현 전 확정).
3. **오프라인 반출 기본 불가.** 보관 기간 중(아카이브 전환 전)에는 다운로드 가능하되, 다운로드 행위자를 전건 감사 기록으로 남겨 문제 발생 시 책임을 추적한다. 아카이브 전환 후에는 다운로드도 불가.
4. 자동 파기 cron은 자동 아카이브 전환으로 교체한다.

## 이유

- 파기는 비가역이라 무인 자동 실행이 위험하다. 아카이브는 가역(권한 복원 가능)이므로 자동화해도 안전하다.
- "기록 보존" 요구는 시스템 밖 반출(출력·로컬 파일)이 아니라 서버 안 분리 보관으로 푼다 — 반출물은 암호화·접근 통제·감사(D14) 밖으로 나가 유출 추적이 불가능하다.
- 개인정보보호법의 "다른 법령상 보존 의무 시 분리 보관" 구조와도 서버 내 아카이브가 부합한다.

## 미결 (법률 검토·Q 확인)

- 아카이브 보존 상한과 최종 파기 시점 — 법 제21조(보유기간 경과 시 파기 원칙)와의 정합. 동의서 문안 법률 검토에 포함.
- 아카이브 열람 가능 역할 범위.
- 보관 기간 기본 1년의 내부 규정 근거.
