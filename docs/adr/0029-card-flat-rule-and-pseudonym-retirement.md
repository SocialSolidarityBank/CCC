# ADR-0029: 카드 성격 규칙(플랫 구획 신설) + 가명 ID 화면 표시 폐지 (D59)

- 상태: 채택 (2026-08-04 그릴링, Q 확정)
- 관련: D59 · DESIGN.md §2·§5 개정 · ADR-0009(D31)·ADR-0015(D37) 부분 개정

## 배경

2026-08-04 그릴링에서 Q 가 두 가지를 지적했다.

1. **"너무 카드만 있어서 답답하다."** 화면의 거의 모든 덩어리가 카드(흰 면 + 회색 1px +
   이중 파스텔 그림자)였다 — 브리핑 3영역·설정 구획·전체 일정 날짜 묶음·전체 목표 줄까지.
   상자가 어디에나 있으면 화면이 상자 나열로 읽히고, 정작 서야 할 카드(리스크 배너·클릭
   카드)가 묻힌다.
2. **가명 ID(crane-001 등)의 화면 상시 노출.** "확인해야 보이도록 위계를 낮추자"에서
   출발해, 그릴링에서 **전면 숨김**으로 확정됐다.

## 결정 1 — 카드 성격 규칙 (D1)

무엇이 카드인지 성격으로 가른다. 레퍼런스(Linear·Stripe 대시보드·Notion 계열 업무 도구)의
공통 규칙과 같다: **"클릭해서 들어가는 단위·집어 드는 단위만 카드"**.

- **카드로 남는 것**: ① 클릭·집어 드는 단위(일정 카드·회차 카드·사업 카드·낱개 리스트 행)
  ② 강조 컨테이너(HERO·리스크 배너·안내줄) ③ 폼 표면(등록·기록 작성·모달).
- **플랫 구획이 되는 것**: 읽기만 하는 구획 — 캔버스에 직접 얹고
  `구획 제목(18/600) + --gradient-brand 1px 구분선 + 여백`으로 선다.
  이번 적용: 브리핑 3영역·미해결 액션·전체 목표 줄·설정 구획·전체 일정 날짜 묶음.
- **카드 안에 카드를 두지 않는다**: 카드 안 하위 묶음(동의 fieldset·폼 안 fieldset)은
  상자 대신 위 `--line` 1px 구분선 하나로 가른다.

구분선을 구획 **제목 쪽**에 붙인다(브리핑 아코디언) — 접혀 있어도 구획 리듬이 남는다.
접힘(details)·전체 접기·앵커 바로가기는 형태만 바뀌고 동작은 유지된다.

## 결정 2 — 가명 ID 화면 표시 폐지 (D2·D3)

- **가명 ID 는 화면에 표시하지 않는다** — 백엔드 전용 식별자로 회귀한다. ADR-0009(D31)의
  원래 정의("기계 식별자·경계 토큰")로 돌아가는 것이고, 2026-07-26 에 "동명이인 구분·감사
  대조·기관 간 참조"로 정당화했던 화면 표시를 철회한다.
- **동명이인 구분은 전화번호가 맡는다** — 목록·일정 행에서 이름 옆에 **전체 번호**를
  나란히 표시한다(Q: 뒷자리 아닌 전체 번호). 연락처 칸이 이미 있는 카드(상담 일정 카드)에는
  중복으로 더하지 않는다. 노출 범위는 D24(역할 기준 실명·연락처 기본 표시)의 기존 틀 안이다
  — 같은 화면·같은 열람자에게 보이던 값의 자리만 바뀐다.
- **폴백 두 경우에만 ID 가 이름 자리에 나온다**: ① 이름 무응답 등록(D41 무응답 원칙)
  ② 보존 기간 경과로 금고가 파기된 당사자(D10·D32). 이 두 경우 ID 는 화면에 남는 유일한
  식별자라 불가피하다(전화번호도 함께 없다).

## 결정 3 — 당사자 정보 페이지 리뉴얼 + 버튼 보정

- **당사자 정보(허브) HERO**: 이름을 h2(18)로 낮추고(이미 '그 사람' 화면이라 페이지 제목
  크기가 과했다) **연락처를 이름 옆에 나란히 직표시**한다. 2026-08-03 의 '이름 클릭 →
  개인정보 접힘'은 폐지 — 연락처가 올라오면 접힘에 남는 내용이 참여 사업뿐인데 아래 사업
  카드와 중복이었다. ParticipantHeroCard 에 `nameSize`·`contact` 슬롯 신설.
- **`--nudge-hangul` = 0 확정**: canvas TextMetrics 실측으로 Pretendard 한글 잉크 중심이
  line-height 1 컨트롤에서 이미 기하 중심 ±0.4px 안임을 확인했다(16px '상담 등록' 기준
  −0.18px). "한글은 위로 떠 보인다"는 전제가 이 폰트에서 성립하지 않아 0.045em·0.02em
  두 값 모두 "아래로 치우침"으로 관찰됐다. 토큰 축은 계약으로 남긴다.

## 적용 범위

전 화면 일괄(D4 — Q 선택). ParticipantName 공용 부품 한 곳이 ID 표기를 소유하므로
나눠 적용할 의미가 없고, 플랫화도 규칙이 결정론적이라 한 PR 로 바꿔 한꺼번에 검토한다.
