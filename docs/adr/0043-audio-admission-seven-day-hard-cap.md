# ADR-0043: 원음 입장 조건과 7일 절대 상한

- 상태: Accepted
- 결정일: 2026-09-03
- 결정 번호: D85
- 관련: ADR-0041 D81, SG8, E5-6
- 대체: ADR-0041 D81의 "첫 실제 처리 기회가 끝내 오지 않는 경우" 미정 부분만 대체한다. 기관 소유 private Storage, 처리 직후 삭제, 처리 기회 뒤 24시간 상한, 관리자 장애 기록은 유지한다.

## 배경

ADR-0041은 원음을 다음 영업일의 첫 실제 Agent 처리 기회까지 보관하고, 그 기회가 생긴 뒤 24시간 안에 처리하지 못하면 삭제하도록 정했다. 그러나 STT가 꺼져 있거나 Agent가 장기간 고장 난 경우에는 첫 처리 기회가 생기지 않아 원음이 무기한 남을 수 있었다.

## 결정

1. 녹음 원본 업로드는 녹음 동의가 유효하고, 선택한 처리 경로에 필요한 동의와 현재 해당 원음을 처리할 건강한 Agent·용량이 있을 때만 받는다. 로컬 STT는 녹음 동의만 요구하고, Azure 같은 외부 STT는 녹음 동의와 외부 STT 동의를 모두 요구한다. 조건을 만족하지 않으면 원음 객체를 만들지 않고 수기 기록 경로를 안내한다.
2. 업로드를 받은 원음은 `uploaded_at + 7 × 24시간`을 `retention_hard_cap_at`으로 갖는다. 계산은 UTC 절대시간으로 한다.
3. 첫 실제 처리 기회가 상한 전에 생기면 `processing_deadline_at`은 `min(첫 처리 기회 + 24시간, retention_hard_cap_at)`이다.
4. 처리 결과를 공식 저장하면 즉시 원음을 삭제한다. 동의 철회와 처리 불가 확정도 즉시 삭제 사유다.
5. `retention_hard_cap_at`에 도달하면 처리 기회, claim, lease, provider 상태와 관계없이 원음을 삭제한다. 진행 중 작업은 결과를 공식화하지 않는다.
6. 상한 삭제는 관리자 사고 상태와 수기 기록 폴백을 함께 남긴다. 삭제 증거는 SG8의 어댑터별 부재 증명 계약을 따른다.

## 결과

- 다음 영업일 처리 기회를 보장하려는 운영 의도는 유지하지만, 원음 보관은 어떤 실패 경로에서도 7일을 넘지 않는다.
- 7일 가까이 지난 뒤 처음 생긴 처리 기회는 24시간 전체를 보장받지 못한다. 개인정보 최소 보관을 처리 복구보다 우선한다.
- 녹음 시점의 Agent 건강 확인이 제품 입장 조건이 된다. 실패하면 서비스 전체가 아니라 녹음 기능만 닫히고 수기 기록은 계속된다.

## 구현 소유

- 계약과 fixture: SG8
- Agent claim, lease, 결과와 삭제 요청: SG5, E5-1a
- 저장 구조, 삭제 조정과 사고 상태: E5-6
- 화면 안내와 수기 폴백: E2 기록 화면 티켓
