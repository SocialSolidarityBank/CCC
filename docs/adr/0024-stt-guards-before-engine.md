# STT는 안전장치를 먼저 넣고, 엔진은 갈아끼울 수 있게 둔다

`apps/pipeline/ccc_pipeline/transcribe.py`가 오디오 파일을 통째로 Whisper(`medium`)에 보내던 시기의 조사 문서에는 **실측된 실패**가 있다(`docs/aside/맥북-녹음-배치-전사-3엔진-비교-2026-07-12.md`). whisper large-v3가 34분 대화 녹음의 17분 44초 지점부터 끝까지, 전체의 48%에서 같은 문장을 254번 연속 반복하며 내용을 잃었고 마지막에 녹음에 없던 "다음 영상에서 만나요!"를 지어냈다. 같은 파일에서 Apple(SpeechAnalyzer)과 Qwen3-ASR-1.7B는 반복 0회로 완주했다. 같은 구간을 3분으로 잘라 넣으면 Whisper도 반복하지 않았다. 이 기록은 통짜 입력 방식이 실패 원인의 일부였다는 역사·회귀 증거다.

상담에서 이 실패가 나면 승인 화면의 "음성에 없는 내용"에 AI가 지어낸 문장이 오르고, 승인=정합성 검증(R2)의 전제가 무너진다.

**2026-07-31 Q 결정:** 엔진 교체보다 안전장치를 먼저 넣는다. **2026-09-08 구현 순서 명확화:** 안전장치와 실제 어댑터를 먼저 구현하고, 사람 품질 비교와 하드웨어 자격 검증은 후속 단계로 미룬다. 기존 합성 5건의 사람 청취 미완료와 `independentSTT=BLOCKED_ACCESS` 상태는 역사·회귀 증거이며 구현이나 운영자 본인의 비민감 테스트 녹음 시험의 선행조건이 아니다.

## 넣을 것

1. **Local 무음 경계 청크 분할:** 사람 말이 없는 구간을 찾아 그 자리에서 자른 뒤 조각별로 전사한다. 문장 중간을 자르지 않으므로 경계에서 말이 깨지지 않는다.
2. **공통 반복·출력 검사:** Local과 Azure 결과에서 같은 문장이 임계값 이상 연속되면 실패 구간을 경고한다. Local은 해당 조각을 한 번만 더 잘라 재시도할 수 있다. Azure 어댑터는 원본 파일의 HTTP send를 attempt당 최대 한 번 시작하고 자동 client 재시도를 하지 않는다. 이는 provider 내부 처리의 exactly-once 보장이 아니다. 반복이 남으면 산출물에 **경고와 함께** 실어 승인 화면에서 실무자가 보게 하고 조용히 통과시키지 않는다.
3. **엔진 경계:** Local은 격리된 Python 환경의 `Qwen/Qwen3-ASR-1.7B`와 `Qwen/Qwen3-ForcedAligner-0.6B` 원본 checkpoint를 사용한다. Azure는 `api-version=2025-10-15`, 원본 파일 1회 client send와 `diarization.enabled=true`, `maxSpeakers=2`로 받은 익명의 파일별 provider 화자 ID를 사용한다. 두 경로는 서로 자동 전환하지 않는다.

## 결과

- 위 Local 가중치는 취소된 Alibaba Cloud Token Plan과 무관한 로컬 공개 가중치다. 현재 구현 checkpoint라는 뜻이며 세계 최고나 보편적인 최신 모델이라는 뜻은 아니다.
- 운영자 본인의 비민감 테스트 녹음은 내부 기능 시험에만 쓴다. 실제 당사자나 제3자 음성의 이용 권한, 운영 동의, NER 면제 또는 signed registry 활성화를 뜻하지 않는다.
- 사람 모의상담 품질, 캡처 조건, 최소·권장 장비와 처리량은 후속 품질 단계에서 판단한다. 근접 4.2%와 원거리 14.3% WER의 기존 캡처 관측은 역사 증거로 보존하되 구현을 막지 않는다.
- `yellow` 가드는 실패를 없애지 못하고 **드러나게** 만든다. 반복 구간이 있으면 그 회차의 전사는 불완전하며, 실무자가 수기 메모로 메워야 한다(D5 폴백).
