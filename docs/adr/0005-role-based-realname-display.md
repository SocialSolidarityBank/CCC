# 내부 화면 PII는 역할 기준 실명 표시

> **2026-07-18 일부 대체(ADR-0009, D31)**: "그 외 사용자에겐 마스킹·가명" 부분 폐기 — 내부 인증 사용자 전원 실명 기본 표시(화면 조회 감사는 유지). 상담 내용 접근 범위(본인 담당 케이스만)는 불변.

2026-07-17 확정. 내부 화면의 참여자 PII 표시를 **마스킹 기본(D22, 2026-07-16)에서 역할 기준 실명 기본으로 대체**한다. 담당자(본인 배정 케이스)와 배정 책임자에게는 실명·연락처·계좌가 클릭 없이 기본 표시되고, 마스킹·가명화는 그 외 사용자, AI 파이프라인, 통계, 외부 출력에만 적용한다.

하루 만의 번복은 실사용 피드백 때문이다: 상담 5분 전 "빠른 스키밍" 화면에서 이름을 보려고 '전체 보기'를 클릭하는 동작 자체가 제품 컨셉과 충돌했고, 가명 ID(동물 슬러그)는 기억 보조로는 좋지만 담당자가 참여자를 특정하는 수단이 될 수 없었다. 참여자 선택 UI도 실명 목록이 전제되어야 "검색이 아니라 선택"이 성립한다.

배정 책임자의 PII 열람은 담당자와 동일하게 확대한다(ADR-0002의 "배정 책임자는 가명 ID·진행 상태·현재 담당자만" 부분을 대체). 배정 업무는 실명 없이 수행할 수 없기 때문이다. 단 **상담 내용(세션 기록·브리핑)은 여전히 본인이 담당자로 배정된 케이스만** 열람한다 — 접근권한이 상담 관계와 담당 배정에서 나온다는 ADR-0002의 원칙 자체는 유지된다.

감사(D14)는 클릭 단위에서 화면 단위로 바꾼다: PII가 표시되는 화면 조회당 감사 1건. '전체 보기' 클릭 이벤트(reveal_participant_pii)와 마스킹 표시 감사(read_participant_pii_masked)는 이 모델에서 의미를 잃는다.

## Considered Options

- **페이지 기준 구분** (스키밍 화면만 실명, 나머지는 마스킹 유지): 화면마다 규칙이 달라 사용자 예측이 어렵고, 신규 화면마다 분류 결정이 필요해 기각.
- **D22 유지 + 참여자 선택 UI만 실명 허용**: 최소 변경이지만 "상담 중 클릭해서 열람" 문제가 그대로 남아 기각.
- **역할 기준 전면 노출**: 권한이 있으면 항상 보이고 없으면 항상 가려져 규칙이 단순하고, 스키밍 컨셉과 일치해 채택.

## Consequences

- 가명 ID의 역할이 축소된다: 기록·AI 처리·통계·외부 출력 전용. 내부 화면에서는 실명과 병기하거나 실명이 우선한다 (CONTEXT.md 가명 ID 정의 수정).
- 티켓 CCC-archive#18(pii-masked-reveal)로 구현된 마스킹 표시·전체 보기 흐름은 역할 기준 표시로 재작업 대상이다.
- 목록·일정 화면이 여러 참여자의 PII를 한 번에 복호화하게 되므로 성능과 감사 로그 볼륨을 설계에서 고려해야 한다.
- 동의서 문안의 열람 범위 항목에 "담당자 및 배정 책임자"를 명시해야 한다 (법률 검토 미결 사항에 반영).
- 참여자 직접 접속 영역(가입·로그인·동의서 작성)은 이번 개편에서 IA만 분리하고 구현하지 않는다 — 동의서 법률 검토(D23) 후 별도 단계.

(2026-07-17 그릴링 세션에서 결정. D22의 PII 마스킹 부분과 ADR-0002의 배정 책임자 열람 범위를 대체한다.)
