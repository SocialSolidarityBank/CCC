# ADR-0042: Supabase 사전 점검은 변경 없이 시작한다

- 상태: 승인 (2026-08-31, GitHub #204, CCC-140)
- 결정자: Q
- 번호 재배정: 2026-09-02 E0-5b에서 ADR-0040과 D76 충돌을 해소
- 관련: ADR-0041(D76~D83, E0-1 발행 예정), D84, CCC Open Pilot v0.3
- 부분 대체: 구 ADR-0040의 배포 문, Workers 중계, 원음 30일 정책은 ADR-0041이 대체
- 보존: 구 결정 4의 read-only `plan`, 구 결정 5의 시크릿 입력과 출력 분리

## 배경

기관 소유 Supabase 프로젝트를 설치 대상으로 삼더라도 첫 동작부터 자원을 바꾸면 리전, 권한, 기존 데이터와 설치 버전을 확인하기 전에 돌이키기 어려운 변경이 생긴다. 관리 자격증명을 명령행이나 출력에 노출하면 설치 도구 자체가 새로운 시크릿 유출 경로가 된다.

배포 모드, Auth, Storage 수명과 API 실행 위치는 ADR-0041이 정한다. 이 문서는 그 정책을 구현하기 전에 Supabase 프로젝트를 변경 없이 읽는 사전 점검만 결정한다.

## 결정 1: 첫 공개 동작은 read-only plan이다

공개 진입점은 `pnpm supabase:bootstrap -- plan`이다. CCC-140에서는 `plan`만 연다. `apply`, `verify`, `status`는 후속 티켓이 같은 진입점에 추가한다.

호스팅 프로젝트의 plan은 Supabase Management API의 프로젝트 조회, Auth 설정 조회, `database/query/read-only`만 사용한다. 데이터베이스 쿼리는 공급자의 `supabase_read_only_user` 경로로 실행한다. 로컬 plan은 `BEGIN READ ONLY` 트랜잭션으로 같은 카탈로그 검사를 수행한다.

plan은 실행 전후의 스키마, 정책, 버킷, Auth, 기관 데이터 지문을 비교한다. 서울 리전 증거 누락, 다른 리전, 기존 데이터, 지원하지 않는 설치 버전, 읽는 동안의 상태 변경은 적용 전 차단 사유다. 적용 예정 자원 이름과 비개발자가 실행할 다음 행동을 함께 보여준다.

## 결정 2: 시크릿은 입력과 출력에서 분리한다

Management API 토큰은 `SUPABASE_ACCESS_TOKEN` 환경변수로만 받는다. 토큰과 데이터베이스 연결 문자열은 명령행 인자가 아니다. 프로젝트 식별자는 비시크릿 설정이라 `--project-ref` 또는 `CCC_SUPABASE_PROJECT_REF`로 받을 수 있다.

표준 출력, 오류 출력, 임시 파일에는 URL, 토큰, 연결 문자열, 서비스 역할 키, 공급자 원문 오류를 남기지 않는다. plan은 임시 결과 파일을 만들지 않는다. 누락, 무효, 권한 부족 자격증명은 각각 `CREDENTIAL_MISSING`, `CREDENTIAL_INVALID`, `CREDENTIAL_INSUFFICIENT`로 구분하고 원문 응답 대신 고정된 한국어 복구 안내만 출력한다.

## 구현 범위

CCC-140에서 다음을 구현한다.

1. 로컬과 호스팅 프로젝트의 읽기 전용 상태 수집
2. 서울 리전, 읽기 권한, 기존 데이터, 설치 버전 검사
3. PostgreSQL, RLS, Auth, Storage 적용 예정 자원 계획
4. 실행 전후 지문 비교와 차단 사유
5. 시크릿 없는 한국어와 JSON 출력
6. 유효, 잘못된 리전, 자격증명 오류, 기존 데이터의 블랙박스 검증

## 이번에 하지 않는 것

1. 기준선과 마이그레이션을 적용하는 `apply`
2. 외부 동작과 영수증을 만드는 `verify`
3. 설치 뒤 드리프트를 읽는 `status`
4. 실제 기관 데이터 이전과 운영 전환
5. 배포 모드, 인증 공급자와 원음 보관 정책 결정

## 완료 조건

- PR #210이 ADR-0042와 D84를 사용하고 ADR-0041이 대체한 정책 문장을 포함하지 않는다.
- 호스팅과 로컬 plan이 프로젝트 상태를 바꾸지 않는다.
- 실행 전후 지문이 다르면 실패한다.
- 시크릿, URL, 연결 문자열, 서비스 역할 키와 공급자 원문 오류가 출력되지 않는다.
- `apply`, `verify`, `status`는 공개 명령으로 열리지 않는다.
