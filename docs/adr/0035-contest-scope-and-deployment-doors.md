# ADR-0035: 대회 4주 범위와 배포 문 넷

- 상태: 승인 (2026-08-16 Q)
- 결정자: Q
- 관련: ADR-0027(OpenAI 정본과 마스킹 텍스트 큐) · D43(GAS 보류 선례) · D53(STT 안전장치) · D10·D32·D46(보존·파기 절차와 법률 검토 동결) · D11·R4(감정 분석 원 결정)
- 후속: 9장 결정표 D63~D68 등재 · `docs/consent/legal-review-open-items-v1.md` · `docs/policy/deferred-blockers-v1.md` · `apps/pipeline/ccc_pipeline/worker.py` 의 `EMOTION_DEFERRED` 스위치

## 배경

2026-08-15~16 노션에 모델 넷의 검토가 모였다. 장표 13종과 그 부모인 마스터 정리 문서다.
검토는 의견에 그치지 않고 레포를 직접 실측해 문서 오류 하나를 잡아냈다. `AGENTS.md:148` 과
`CLAUDE.md:148` 이 "파기 위험은 현재 없다" 고 적어 뒀지만, 실제로는 종단 경로 전체가 살아
있었다.

- `migrations/0006_participant_support_case_cutover.sql:1773` 의 트리거
  `support_cases_schedule_pii_purge_due` 가 마지막 활성 케이스가 종결되는 순간
  `purge_due` 를 채운다.
- `apps/api/src/index.ts:84` 의 `ctx.waitUntil(runPurge(env))` 가 매일 03:00 UTC 이 경로를
  깨운다.
- `db/gateway.ts:4816` 이 도래분의 `enc_name`, `enc_phone` 을 포함한 암호화 칼럼을 직접
  `NULL` 로 바꾼다.
- `apps/api/test/watchdog-purge.test.ts:282` 는 이 경로가 실제로 도는 것을 테스트로
  증명한다. `runPurge` 의 결과가 `{attempted: 1, purged: 1, noops: 0}` 이다.

이 네 지점이 한 문장으로 이어진다. 정책은 절차(D32·D46)를 요구했는데 코드는 파기만 하고
절차 없이 지운다. "위험이 없다" 는 문장은 이 상태를 반대로 적은 것이었다. 이번 검토가
아니었다면 이 어긋남은 실제 상담 데이터가 들어올 때까지 묻혀 있었을 것이다.

동시에 네이버 커넥트재단 'AI 챌린지 해' 4주 대회(2026-08-24 시작, 2026-09-18 마감)가 범위를
강제한다. 서비스는 아직 시작하지 않았고, 이 레포가 다루는 모든 자료는 더미다. 이 두 조건이
아래 여섯 결정의 바탕이다. 지금 무엇을 고치고 무엇을 미루는지는 "옳고 그름" 이 아니라
"4주 안에 들어가는가, 그리고 실데이터가 없는 동안 미뤄도 되는가" 로 갈린다.

핵심 논거는 셋이다.

1. **사용기관이 자료 관리 책임을 지는 구조는 의도된 설계이지 책임 회피가 아니다.** 배포기관
   (사회연대은행)이 모든 설치의 정책·AI·DB·전사 설정까지 떠안으면, 그 허들 자체가 배포를
   막는다. 책임을 나누는 것이 배포를 늘리는 길이다.
2. **Non-IT 인력이 쓰므로 최소 설정 UX 가 절대 조건이다.** 이것이 로컬 우선 1차 설계의
   근거다. 설정할 것이 많을수록 실제로 쓰는 기관이 줄어든다.
3. **미루는 것들은 기각이 아니라 연기다.** 서울 PostgreSQL 이전, 전사 보관, 법률 정책,
   감정 분석 넷 모두 "안 한다" 가 아니라 "지금은 아니다" 다. 재개 조건은 결정마다 명시한다.

## 결정

### D63 배포 형태와 책임 구도

코어 하나에 배포 문 넷(관리형 웹, CCC 박스, 개인 노트북 모드, 기관 자체 클라우드). 자체
클라우드는 맞춤 계약으로만 열고 후순위. **자료 관리 책임은 사용기관이 진다.** 배포기관
(사회연대은행)은 안전 기본값, 알림, 서식을 제공한다. 유료 관리형 웹에서 저장을 맡는 경우에만
배포기관이 수탁자가 된다. Apache 2.0 배포는 **이미 적용 상태**다(`LICENSE`, 레포 public).
상세 ADR-0035.

`LICENSE` 파일이 이미 레포 루트에 있고 조건을 새로 만들 필요가 없다. 이 결정이 하는 일은
라이선스를 바꾸는 것이 아니라, 이미 열려 있는 배포 형태에 맞춰 책임의 소재를 문서로
분명히 하는 것이다. 배포기관이 모든 문의 데이터까지 관리하려 들면 위 핵심 논거 1의 허들이
그대로 되살아난다.

### D64 감정 분석 보류

제외가 아니라 연기다. **D43(GAS 보류)과 같은 방식**으로 스키마, 데이터, `emotion.py`, 테스트를
전부 남기고 계산만 멈춘다(`worker.py` 의 `EMOTION_DEFERRED`). 파이프라인은
`emotionScores: {}` 를 보내며 이는 `migrations/0032:10` CHECK 와 `assertNumericJson` 을
통과한다. 마이그레이션 0건, API 변경 0건. **R4 와 D11 은 폐기하지 않는다.** 다시 켤 때 그대로
적용된다. 동의 문안은 보류 사실을 표시한다. 재개 조건: 정식 서비스 단계. 상세 ADR-0035.

빈 객체를 보내도 안전하다는 것은 의견이 아니라 실측이다. `migrations/0032_recording_result_commits.sql:10`
의 CHECK 는 `json_valid` 와 `json_type = 'object'` 만 요구하므로 `{}` 가 그대로 통과한다.
`db/gateway.ts` 의 `assertNumericJson` 은 빈 객체에서 순회할 항목이 없어 예외를 던지지
않는다. `apps/api/src/request-handler.ts:1387` 의 `requireOnlyKeys` 와 `:1394` 의
`asObject(body.emotionScores)` 는 키 존재와 객체 여부만 본다. 세 지점 모두 값의 내용을
검사하지 않으므로, 계산을 멈추고 빈 값을 보내는 것만으로 스키마와 API 양쪽을 안전하게
통과한다. 삭제 대신 보류를 고른 이유는 되돌릴 때의 비용이다. 지우면 되돌릴 때 저장 구조와
동의서를 다시 세워야 하지만, 보류는 계산 한 지점만 다시 켜면 된다.

### D65 저장소는 로컬 우선, 이식은 준비만

1차는 로컬(관리자 PC 서버 또는 각자 로컬 저장). 서울 리전 PostgreSQL 은 **연기**이며 이번에는
경계만 유지한다. 근거: SQL 이 순수 SQLite 방언이라 노트북 모드 이식은 저비용이지만,
PostgreSQL 은 `db/gateway.ts` 의 D1 호출 160곳(`prepare` 125 + `batch` 35)과 마이그레이션
34개 방언 변환이 필요해 4주에 들어가지 않는다. **D1(Cloudflare)을 지금 대체하지 않는다.**
문서에는 "실운영 전 서울 리전 이전 계획"으로 적는다. **로컬 모드는 배포 문이 하나 늘어나는
것이며 자체 DB 인스턴스를 갖는다.** 관리형 웹으로 만든 케이스의 클라우드 금고 결합은
그대로다(이 결정은 저장 위상을 넓히는 것이지 기존 금고를 파일로 바꾸는 것이 아니다).
상세 ADR-0035.

호출부 160곳을 4주 안에 전부 방언 변환하는 것은 이 대회의 다른 아홉 항목을 밀어내야만
가능한 분량이다. 반면 SQLite 방언을 그대로 쓰는 노트북 모드는 새 DB 엔진을 배우지 않아도
되므로, 핵심 논거 2(최소 설정 UX)에 그대로 들어맞는다. 이전 계획 자체를 버리지 않고 "지금은
경계만" 으로 남기는 이유가 이것이다.

### D66 AI 연결 규율

공식 기업용 API 만 쓴다. 무료 등급 금지(학습에 쓰임), 비공식 구독 프록시 금지(약관·계정
정지·감사 위험). 키는 기관 관리자만 입력하고 실무자는 키를 보지 않는다. **D57(OpenAI 정본,
ADR-0027)을 대체하지 않고 그 위에 규율을 얹는다.** 키가 어떤 등급이고 어떤 약관에 묶여
있는지는 **설정 시점에 기관 관리자가 확인하고 기록한다**(재개 항목). 키를 넣었다는 사실만으로
이 규율이 충족되지 않는다. 상세 ADR-0035.

D57 은 어떤 사업자를 부를지 정했고, 이 결정은 그 사업자의 어떤 등급 키를 쓸 수 있는지를
정한다. 층이 다르므로 대체가 아니라 위에 얹는 규율이다. 기관마다 키를 직접 넣는 구조
(BYO API 키)라서, 등급 확인을 코드가 자동으로 강제할 수 없는 자리가 남는다. 그래서 확인의
책임을 기관 관리자에게 명시하고, 그 확인이 아직 자동화되지 않았다는 사실도 함께 남긴다.

### D67 STT 결승은 CLOVA 와 RTZR

같은 한국어 상담 녹음으로 정확도, 화자 구분, 속도, 비용, 보관 조건을 비교해 정한다.
**D53(무음 경계 분할 + 반복 검사 + 엔진 추상화)의 안전장치는 그대로 유지**되며, D53 이 남긴
후보 순위(Qwen3-ASR 1순위)만 이 결정이 갱신한다. **D53 이 남긴 G1~G3 게이트는 폐기가 아니라
D68 의 대회 범위 안에서 이 비교로 수행한다.** '처리 장비 앞 세션' 요건이 대회 일정 안으로
들어오는 것이다. Qwen3-ASR 은 후보에서 빠지지 않고 **대회 밖 대체 후보**로 남는다. 로컬
전사는 정본이 아니라 **회상 힌트**로만 쓰고, 엉망 전사에서 이름·금액·날짜를 추출하지 않는다.
상세 ADR-0035.

D53 이 만든 것은 엔진 하나가 아니라 엔진을 갈아 끼울 수 있는 자리다. 그래서 이 결정은 D53
을 뒤집는 것이 아니라, 그 자리에 넣을 후보를 대회 일정 안에서 검증 가능한 둘로 좁히는
것이다. Qwen3-ASR 을 완전히 버리지 않는 이유는, 지금 좁히는 기준이 "4주 안에 실측
가능한가" 이지 "어느 것이 더 나은가" 가 아니기 때문이다.

### D68 대회 4주 범위

네이버 커넥트재단 'AI 챌린지 해'(2026-08-24 시작, 2026-09-18 마감) 범위. 하는 것: 안전
잠금(녹음 무시 규칙, 감정 보류), STT 비교, 기록부터 승인까지 한 흐름, 시연은 전부 가상
데이터. 미루는 것: 보존·파기 절차, 관리자 접근 축소, PostgreSQL 이전, 법률 검토
(`docs/policy/deferred-blockers-v1.md`, `docs/consent/legal-review-open-items-v1.md`).
미루는 근거: 서비스 미개시 + 전 데이터 더미. 상세 ADR-0035.

이 결정은 D63~D67 을 담는 그릇이다. 다섯 결정 각각이 "지금 한다" 와 "지금은 미룬다" 로
갈리는 이유가 결국 이 한 문장으로 수렴한다. 실제 당사자 데이터가 없는 동안에는 안전장치를
켜 두는 것과 시연이 가능한 흐름을 갖추는 것이 먼저이고, 그 밖의 것은 실데이터가 들어오기
전까지 시간이 있다.

## 버린 안

- **(가) 감정 분석 코드 삭제.** 되돌릴 때 스키마와 동의 문안을 다시 세워야 해서 기각했다.
  D64 의 보류로 대체한다.
- **(나) 대회 전 PostgreSQL 이전.** `db/gateway.ts` 의 D1 호출 160곳(`env.DB.prepare` 125 +
  `env.DB.batch` 35)을 방언 변환해야 해서 4주에 들어가지 않는다. D65 로 연기한다.
- **(다) 파기 경로 즉시 수정.** 더미 데이터라 긴급도가 낮고, D32·D46 이 요구하는 절차
  전체(아카이브 전환, 접근 제한, 검토 큐, 보존 사유 확인, 기관 관리자 확인)를 한꺼번에
  만들어야 해서 이번 범위와 분리했다. 재개 조건과 착수 지점은
  `docs/policy/deferred-blockers-v1.md` 에 남긴다.

## 미결

- 법적 검토가 필요한 항목은 이 ADR 이 판정하지 않는다. `docs/consent/legal-review-open-items-v1.md`
  로 넘긴다.
- 이번에 고치지 않고 미루는 차단 항목(파기 경로, 관리자 접근)의 재개 조건과 착수 지점은
  `docs/policy/deferred-blockers-v1.md` 로 넘긴다.
