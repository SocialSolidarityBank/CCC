# ADR-0016: 1차 MVP 가입 흐름 — 화면 흐름 프로토타입 (온보딩·초대·참여자 링크 가입)

- 상태: 승인 (2026-07-27, Q 그릴링). 결정 번호 **D39**.
- 관계: **D26(참여자 직접 접속)·D27(자체 인증)을 대체하지 않는다** — 두 결정이 "다음 단계·법률 검토 후"로 미룬 영역을, 인증 없는 **화면 흐름 프로토타입**으로 먼저 걷는다. D23(동의 기록)의 기록자 범위를 한 줄 넓힌다(아래). 겸임 데모 계정은 용어집 "역할 겸임"을 그대로 쓴다.

## 배경

1차 MVP의 완성 기준은 "관리자 온보딩 → 상담사 초대 가입 → 참여자 링크 가입 → 인테이크 → 브리핑 → 다음 상담 등록"이 **화면 이동으로 한 바퀴 완주되는 것**이다. 그런데 가입 계열 화면이 전부 없고, 진짜 인증(비밀번호·세션·이메일 발송)을 붙이면 D26·D27을 뒤집고 동의서 법률 검토를 앞지르게 된다. 그릴링으로 "기존 결정을 유지한 채 흐름만 완성하는" 깊이를 확정했다.

## 결정 (2026-07-27 그릴링 8건)

1. **화면 흐름 MVP** — 실제 인증·이메일 발송 없음. 초대 "이메일"은 발송 대신 **복사 가능한 링크 + QR + 이메일 문안**으로 표시한다(QR은 외부 서비스 없이 로컬 생성). 운영 인증은 여전히 Cloudflare Access(D16·D27) 몫이다.
2. **온보딩 = 조직 + 첫 사업 등록**(2단계 화면). 저장은 **이름만 진짜** — 조직 이름과 사업 표시 이름을 저장하고, 내부 유형은 금전지원형 v1(`financial_support_v1`) 고정. programs 테이블 신설·사업 전환기 개편은 하지 않는다(MVP 목적 초과).
3. **관리자+상담사 = 겸임 1계정** — 데모 신원은 역할 겸임 계정 하나로 관리자·상담사 화면을 오간다. 상담사 초대→가입 화면 흐름은 만들되, 가입한 상담사는 목록에 데이터로 추가될 뿐 신원 전환은 없다.
4. **참여자만 외부 링크 가입** — 참여자는 users 디렉터리에 넣지 않는다. 로그인 없는 **고유 토큰 URL**로 가입하고, 같은 링크가 자기 확인 페이지 입구가 된다.
5. **참여자 초대 링크 = 사업 + 담당자 묶음** — 상담사가 워크스페이스 안에서 발급하며 링크에 사업·발급 상담사가 박힌다. 가입 완료 시 참여자 + 케이스(참여 사업)가 자동 생성되고 발급 상담사가 담당자가 된다 — 목록 게시까지 한 번에 이어진다.
6. **가입 폼 = 이름·이메일·연락처 + 동의 2종 체크(기록자=본인)** — 기존 등록 폼(D23 동의 2종, 기본 미동의·미동의여도 진행)을 재사용하되 기록자를 '본인'으로 저장한다. **법률 검토 전 프로토타입**이며 문안 확정 시 교체만 하면 되는 구조로 만든다.
7. **알림 = 배지 2곳** — 참여자 목록 '새 가입' 배지 + 사이드바 참여자 메뉴 미확인 숫자 배지. 알림 센터·푸시는 만들지 않는다. 배지 색은 민트 계열(사람·소속, D34) — DESIGN.md에 규정.
8. **저장 후 동선** — 인테이크 기록지 저장 → 해당 참여 사업 **브리핑으로 즉시 이동** + 상단 '다음 상담 등록' 안내 한 줄(등록 버튼 포함). **참여자 자기 확인 페이지**는 내 정보·참여 사업·담당자·상담 일정·동의 상태까지만 — 상담 기록 내용(요약·GAS·플래그)은 미포함.

## 대안과 트레이드오프

- **간이 자체 인증(이메일+비밀번호)까지 구현**: D27의 "다음 단계"를 지금 당기는 결정이 되고 법률 검토 전제를 건드린다 — 기각.
- **programs 테이블 신설**: 복수 사업을 진짜 데이터로 만들 수 있으나 사이드바 전환기·기록 스키마 연결까지 번진다 — MVP 목적 초과로 기각.
- **참여자도 users 등재 + 역할 전환기**: 인증 모델 변경이 커진다 — 토큰 링크 방식으로 기각.

## 결과

- 신규 화면 6종(온보딩·상담사 가입·참여자 초대 발급·참여자 가입·자기 확인·배지 확장) + 초대 토큰 테이블 마이그레이션 1건.
- D26·D27의 본구현(실제 인증·법률 검토 후 동의)은 그대로 남은 일이다. 이 프로토타입의 가입 데이터는 가상 시드 전용 환경(로컬·미리보기, CCC-6)에서만 쓴다 — 운영 PII를 태우지 않는다.
