# ADR-0013: 목표 3층 구조 — 전체 목표 · 세션 목표 · 세부 목표

- 상태: 승인 (2026-07-26, Q)
- 관계: **D12(목표 변경 규칙)·D28(세션 목표)를 대체**한다. D6(GAS 주체)·R4·R5는 불변.
- 배경 발단: 2026-07-25 미리보기 실사용 테스트에서 Q가 "상담의 목표는 무엇인가요?" 화면에 목표 3개를 적었다가 거부당함 → "목표가 왜 3개인가, 병렬로 물어보면 혼란스럽다. 체계가 필요하다"는 문제 제기.

## 배경

기존 구조는 2층이었다.

```
케이스 목표 (1~3개, 수정 금지)
  └ 세션 목표 (회차마다, 케이스 목표에 선택 연결 — D28)
```

여기에 두 가지 문제가 있었다.

**① 층이 부족해 성격이 다른 것들이 한 줄에 섞였다.** "경제적으로 자립한다"(방향)와 "3개월 내 연체 2건 상환 합의"(측정 가능한 성과)가 같은 층에 병렬로 놓였다. 상담사는 무엇을 어느 칸에 적어야 하는지 판단할 근거가 없었다.

**② 수정 금지(D12)가 방향까지 묶었다.** D12가 문구 수정을 금지한 이유는 GAS 점수 이력 때문이다 — 3회차에 +1을 받은 목표의 문구가 5회차에 바뀌면 그 +1이 무엇에 대한 점수인지 알 수 없게 된다. 그러나 이 제약이 "자립"처럼 거의 변하지 않는 큰 방향에까지 걸려, 실제로는 고쳐야 마땅한 문구도 종료+신설로만 바꿀 수 있었다.

## 결정

**3층으로 나누고, GAS 점수는 가장 아래층에만 붙인다.**

```
전체 목표    "경제적으로 자립한다"            케이스당 1개 · 수정 가능 · 점수 없음
  └ 세션 목표  "이번 상담: 부채 정리 방향 잡기"   회차마다 · 케이스 목표 아닌 전체 목표의 하위
      └ 세부 목표 "3개월 내 연체 2건 상환 합의"    GAS 채점 단위 · 수정 금지(종료+신설)
```

| 층 | 개수 | 수정 | GAS | 성격 |
|---|---|---|---|---|
| 전체 목표 | 케이스당 **1개** | **가능** | 없음 | 방향. 이 참여자와 무엇을 향해 가는가 |
| 세션 목표 | 회차마다 복수·미연결 허용 | 가능 | 없음 | 이번 회차에서 다룰 것 |
| 세부 목표 | 제한 없음 | **금지**(종료+신설) | **매긴다** | 측정 가능한 성과 단위 |

### 왜 이 배치인가

**GAS를 세부 목표에 둔 것이 이 ADR의 중심이다.** 그래야 D12의 원래 취지(점수 이력 연속성)를 점수가 실제로 붙는 층에서만 강제할 수 있다. 위층은 점수를 지고 있지 않으므로 자유롭게 고쳐도 이력이 깨지지 않는다 — Q가 요구한 "전체 목표는 수정 가능"이 D12를 어기지 않고 성립한다.

대안이었던 "전체 목표에 GAS"는 게이지가 1개로 단순해지는 대신 "자립 +1"이 무엇이 나아진 것인지 말해주지 못한다. "세션 목표에 GAS"는 기록 시점은 자연스럽지만 누적 진척이 아니라 회차 만족도에 가까워져 GAS 본래 목적과 멀어진다.

## 세부 목표와 액션 아이템의 경계

층을 늘릴 때 가장 흔한 실패는 새 층이 기존 개념과 겹쳐 같은 내용이 두 군데 쌓이는 것이다. 명시적으로 가른다.

| | 세부 목표 | 액션 아이템(다음 행동) |
|---|---|---|
| 묻는 것 | **상태가 나아졌나** | **하기로 한 걸 했나** |
| 기록 | GAS -2~+2 | 완료 / 진행 중 / 못 함 / 보류 |
| 기간 | 여러 회차에 걸침 | 다음 상담까지 |
| 예 | "연체 2건 상환 합의" | "주민센터 방문해 서류 떼기" |

**둘은 별개 테이블로 유지하고, 액션 아이템이 세부 목표를 선택적으로 참조한다**(필수 아님). 액션을 세부 목표 아래로 완전히 편입하는 안은 기각했다 — 목표에 엮이지 않는 단순 심부름까지 억지로 목표를 만들게 되기 때문이다.

## 브리핑 화면

**진행 중인 세부 목표만 최대 3개**를 게이지로 표시한다. 종료된 세부 목표는 게이지에서 빠지고 이력에만 남는다. 현재 화면 설계(가로 3개 라디얼 + 미니 추이)를 그대로 쓸 수 있고 "5분 전에 열어 15초 안에 훑는다"는 제약도 유지된다.

진행 중인 세부 목표가 4개 이상일 때 무엇을 보일지는 **최근 갱신순 3개 + "외 N개"** 로 한다. 상담 직전에 필요한 것은 전체 목록이 아니라 지금 움직이고 있는 것이기 때문이다. 이 규칙은 실사용 후 재검토 대상이다.

전체 목표는 게이지 없이 HERO 아래 한 줄로 표시한다(방향 확인용).

## 기존 데이터

이 결정 시점에 **실제 참여자 데이터는 없다** — 운영·미리보기 DB의 참여자는 전부 가상 인물 시드다. 따라서 이전 비용이 가장 싼 시점이다.

**기존 목표는 전부 세부 목표로 내리고, 전체 목표는 빈칸으로 둔다.** 점수 이력은 세부 목표가 점수 단위가 되므로 그대로 보존된다. 전체 목표는 다음 상담 때 상담사가 직접 적는다 — 첫 목표를 자동으로 승격시키는 안은 기각했다. 그 목표가 정말 "전체 방향"인지 알 수 없는데도 화면상 확정된 것처럼 보이게 만들기 때문이다.

## 결과

- D12의 "1~3개" 상한은 **전체 목표 1개 + 세부 목표 무제한**으로 대체된다. Q가 겪은 "3개 초과 거부"는 사라진다.
- D28의 "세션 목표는 케이스 목표의 하위"는 **"세션 목표는 전체 목표의 하위, 세부 목표는 세션 목표의 하위"**로 대체된다.
- CONTEXT.md 용어 3건(케이스 목표·세션 목표·GAS) 개정 필요. "케이스 목표"는 "전체 목표"로 명칭 변경.
- 마이그레이션 필요: `goals` 테이블에 층 구분과 상위 참조, `action_items`에 세부 목표 참조(선택).

## 미결

- 세부 목표 개수 상한을 둘지 — 지금은 무제한. 실사용에서 과다 생성이 관찰되면 재검토한다.
- 진행 중 세부 목표 4개 이상일 때의 표시 규칙(최근 갱신순 3개)은 실사용 후 재검토.
- 전체 목표 수정 시 이력을 남길지 — 점수가 붙지 않아 이력 연속성 문제는 없으나, 방향이 언제 왜 바뀌었는지는 사례관리상 의미가 있을 수 있다.
