## 1. 결론

1. **실시간이 나빴던 건 마이크나 모델 탓이 아니라 '실시간 방식' 탓이다.** 같은 녹음을 배치로 다시 전사하자 세 엔진 모두 실시간 터미널 출력과 비교할 수 없게 좋아졌다. 스트리밍은 짧은 조각을 문맥 없이 즉시 디코딩하므로 구조적으로 불리하다. (별건: 저장된 실시간 출력 1건은 한국어 발화가 **영어로** 적혀 있었다 — 언어 미고정 시 whisper의 번역 드리프트. rec-md에 `-l ko` 고정 필요.)
2. **whisper large-v3는 가드 없이 배치로 돌리면 위험하다 — 이번에도 붕괴했다.** 대화 녹음(34분)에서 17:44부터 끝까지 약 16분(전체의 48%)을 같은 문장 254연속 반복으로 잃었고, 마지막에 "다음 영상에서 만나요!"라는 유튜브식 날조 멘트까지 만들었다. 발표 녹음(36분)에서도 19초 루프 1회. 언컨퍼런스 실측(121줄 반복)과 동일한 실패 모드의 재현이다.
3. **Apple(SpeechAnalyzer)과 Qwen3-ASR-1.7B는 두 파일 모두 반복 0회로 끝까지 전사했다.** 근접 대화 녹음에서는 둘이 막상막하, 어려운 음향(발표/원거리)에서는 Apple이 내용을 가장 많이 흘렸다(출력량 최소). Qwen이 두 파일 모두에서 가장 안정적으로 내용을 보존했다.
4. **CCC 시사점**: "Qwen 1순위 + Whisper는 VAD·가드 필수 폴백"이라는 검증 브리프(같은 날짜) 결론이 새 녹음 2개에서 재확인됐다. 속도는 Apple 압도적(67분 파일을 64초, 약 63배속) — 맥에서의 교차검토용으로 최적.

## 4. 해석과 적용

1. **왜 실시간은 별로였나**: 스트리밍은 (a) 3~8초 조각 단위 디코딩이라 문맥이 없고, (b) greedy 디코딩 위주며, (c) 언어 미고정 시 영어 번역으로 드리프트한다(저장된 18:08 출력이 그 증거). 같은 오디오의 배치 전사는 전체 문맥 + beam search + 언어 고정을 쓴다. **rec-md의 "종료 후 정밀 재전사" 설계(v2)가 옳았고, 미리보기는 참고용으로만 취급할 것. rec-md whisper-stream 경로에 `-l ko` 고정 반영 권장.**
2. **whisper를 계속 쓰려면**: 검증 브리프 §6대로 VAD 무음 경계 ≤30초 청크 + 환청 억제 파라미터가 필수다. 이번 실측은 "정규화+beam5만으로는 부족하다"의 직접 증거다.
3. **CCC 게이트에 주는 근거**: G2(대화체 실오디오) 지표에 "반복 환청 0건"을 넣은 것이 정당함이 재확인됐다. 이번 두 파일은 행사 녹음이므로 상담 조건(조용한 방, 2인)에서의 최종 실측은 여전히 필요하다.
4. **맥 사용자용 실무 조합**(rec-md): 즉시성 = Apple(음성 메모/yap, 63배속), 보존성·정확 = Qwen 배치, whisper는 가드 갖춘 경우만.
