# 한국어 특화 로컬 STT 모델 조사

- 작성일: 2026-07-11
- 대상 환경
  - A: M4 Pro, 통합 메모리 24GB, macOS 26.5.2
  - B: Windows + WSL2 + RTX 5070 Ti, VRAM 12GB
- 기준선: `whisper.cpp 1.9.1 + large-v3 + speechnorm + beam size 5 + 고유명사 프롬프트`
- 민감정보 원칙: 테스트 음성은 외부 서비스나 API로 전송하지 않음

---

## 1. 한눈에 보는 결론

### 결론부터

**공개 자료만으로 “한국어에서 Whisper large-v3보다 확실히 우수하다”는 조건까지 완전히 증명된 로컬 모델은 아직 0개다.**

이유는 단순하다.

- Apple은 실제 사용자 샘플에서 가장 좋아 보이지만 한국어 WER/CER를 공개하지 않았다.
- Qwen3-ASR-1.7B는 한국어 단독 CER를 공개했지만, 같은 표에 Whisper의 한국어 단독 수치가 없다.
- 한국어 파인튜닝 Whisper 중 수치가 뛰어난 모델들은 라이선스 미표기가 많다.
- NVIDIA 한국어 모델은 WSL2·12GB 제약과 한국어 단독 수치 부재가 겹친다.

따라서 이번 조사의 올바른 결론은 “즉시 교체”가 아니라 다음의 **2개 최우선 검증안**이다.

### 최종 추천

1. **환경 A·B 공통 1순위: Qwen3-ASR-1.7B**
   - Apache-2.0, 한국어 공식 지원, 한국어 단독 CER 공개, 장시간 처리 지원.
   - M4 Pro에서는 MLX 포트가 약 3.4GB 메모리로 실행된다.
   - CUDA에서는 BF16 배치 1 기준 약 5~6GB 추정이라 12GB에 여유가 있다.
   - CCC까지 이어질 수 있는 유일한 강한 공통 후보다.

2. **환경 A 실사용 1순위: Apple SpeechAnalyzer + `yap`**
   - Voice Memos에서 이미 현행 Whisper보다 육안상 우위가 관찰됐다.
   - macOS 26 시스템에서 한국어 전사 자산이 직접 확인됐다.
   - 완전 온디바이스, 장시간·원거리·회의 음성을 목표로 설계됐다.
   - 단, 공개 한국어 WER/CER가 없으므로 정식 채택 전 자체 CER 측정이 필수다.

### 추천하지 않는 것

- **Voxtral Mini 4B Realtime**: 한국어 FLEURS에서 최장 지연 설정도 Whisper와 동률이고 Common Voice 한국어에서는 더 나쁘다. VRAM도 공식 최소 16GB라 환경 B에 맞지 않는다.
- **NVIDIA Parakeet/Canary 한국어판**: WSL2 미지원 또는 12GB 초과, 한국어 단독 WER/CER 부재.
- **라이선스 없는 한국어 Whisper 파인튜닝**: 수치가 좋아도 내부 업무 사용 기준상 탈락.
- **ETRI·리턴제로·클로바 API**: 외부 전송이므로 탈락.

## 2. 판정 기준과 근거 등급

### 필수 통과 기준

1. 녹음 외부 전송 없는 로컬 실행
2. 명시적 라이선스와 내부 업무 사용 가능성
3. 환경 A 또는 B에서 실행 가능
4. 30분 이상 녹음 처리 가능
5. 한국어 WER/CER 수치 존재

### 근거 등급

- **A: 직접 확인**
  - 공식 저장소·논문·모델 카드, 로컬 시스템 파일, 실제 사용자 샘플 관찰
- **B: 강한 간접 근거**
  - 같은 공식 평가에서 한국어 단독 수치는 있으나 Whisper 한국어 단독 행이 없음
- **C: 참고**
  - 다국어 평균, 영어 회의·잡음 수치, 제3자 VRAM 추정

“다국어 평균에 한국어가 포함됐다”는 사실만으로 한국어 성능을 증명했다고 보지 않았다.

## 4. 후보 1: Qwen3-ASR-1.7B

| 항목 | 내용 |
|---|---|
| 모델/엔진 이름 | [Qwen/Qwen3-ASR-1.7B](https://huggingface.co/Qwen/Qwen3-ASR-1.7B), [공식 저장소](https://github.com/QwenLM/Qwen3-ASR) |
| 라이선스 | [Apache-2.0](https://github.com/QwenLM/Qwen3-ASR/blob/main/LICENSE). 내부·상업적 사용 가능. 저작권·NOTICE 보존 필요 |
| 실행 환경 | B: 공식 PyTorch/Transformers/vLLM. A: [mlx-qwen3-asr](https://github.com/moona3k/mlx-qwen3-asr), Apache-2.0 |
| 필요 메모리 | MLX 1.7B 약 3.4GB. CUDA BF16 배치 1은 약 5~6GB 추정. RTX 12GB에서 배치 1 권장 |
| 한국어 성능 | 공식 논문 부록: Common Voice-ko CER **5.88%**, MLC-SLM-ko CER **8.61%**, FLEURS-ko CER **2.57%** |
| 긴 녹음 | 공식 모델이 long audio 지원. MLX 포트는 저에너지 경계로 자동 분할, 청크당 최대 20분 |
| 설치 난이도 | 맥: 낮음. CUDA: 중간. vLLM보다 우선 Transformers 배치 1로 검증 권장 |

### 수치를 어떻게 읽어야 하나

Qwen 논문 부록의 한국어 행은 모델 크기별로 다음과 같다.

| 한국어 데이터셋 | 0.6B | 1.7B | API 전용 Flash |
|---|---:|---:|---:|
| Common Voice-ko CER | 8.48% | **5.88%** | 3.82% |
| MLC-SLM-ko CER | 10.31% | **8.61%** | 8.09% |
| FLEURS-ko CER | 3.72% | **2.57%** | 2.07% |

출처: [Qwen3-ASR Technical Report v2, Appendix](https://arxiv.org/html/2601.21337v2)

1.7B가 0.6B보다 모든 한국어 공개셋에서 낫다. 품질 우선 목적이므로 0.6B를 먼저 채택할 이유는 없다.

### Whisper 대비 근거의 정확한 한계

공식 다국어 평균에서는 Qwen3-ASR-1.7B가 Whisper large-v3보다 낫다.

| 평가셋 | Whisper large-v3 | Qwen3-ASR-1.7B |
|---|---:|---:|
| Common Voice, 13개 언어 평균 | 10.77 | **9.18** |
| MLC-SLM, 11개 언어 평균 | 15.68 | **12.74** |
| FLEURS, 12개 언어 평균 | 5.27 | **4.90** |

그러나 논문 부록의 한국어 단독 표에는 Qwen 계열만 있고 Whisper 수치는 없다. 따라서 위 표는 **B등급 근거**다. 실제 행사 녹음에서 large-v3보다 낫다는 최종 판정은 아직 하지 않는다.

### 원거리·잡음 조건에 대한 기대와 한계

- Qwen은 공식적으로 복잡한 음향 환경과 long audio를 강조한다.
- 중국어 내부 ExtremeNoise 평가에서는 Whisper 63.17 대비 Qwen3-ASR-1.7B 16.17로 크게 좋다.
- 하지만 이 값은 중국어 내부 데이터이므로 한국어 원거리 회의의 직접 근거가 아니다.
- 사용자의 15분대 다중 화자와 25분대 반복 환청 구간을 반드시 확인해야 한다.

### 환경 A 설치·테스트

```bash
brew install python@3.12 ffmpeg
python3.12 -m venv ~/.venvs/qwen3-asr
source ~/.venvs/qwen3-asr/bin/activate
pip install -U mlx-qwen3-asr
mlx-qwen3-asr --doctor
```

전체 파일 품질 우선 전사:

```bash
mlx-qwen3-asr \
  ~/DEVELOPER/TOOLS/live-transcribe/testdata/샘플-원거리-언컨퍼런스.m4a \
  --model Qwen/Qwen3-ASR-1.7B \
  --language Korean \
  --context "뉴웨이즈 온보딩데이 이수진 의원 전주 안양 민주당" \
  -f txt \
  -o ~/Documents/transcripts/qwen3-1.7b/
```

타임스탬프가 필요하면:

```bash
pip install -U "mlx-qwen3-asr[aligner]"
mlx-qwen3-asr <파일> \
  --model Qwen/Qwen3-ASR-1.7B \
  --language Korean \
  --timestamps \
  -f json \
  -o ~/Documents/transcripts/qwen3-1.7b/
```

### 환경 B 설치·테스트

WSL2의 새 Python 3.12 가상환경에서 먼저 공식 Transformers 경로를 사용한다.

```bash
python3.12 -m venv ~/.venvs/qwen3-asr
source ~/.venvs/qwen3-asr/bin/activate
pip install -U qwen-asr
```

공식 예제에서 다음 값을 사용한다.

- 모델: `Qwen/Qwen3-ASR-1.7B`
- `device_map="cuda:0"`
- `dtype=torch.bfloat16`
- `max_inference_batch_size=1`
- 언어: `Korean`
- 긴 파일은 10~15분 또는 VAD 기반 청크

처음부터 vLLM 서버를 붙이지 않는 이유는 설치 변수가 늘어나기 때문이다. 품질 검증을 통과한 뒤 처리량이 필요할 때만 vLLM으로 옮기는 편이 안전하다.

## 5. 후보 2: Apple SpeechAnalyzer + yap

| 항목 | 내용 |
|---|---|
| 모델/엔진 이름 | [Apple SpeechTranscriber](https://developer.apple.com/documentation/speech/speechtranscriber), CLI [finnvoor/yap](https://github.com/finnvoor/yap) |
| 라이선스 | `yap`은 [CC0-1.0](https://github.com/finnvoor/yap/blob/90d76546ce9b6085759b8dd19465d1556766543e/LICENSE). Apple 모델은 오픈 가중치가 아닌 macOS SDK 구성요소. 문서화된 API의 내부 사용은 가능하나 모델 추출·재배포 불가 |
| 실행 환경 | A 전용, macOS 26+ |
| 필요 메모리 | 모델은 OS 관리 프로세스에서 실행. 앱 자체 메모리와 분리 |
| 한국어 성능 | 공개 한국어 WER/CER 없음. 사용자 Voice Memos 결과가 현행 Whisper보다 육안상 우수 |
| 긴 녹음 | SpeechAnalyzer가 파일 전체·long-form·회의·원거리 오디오를 공식 목표로 함 |
| 설치 난이도 | 매우 낮음. `brew install yap` |

### 한국어 지원 검증

이 맥의 다음 시스템 파일을 직접 확인했다.

```text
/System/Library/UnifiedAssetFramework/AssetSets/
com.apple.speech.automaticspeechrecognition.plist
```

- 지원 언어 배열에 `ko` 존재
- 설치 자산 `com.apple.speech.asr.transcription.ko`
- 설치 버전 `3100.44005.81619.13.302159`

Apple 공식 문서는 언어 목록을 정적 표로 고정하지 않고 기기에서 `SpeechTranscriber.supportedLocales`를 조회하도록 설계한다. 위 시스템 자산과 실제 한국어 Voice Memos 전사 경험을 합치면 이 장비의 한국어 지원은 사실상 확인됐다고 볼 수 있다.

### 정확도 근거의 공백

- Apple·Argmax가 공개한 숫자는 영어 Earnings22 WER 14.0이다.
- 한국어 WER/CER는 찾지 못했다.
- 따라서 엄격한 필수조건 5에는 아직 미달이다.
- 다만 사용자의 동일 녹음 관찰은 연구 방향을 정하는 매우 강한 현장 근거다.

Apple·Argmax 영어 비교: [Apple and Argmax](https://www.argmaxinc.com/blog/apple-and-argmax)

### 장점

- 녹음이 기기 밖으로 나가지 않는다.
- macOS가 모델 자산을 관리한다.
- 긴 파일, 원거리, 강의, 회의, 대화용으로 발표됐다.
- `yap`은 TXT·SRT·VTT·JSON·단어 타임스탬프를 지원한다.
- 첫 자산 다운로드 후 전사는 로컬이다.

### 한계

- 환경 B와 CCC에는 사용할 수 없다.
- Whisper의 고유명사 프롬프트와 같은 사용자 어휘 기능이 현재 없다.
- Apple 모델 버전이 OS 업데이트에 따라 바뀔 수 있어 재현성 관리가 필요하다.
- 공개 한국어 수치가 없어 자체 정답셋을 유지해야 한다.

### 설치·테스트

```bash
brew install yap
yap transcribe \
  --locale ko-KR \
  ~/DEVELOPER/TOOLS/live-transcribe/testdata/샘플-원거리-언컨퍼런스.m4a \
  --json \
  --word-timestamps \
  -o ~/Documents/transcripts/apple-speechanalyzer.json
```

간단한 텍스트만 필요하면:

```bash
yap transcribe --locale ko-KR <파일.m4a> --txt -o <결과.txt>
```

실사용 래퍼는 `yap`을 추천한다. [Argmax 예제 CLI](https://github.com/argmaxinc/apple-speechanalyzer-cli-example)는 MIT이지만 기능과 관리 상태가 최소 예제 수준이다.

### 6.2 SpeechBrain ReturnZero Conformer

| 항목 | 내용 |
|---|---|
| 저장소 | [speechbrain/asr-conformer-transformerlm-ksponspeech](https://huggingface.co/speechbrain/asr-conformer-transformerlm-ksponspeech) |
| 라이선스 | Apache-2.0 |
| 환경 | B, CUDA 12GB에 충분 |
| 성능 | KsponSpeech eval-clean CER 7.33%, eval-other 7.99% |
| 긴 파일 | 자체 30분 처리 없음. VAD 또는 20~30초 청크 필요 |

2022년 모델이고 깨끗한 KsponSpeech 중심이다. 현재 Whisper large-v3보다 원거리·잡음에서 나을 근거가 없다.

**판정: 가벼운 한국어 전용 기준선. 최종 추천 아님.**

## 7. 탈락 후보와 이유

### 7.1 Voxtral Mini 4B Realtime 2602

- Apache-2.0, 한국어 지원, 무제한 스트리밍 구조.
- 공식 BF16 최소 VRAM 16GB로 환경 B의 12GB를 초과.
- FLEURS-ko:
  - Whisper 14.30%
  - Voxtral 480ms 15.74%
  - Voxtral 2400ms 14.30%
- Common Voice-ko:
  - Whisper 20.86%
  - Voxtral 2400ms 25.26%

출처: [모델 카드](https://huggingface.co/mistralai/Voxtral-Mini-4B-Realtime-2602), [기술 보고서](https://arxiv.org/html/2602.11298v1)

**탈락: 한국어 우위 없음 + 12GB 제약 위반.**

### 7.2 NVIDIA Parakeet/Canary 한국어판

- Parakeet-RNNT-1.1B multilingual은 한국어를 지원하지만 오프라인 VRAM 약 10.8GB로 매우 빡빡하다.
- Canary 1B Riva multilingual은 약 13.4GB, 0.6B Turbo는 약 12.2GB다.
- 공식 지원표에서 해당 한국어 Riva/NIM 계열은 WSL2 미지원이다.
- 한국어 단독 WER/CER가 없다.
- NVIDIA Community Model License는 Apache/MIT보다 조건이 복잡하다.

**탈락: 환경 B와 수치 근거 미충족.**

### 7.3 한국어 Whisper 파인튜닝

`ghost613/whisper-large-v3-turbo-korean`은 Zeroth 테스트에서 baseline CER 7.58%를 2.06%로 낮춘다. 그러나 모델 저장소에 라이선스가 명시되지 않았다.

- 모델: https://huggingface.co/ghost613/whisper-large-v3-turbo-korean

`o0dimplz0o/Whisper-Large-v3-turbo-STT-Zeroth-KO-v2`도 같은 라이선스 문제로 탈락한다.

**탈락: 수치가 좋아도 내부 업무 사용의 법적 근거가 없음.**

### 7.4 ENERZAi EZWhisper KR

- KsponSpeech eval-other에서 Whisper large-v3 CER 11.13%를 제시한다.
- 50,000시간 한국어 학습 모델이 large-v3보다 작고 정확하다고 보고한다.
- 그러나 다운로드 가능한 가중치, 명시적 모델 라이선스, 공개 실행 저장소가 없다.

출처: [ENERZAi 기술 글](https://enerzai.com/resources/blog/small-models-big-heat-conquering-korean-asr-with-low-bit-whisper)

**탈락: 현재는 구매·협업 대상 제품이지 설치 가능한 공개 로컬 모델이 아님.**

### 7.5 ETRI·상용 한국어 API

리턴제로 벤치마크의 평균 CER 참고값:

- 리턴제로 6.18%
- 리턴제로 Whisper 7.79%
- Naver ClovaSpeech 9.52%
- ETRI 10.19%
- OpenAI Whisper 11.39%

출처: [Awesome Korean Speech Recognition / RTZR benchmark](https://blog.rtzr.ai/korean-speechai-benchmark/)

이 수치는 한국어 서비스 지형을 이해하는 참고자료일 뿐이다. 모델 가중치가 공개되지 않았거나 외부 API이므로 이번 조건에서는 모두 탈락한다. 또한 이 벤치마크의 “OpenAI Whisper” 버전이 large-v3인지 명확하지 않아 현재 기준선과 직접 비교하면 안 된다.

## 8. 실제 샘플 검증 설계

### 가장 중요한 원칙

자동 전사본끼리 비교하면 CER를 계산할 수 없다. 0·15·25분대의 짧은 구간을 사람이 직접 정답 전사해야 한다.

### 권장 구간

| 구간 | 길이 | 이유 |
|---|---:|---|
| 00:00~03:00 | 3분 | 일반 대화, 고유명사·정치 용어 확인 |
| 14:30~17:30 | 3분 | 다중 화자 토론, turbo 붕괴 지점 |
| 24:30~27:30 | 3분 | 현행 최선도 반복 환청이 남는 변별 구간 |

9분 전체가 부담되면 각 구간 2분, 총 6분으로 시작해도 된다.

### 로컬 클립 만들기

```bash
cd ~/DEVELOPER/TOOLS/live-transcribe
mkdir -p testdata/eval-clips

ffmpeg -i testdata/샘플-원거리-언컨퍼런스.m4a -ss 00:00:00 -t 180 -ar 16000 -ac 1 testdata/eval-clips/00m.wav
ffmpeg -i testdata/샘플-원거리-언컨퍼런스.m4a -ss 00:14:30 -t 180 -ar 16000 -ac 1 testdata/eval-clips/15m.wav
ffmpeg -i testdata/샘플-원거리-언컨퍼런스.m4a -ss 00:24:30 -t 180 -ar 16000 -ac 1 testdata/eval-clips/25m.wav
```

### 비교할 출력

1. 현행 비교3 Whisper
2. Apple SpeechAnalyzer raw 입력
3. Qwen3-ASR-1.7B raw 입력
4. 선택: Qwen3-ASR-1.7B speechnorm 입력

Apple에는 고유명사 힌트를 줄 수 없으므로 두 가지 점수를 따로 본다.

- **음향 복원력**: 일반 문장, 누락, 환청, 반복
- **용어 정확도**: 인명·단체명·지역명

### 정량 지표

- 공백·문장부호를 제거한 한국어 CER
- 반복 문장 횟수
- 5초 이상 무음에서 생성된 환청 횟수
- 10초 이상 통째 누락된 구간 수
- 고유명사 정확 개수 / 전체 고유명사 개수

### 채택선 제안

- Qwen 또는 Apple이 비교3보다 CER를 **상대 15% 이상 감소**
- 25분대 반복 환청이 **0~1건**
- 긴 누락이 증가하지 않음
- 고유명사 정확도가 비교3보다 크게 악화되지 않음

CER 차이가 5% 이내면 모델을 교체하기보다 현행 Whisper와 병행 모드로 두는 편이 안전하다.

## 9. rec-md와 CCC에 대한 권고

### rec-md

단계적 반영을 권한다.

1. `--engine whisper|apple|qwen` 선택지를 만든다.
2. 기본값은 검증 완료 전까지 현행 Whisper를 유지한다.
3. Apple·Qwen 결과를 같은 Markdown 포맷으로 내보낸다.
4. 6~9분 정답셋에서 통과한 엔진만 기본값 후보로 승격한다.
5. Apple은 OS 모델 버전을 결과 파일에 기록한다.

실무 예상:

- 맥의 개인 녹취 기본: Apple이 이길 가능성이 높음
- 고유명사 프롬프트가 중요한 행사: Qwen 또는 Whisper가 일부 구간에서 유리할 수 있음
- 장기적으로는 Qwen이 맥·CCC 공통 파이프라인을 단순화할 가능성이 있음

### CCC

현 시점 적합성:

| 후보 | CCC 적합성 |
|---|---|
| Qwen3-ASR-1.7B | **가장 높음**. Apache-2.0, CUDA 12GB, 로컬, 한국어 수치 존재 |
| Cohere Transcribe | 보조 실험. 상담·무음에서 VAD 필수 |
| SpeechBrain ReturnZero | 오래된 가벼운 기준선 |
| Apple | 사용 불가, 맥 전용 |
| NVIDIA 한국어 NIM | 현재 WSL2·12GB 구성에 부적합 |

CCC 반영 전에는 반드시 실제 상담과 유사한 비식별 샘플로 별도 검증해야 한다. 행사장 녹음과 전화·상담 음성은 오류 양상이 다르다.

## 10. 이번 세션의 로컬 검증 상태

### 확인 완료

- 테스트 음성 위치와 크기 확인: 약 48MB, 29분
- 비교1·2·3 전사본 확인
- 비교3의 25분대에서 동일 문장이 30초 이상 반복되는 실패 확인
- macOS 26.5.2의 한국어 SpeechTranscriber 자산 설치 확인
- `yap` CC0 라이선스와 구현 확인
- Qwen3-ASR·MLX 포트 라이선스, 한국어 수치, 장시간 처리, 메모리 요구 확인
- Qwen MLX 패키지를 격리된 임시 Python 환경에 설치하는 단계까지 확인

### 이 세션에서 실행하지 못한 것

Aside 에이전트 실행 환경은 Speech.framework 프로세스를 OS가 종료했고, MLX에서는 Metal 장치를 노출하지 않았다. 따라서 이 세션 안에서 Apple·Qwen으로 29분 파일 전사를 완료하지 못했다.

이것은 사용자 맥의 호환성 실패가 아니다.

- 같은 맥의 일반 터미널에서는 Speech.framework와 Metal에 접근 가능하다.
- MLX 포트는 M4 Pro·macOS 26.2 실측을 공개한다.
- `yap`은 macOS 26용 배포 바이너리를 제공한다.

테스트 음성은 어떤 외부 API에도 업로드하지 않았다.
