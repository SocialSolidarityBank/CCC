## 1. 결론부터

**질문**: CCC 상담은 전부 맥을 쓸 수 없다. 회사 노트북(RTX 5070 Ti Laptop 12GB, WSL2) 로컬 배치 처리로, Apple(맥 음성 메모) 수준에 최대한 가까운 한국어 녹취록을 뽑을 수 있는가?

**답: 가능성이 높다. 다만 모델 하나로 되는 게 아니라 3축이 필요하고, 최종 확정은 실측 게이트 3개를 통과해야 한다.**

1. **녹음(캡처) 표준화가 가장 큰 레버다.** Apple 우위의 "모델 기여분"은 한국어에서 공개 근거로 입증된 게 없다(입증된 우위는 주로 속도). 반면 마이크 거리·SNR은 오류율을 3배 이상 가른다(근접 4.2% vs 원거리 14.3% WER). 조용한 상담실 + 테이블 중앙 근접 마이크만 표준화해도, 기존 테스트(행사장 원거리)보다 CER가 크게 내려간다 — 이건 애플 기기가 아니어도 얻는 이득이다.
2. **모델은 Qwen3-ASR-1.7B 1순위 유지.** 적대적 반박 검증에서도 핵심 랭킹이 생존했다(Apache-2.0·한국어 수치·타임스탬프 경로 모두 1차 출처 확인). 단 실측 A/B에 도전자 2개를 추가한다: Cohere Transcribe 03-2026(2026-04 릴리스, 롱폼 강점)과 Dolphin small(조건부).
3. **배치라서 살 수 있는 품질을 다 사라.** VAD 무음 경계 청크, 반복 환청 자동 검사, 상담 용어집 주입(context), 가명화-Claude 단계에 용어집 한정 교정+문장부호 복원을 얹는다. CCC는 실시간이 필요 없으므로(SLA 다음 영업일) 처리 시간으로 품질을 사는 설계가 옳다.

**실측 게이트 3개(이걸 통과해야 "채택 확정")**:
- G1. Qwen3-ASR-1.7B가 실제 노트북(Blackwell sm_120 + WSL2)에서 구동되는가
- G2. 한국어 **대화체 실오디오**(비식별 상담 유사 샘플)에서 CER·반복 환청률이 수용 기준을 넘는가 — 공개 수치는 전부 낭독체라 상담 성능을 보증하지 않는다
- G3. head-to-head: Qwen vs Cohere vs Dolphin vs Whisper-large-v3(폴백) 동일 샘플 비교

## 2. 왜 "비맥으로도 근접 가능"인가 — Apple 우위 분해

| 축 | 근거 | 판정 |
|---|---|---|
| Apple **모델**이 한국어에서 더 정확하다 | 공개 한국어 벤치마크 없음. 입증된 우위는 속도(Whisper 대비 약 55% 빠름). "중급 Whisper와 대등, 장문·전문용어는 대형 Whisper 우세" 보고 | **UNVERIFIED — 좇을 근거 약함** |
| Apple **캡처**(마이크·녹음 처리)가 좋다 | 다중 마이크·빔포밍 하드웨어는 실재. 단 Voice Memos 파일 녹음에 어떤 처리가 적용되는지 공식 미확인 | 부분 사실, 정량 불가 |
| **거리·SNR**이 오류율을 지배한다 | 근접(랩) 4.2% vs 단일 원거리 14.3% WER(Kumatani et al., IEEE), 20dB 이하 SNR에서 급격 악화 | **CONFIRMED — 최대 레버** |
| 상담실은 기존 테스트보다 쉬운 조건이다 | 기존 실측은 행사장 원거리·다중 화자(-36.8dB 평균 음량). 상담은 조용한 실내·2인·근접 배치 가능 | **CONFIRMED(추론 타당)** |

**함의**: 사용자가 관찰한 "맥이 워낙 좋다"의 상당 부분은 (조용한 환경에서) 기기를 가까이 두고 녹음한 캡처 품질이다. 비맥 환경에서 같은 캡처 조건을 만들고, 낭독체 벤치 최상위권 오픈 모델을 쓰면 격차의 대부분을 회수할 수 있다. 남는 불확실성은 "대화체·실환경"뿐이고, 그건 G2 실측으로만 닫힌다.

- **HF 커뮤니티 반복 출력 보고**: Qwen3-ASR-1.7B discussions #23 "Endless repetition in output"(재현됨, temperature 상향으로 완화), #25 "2분 파일이 20초만 전사". `yellow` LLM-ASR 계열 공통 실패 모드로, 침묵·간투사 많은 상담 녹취에서 촉발되기 쉽다 → G2 게이트에 반복률 지표를 넣는 이유.
- **Cohere Transcribe 03-2026 재평가 필요**: 기존 조사(7/11)는 "보조 실험, VAD 없이 채택 금지"로 분류했는데, 이후 검증에서 Apache-2.0 · 2B · **네이티브 롱폼 청킹(55분 실증)** · Open ASR Leaderboard 평균 1위(WER 5.42%)가 확인됐다. 한국어 CER 정확값은 미공개(그래프만)라 정확도 우열은 미확정 — **G3 head-to-head 참가자로 승격**하되 기존 경고(무음·비음성 환청 경향, VAD 필수)는 유지.

**탈락 유지(배치 완화로도 부활 못 함)**: Voxtral Mini 3B(한국어 미지원 — 지원 언어 8개에 ko 없음, FLEURS 표에 ko 행 자체가 없음), NVIDIA parakeet/canary v2·v3(유럽 25개 언어 전용; 단 탈락 사유가 "WSL2 미지원"이 아니라 "한국어 미지원"으로 교체 — Riva 없이 NeMo 직접 실행은 가능했다), NVIDIA Nemotron 3.5 ASR(한국어 지원·클린 라이선스지만 FLEURS-ko CER 7.12로 Qwen의 2.8배), CrisperWhisper(CC-BY-NC + 영/독 전용), Kimi-Audio(한국어 근거 없음+7B), Granite Speech(한국어 미지원), Kanana 오디오(가중치 미공개+NC), SenseVoice-Small(한국어 수치 전무+커스텀 라이선스), 무라이선스 한국어 파인튜닝(여전히 무라이선스).

## 5. 처리 장비 적합성 (회사 노트북)

- **GPU 확정**: RTX 5070 Ti **Laptop** = 12GB GDDR7(데스크톱 16GB와 다른 부품), Blackwell, compute capability **sm_120**. 데스크톱 벤치·수치를 그대로 대입하면 안 됨.
- **소프트웨어 경로 확정**: PyTorch **2.7.0 이상 + cu128(또는 cu130) 휠** 필수 — 구버전 stock 휠은 "no kernel image" 오류. cu126은 Blackwell 미지원. WSL2는 최신(dxgkrnl 개선판)으로. `red` **WSL 안에 리눅스 NVIDIA 드라이버를 설치하지 말 것**(Windows 드라이버 패스스루를 깨뜨림).
- **VRAM 예산(순차 실행 전제)**: Qwen 1.7B 추론 ~5-6GB + ForcedAligner ~2GB(동시 로드 시) / pyannote ~1-2GB / 감정 모델 ~1-2GB. 스테이지별 로드→추론→해제(empty_cache)와 청크 처리 전제에서 12GB 안정. 통짜(비청크) 디코딩은 OOM 위험.
- **주의**: FlashAttention2의 sm_120 prebuilt 휠 가용성을 설치 시점에 확인(없으면 청크 길이·배치 축소로 흡수). vLLM은 Blackwell 빌드 마찰이 있어 초기엔 배제 — 배치 SLA에는 Transformers로 충분.
- **화자 분리**: pyannote community-1(가중치 CC-BY-4.0, pyannote.audio 4.x) 채택 검토 — 3.1 대비 화자 배정 개선 + exclusive mode가 2인 상담의 화자↔단어 정렬을 단순화. HF gated(계정 동의+토큰)는 가중치 1회 다운로드 절차일 뿐 데이터 유출이 아님(D13 무관).

## 6. 권장 파이프라인 설계 (현 코드 기준 변경점)

현재 apps/pipeline 코드와의 차분으로 적는다.

1. **transcribe.py — 엔진 교체가 첫 번째 개선이다.** 현재 기본값이 whisper `medium`인데, 이는 기존 실측에서 이긴 large-v3보다도 낮은 급이다. 어떤 결정을 하든 medium 기본값은 상향돼야 한다. 권장: `--engine qwen|whisper` 선택 구조, Segment(start,end,text) 인터페이스 유지.
2. **VAD 청크 단계 신설**: silero-vad(MIT)로 무음 경계 분할. Qwen 경로는 2~5분 병합(타임스탬프 필요 시 ForcedAligner 5분 상한이 청크 상한), Whisper 폴백 경로는 ≤30초 병합 + 환청 억제 파라미터(condition_on_previous_text=False, compression_ratio_threshold=2.4, logprob_threshold≈-1.0, no_speech_threshold=0.6, temperature fallback). Whisper식 30초 고정 컷을 Qwen에 쓰지 말 것(문맥 손실).
3. **화자 정렬 구조는 유지**: 현행 "전사 → pyannote 턴과 겹침 배정"이 주류 구현과 일치함을 확인. Qwen 채택 시 ForcedAligner로 타임스탬프 확보(초기화 시 `forced_aligner=` 지정, `transcribe(..., return_time_stamps=True)`).
4. **상담 용어집 주입**: 기관명·사업명·복지/법률 용어를 Qwen context(시스템 프롬프트)로. 'Proper nouns:'/'Vocabulary:' 프레이밍이 맨 나열보다 낫다. Whisper 폴백은 initial_prompt(마지막 224토큰 캡).
5. **반복 환청 자동 검사**: 저장 전 n-gram 반복 탐지 + 5초 이상 무음 구간 출력 검사. 반복 감지 시 해당 청크 temperature 상향 재전사(HF #23 완화책과 일치). 이 검사는 R2 승인 화면 이전의 기계적 게이트다.
6. **가명화-Claude 단계(기존 R3 경로)에 후처리 통합**: PII 마스킹 후 Claude 호출 한 번에 (a) 용어집 한정 오인식 교정 + (b) 문장부호·문단 복원을 묶는다. `red` 자유 재작성 금지 — "부호·줄바꿈 추가와 용어집 내 교정만, 어절 보존"으로 제약하고, 교정 전후 CER 회귀 측정을 의무화(개선 없으면 롤백). zero-shot 자유 교정은 과교정으로 오류를 늘릴 수 있다는 서베이 근거 있음. 산출물은 기존대로 approved_at 게이트(R2)를 거친다.
7. **이중 전사(앙상블)는 보류**: 단일 모델이 G2 기준 미달일 때만. 그 경우도 GPU 경합 없는 "Claude 다중 가설 융합(Qwen+Whisper 전사를 함께 투입)"을 먼저.

## 7. 녹음(캡처) 표준 — 최대 레버

> 모델보다 이게 먼저다. 행사장 원거리→상담실 근접 전환은 오류율을 지배하는 축(거리·SNR·잔향)을 직접 개선한다.

**장비 3안** (비침습 순, 비용은 국내 유통가 대략치):

| 안 | 구성 | 비용 | 특징 |
|---|---|---|---|
| A(1차 권장) | 테이블 중앙 단일 레코더(Zoom H1essential급) 또는 경계면(PZM) 마이크, 30~60cm | 5~20만원 | 비침습, 라포 방해 최소. 조용한 방+근접만으로 이득 대부분 확보 |
| B(무비용) | 스마트폰 녹음 앱, 두 사람 사이 중앙 근접 배치 | 0원 | 파일럿 시작점. 단일 마이크라 먼 화자 SNR 하락 |
| C(품질 최대) | 2채널 무선 라발리에(상담사·수혜자 각 1) | 20~40만원 | 두 화자 모두 근접 SNR + 채널≈화자로 화자분리 부담 급감(D11 확인 작업 축소). 단 착용 침습성 — 수혜자 수용성 파일럿 필수 |

**C안 주의(적대적 검증 반영)**: "채널=화자"는 순진하게 성립하지 않는다 — 크로스토크(상대 목소리 유입)가 실재하므로 채널별 에너지 비교 게이팅이 필요하고, 옷 스침 소음 관리, **2트랙 분리 보존(모노 다운믹스 금지)**이 전제다. 그래도 근접장 SNR 차이가 커서 게이팅으로 깔끔히 복원된다.

**설정·포맷 표준**:
- 샘플레이트 최소 16kHz(48kHz 무방 — 어차피 16kHz로 리샘플됨, 8kHz는 금지), 무손실 WAV/FLAC 선호(부득이 압축 시 AAC ≥128kbps)
- 기기 노이즈 억제·Voice Isolation·과도한 AGC는 **이 시나리오(조용한 방+강건 ASR)에서는 끈다** — denoising 전처리가 최신 ASR에 오히려 해롭다는 연구(의료 ASR 40개 구성 전부 악화). 단 이는 고SNR 조건 한정 권고다: 실제로 시끄러운 녹음이 들어오면 범주적으로 배제하지 말고 실측 비교. 참고로 삼성 녹음기는 억제 토글이 있고, 아이폰 음성 메모의 Voice Isolation은 기본 꺼짐. AGC는 폰에서 못 끄는 경우가 많다 — 전용 장비(A/C안)가 이를 하드웨어 레벨에서 해결
- 배치: 두 사람 정중앙, 에어컨 송풍구·유리 등 반사면에서 이격, 종이·책상 두드림 주의
- 파이프라인에도 denoising 단을 기본 삽입하지 않는다(위와 같은 근거, Whisper가 아티팩트에 특히 취약)

## 8. 실측 검증 게이트 (채택 조건)

CLAUDE.md §8 미결에는 "감정 모델 실측"만 있고 **ASR 실측 게이트가 누락**돼 있다 — 아래를 추가할 것을 제안한다.

| 게이트 | 내용 | 수용 기준(안) |
|---|---|---|
| G1 하드웨어 | 노트북(sm_120+WSL2)에서 Qwen3-ASR-1.7B+ForcedAligner 구동 스모크 | 10분 샘플 전사 완료, VRAM 피크 <10GB |
| G2 대화체 품질 | 비식별 상담 유사 샘플(2인 대면, 근접 녹음)로 CER·반복률 측정 | 정답 전사 대비 CER ≤ 10%(캡처 표준 적용 시), 반복 환청 0건, 10초+ 통누락 0건 — 파일럿 후 보정 |
| G3 head-to-head | 동일 샘플로 Qwen vs Cohere vs Dolphin vs Whisper(폴백) | CER 최저 + 반복 0 후보를 기본 엔진으로 확정 |

**평가 프로토콜**(도구 전부 허용 라이선스 확인 완료):
- 지표: 한국어는 **CER**(jiwer, Apache-2.0), 화자 귀속은 cpWER(meeteval, MIT). 정규화 규칙 고정: NFC, 공백 통일, 코어 CER은 구두점 제거 후.
- CCC 특수 지표: **수혜자 발화 한정 CER**(감정 분석·GAS 근거 발췌가 화자 귀속에 의존하므로).
- 정답셋: 대표 상담 유사 녹음 5~10건에서 구간 추출, 사람 정답 전사 30~60분 분량으로 시작(차이 판별용). 절대치 안정에는 1~2시간+.
- 기존 문서의 "6분 정답 전사" 계획은 유효 — 위 프로토콜의 축소판으로 즉시 실행 가능.

## 9. 한계

- 모든 후보의 한국어 공개 수치는 낭독체·클린·1화자 조건이다. 상담 대화체 성능은 G2·G3 실측 전까지 미확정이며, 이 브리프의 순위는 사전 확률이다.
- Cohere Transcribe의 한국어 CER 정확값은 미공개(모델 카드 그래프뿐, README 게이트드)라 Qwen과의 정확도 우열은 확인하지 못했다.
- Qwen의 Blackwell(sm_120) 실행은 일반 근거(PyTorch 2.7+ 공식 지원)만 있고 모델 특정 성공 사례는 못 찾았다 — G1이 필요한 이유.
- Dolphin의 최대 우위 근거는 제작사 자체 비공개 테스트셋이다(이해충돌). 독립 한국어 평가는 존재하지 않는다.
- 캡처 관련 정량 근거는 대부분 영어 WER 기준 — 방향성은 이전되나 절대 수치를 한국어 CER로 1:1 환산할 수 없다.
- 웹 조사 시점은 2026-07-12이며, "더 나은 모델 없음"류 부재 주장은 이후 릴리스로 뒤집힐 수 있다.
