# SG2 Authentication and CapabilityManifest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the lossless mode-aware Actor contract, signed installation trust boundary, and secret-free CapabilityManifest for all three deployment modes.

**Architecture:** `packages/contracts/src/runtime.ts` is the authority for the target `Actor { kind, userId, orgId, roles[], scopes[], authn:{source, assurance, sessionId} }` and `Identity { resolve(request); revokeAll(userId, reason); revokeSession(sessionId, reason) }`. Mode adapters resolve Supabase, transitional Access, Local Single, Local Office, Agent service, and scheduler credentials into that shape without collapsing technical-admin into institution-admin. The static Vite client consumes only a verified same-origin install manifest/bootstrap; public join is a fragment-token, one-time capability flow and never an unverified business-data target.

**Tech Stack:** TypeScript 5.9, Web Crypto, RFC 8785 JCS, Ed25519, ES256/RS256 JWT, Supabase Auth, Argon2id, DPAPI CurrentUser, Electron 44, Vite React PWA, encrypted local storage, Python Processing Agent.

**Spec:** `docs/specs/S2-auth-capability-manifest.md`

## Global Constraints

- Community Cloud, Local Single, and Local Office are all first-class modes and use the same API and lossless canonical Actor authorization rules.
- The canonical runtime port is exactly `Identity.resolve(request): Promise<Actor>`, `revokeAll(userId, reason): Promise<void>`, and `revokeSession(sessionId, reason): Promise<void>`, with a closed RevocationReason union.
- `institution-admin`, `technical-admin`, `supervisor`, `worker`, and `service` remain distinct roles. Technical admin has installation/diagnostic/update access only, never case, counselling, or PII business access. Privileged route MFA reads `Actor.authn.assurance`.
- All Community Cloud human roles, including worker and supervisor, require JWT `aal=aal2`; Office privileged roles require `mfaVerifiedAt`; nonprivileged Office workers may continue without privileged MFA.
- Supabase accepts only asymmetric ES256 or RS256 keys selected from JWKS metadata. `session_id` is the revocation claim and `nbf` is checked only when present. HS256 is rejected at D84 preflight and runtime.
- Local Single signs host/scheme/installId/endpoint-discovery policy, not its runtime random port; a DPAPI-protected endpoint record authenticates the discovered loopback port.
- Agent service scopes are exactly claim, heartbeat, result, release, `audio:read`, and `source:read`; routes are POST claim/heartbeat/result/release plus GET job audio/source. Cloud/Local payload delivery differences stay in S5.
- Cloud pg_cron uses a rotating scheduler secret only for the internal scheduler endpoint and never becomes a human Actor; local schedulers call in-process.
- The signed manifest is fixed at `apps/client/public/ccc-install-manifest.json`. Public bootstrap is exactly `{ apiBase: string, mode: DeploymentMode }` and only points same-origin to that manifest. Signed metadata uses RFC 8785 JCS, expiry, sequence, install binding, and embedded signing-key revocation.
- The browser stores no bearer, refresh token, PII, or API response in Web Storage, IndexedDB, Cache API, cookies, URLs, logs, analytics, or crash output. Cloud PWA sessions are memory-only; reload requires login/MFA.
- Exact CORS permits absent Origin only for authenticated non-browser service calls with no CORS headers, and byte-equal allowlisted browser Origins with a fixed response. `Origin: null`, outside origins, wildcard CORS, and credential cookies are prohibited.
- Public join token is fragment-only, body-exchanged, at least 128-bit one-time nonce with TTL at most 15 minutes. It cannot authenticate capabilities or business endpoints.
- Cloudflare Access assertion and preview `ccc_preview` cookie are transitional environment adapters and temporary business-auth exceptions until E2-7; they are outside final canonical Bearer-only auth and are removed from the business path by E2-7.
- `확정` means the contract and fixtures are complete; runtime adapter evidence is required only for implementation verification in owning E tickets.
