# SG10 CCCX v1 포맷 계약 구현 계획

> 이 계획은 SG10 계약 문서만 소유한다. 구현과 실제 복원 증거는 E3-7이 소유하며, 부모 세션이 병렬 worktree를 통합한 뒤 저장소 전체 검증을 실행한다.

**Goal:** Community Cloud, Local Single, Local Office 간 백업·복구와 모드 이전에 사용하는 `.cccx` v1의 암호 envelope, 결정론적 ZIP, schema/row/file 무결성, PII 금고 재암호화와 crash-safe import 경계를 문서로 확정한다.

**Architecture:** CCCX는 `CCCX` magic + canonical JCS header + AES-256-GCM ciphertext envelope다. 복호화 payload는 32-byte inner SHA-256 digest와 고정 metadata deterministic ZIP이며, importer는 S1의 atomic `Database.batch()`와 target `SecretStore`/file encryption 경계만 사용한다. OS rename/Cloud put과 DB commit의 비원자성은 immutable shadow namespace, complete marker·manifest hash와 함께 이루어지는 single atomic visibility pointer transaction, checksummed DB-backed journal/recovery로 보정하여 원본 유지 또는 완전 적용만 허용한다.

**Spec:** `ADR-0041 D83`, `CCC_OPEN_PILOT_PLAN.md` SG10/E3-7, `docs/adr/0042-supabase-read-only-preflight.md`의 secret 출력 금지 규칙, S9 Recovery Kit v1과 S1 Database 포트 계약.

## Global Constraints

- canonical spec은 `docs/specs/S10-cccx-format.md` 하나다. 이 plan과 spec 외 파일, master plan, application code, sibling spec은 수정하지 않는다.
- `확정`은 인터페이스·규칙표·세 모드 차이·fixture·검증 명령이 문서로 완결된 상태다. 실제 adapter, package import, install, restore evidence를 요구하지 않는다.
- magic은 `43 43 43 58 01`, envelope는 `magic[5] || headerLength[4] || headerUtf8 || ciphertext`, headerLength `1..4096`, canonical JCS golden bytes로 고정한다. 평문 payload hash는 header에 두지 않고 ciphertext 안의 32-byte inner digest로 둔다.
- Argon2id v1.3은 `memoryKiB=65536`, `iterations=3`, `parallelism=1`, output 32 bytes를 사용하며 AES-256-GCM은 nonce 12 bytes/tag 16 bytes를 사용한다. salt/nonce는 인증된 header에만 persist하고 journal/log/importId/path에는 쓰지 않는다.
- base64url은 salt 16 bytes와 nonce 12 bytes에 대해 padding 없는 case-sensitive encoding이고 hash는 lowercase hex다. passphrase는 NFC 16 Unicode scalar 이상이다.
- ZIP member 수는 `<=65,535`, zero-byte member를 허용한다. archive/member/table/row hard caps, manifest-first 후 raw UTF-8 total ordering, store method, fixed DOS epoch, local/central fixed fields 및 common-field byte equivalence, exact EOCD/non-overlap/no ZIP64/no descriptors/no extras를 사용한다.
- manifest descriptor/member는 strict one-to-one bijection이다. exact schemaDigest JCS input은 pii/secret/identity/attachment/FK semantics를 포함하고 migrationSet ordered digest와 함께 authoritative schema를 이룬다.
- canonical SQL logical type은 `int64:`, `decimal:{type,coefficient,scale}`, `blob:`, `timestamp:` 규칙을 사용한다. decimal coefficient는 leading zero 없는 signed integer(0은 `"0"`), scale은 unsigned integer로 trailing-zero semantics를 보존한다. source-ID canonical logical hash와 target physical hash를 분리하고 attachment verification은 plaintext/content hash로 한다.
- export는 consistent DB transaction snapshot과 immutable attachment pin을 잡고 deterministic two-pass streaming을 수행한다. 재조회가 불가능하면 encrypted spool만 허용하며 plaintext ZIP/row/attachment temporary file은 만들지 않는다.
- source key, target key, provider credential, password, DPAPI blob, JWT, signed URL은 package·journal·log·error에 절대 export하지 않는다. PII plaintext는 authenticated payload memory에서 target `PII_ENC_KEY`/`PII_KEY_VERSION`과 S9 vault envelope로 즉시 재암호화하며 disk staging에는 평문을 쓰지 않는다.
- import는 populated main DB를 직접 mutate하지 않고 empty isolated shadow namespace에만 쓴다. pending rows는 normal query/audit/trigger에 노출되지 않는다. pointer, complete marker, manifest hash가 같은 DB transaction으로 전환된 **irreversible commit point** 뒤에만 fully applied다. complete marker를 본 recovery는 이후 정상 write로 바뀐 mutable active row/file hash를 재검증하거나 rollback하지 않는다.
- `importId`는 매 시도마다 CSPRNG UUID이며 payload hash나 package name에서 derive하지 않는다. hash는 integrity/provenance fields일 뿐 log·identifier에 stable fingerprint로 쓰지 않는다.
- journal은 checksummed framed DB-backed durable journal이며 side effect보다 먼저 생성·commit한다. process-exclusive lock은 durable DB lease/fencing을 포함한다. nofollow/exclusive path, per-file provenance, file/parent durability를 지킨다.
- Local은 encrypted atomic rename, Cloud는 Postgres/Storage adapters의 institution-owned private conditional put + durable DB journal을 사용하며 Cloud export와 import 양방향 모두 adapter를 거친다.
- wrong password와 GCM tamper는 `DECRYPTION_FAILED`로 동일 처리한다. schema incompatibility, missing/unknown member, row loss, disk/fsync/rename/put 실패는 성공으로 보고하지 않는다.
- 포맷은 Cloud↔Single, Cloud↔Office, Single↔Office 및 reverse 여섯 방향과 same-mode full-revalidated idempotent restore를 정의한다. 첫 구현 우선순위는 Single→Office와 Single→Cloud다.
- 이번 작업에서는 format/install/update 서명, Recovery Kit key wrapping, AudioStore 수명, 실제 DB/filesystem adapter를 구현하지 않는다. 각각 SG12, SG9, SG8, E3-7/E6-E8의 소유다.

### Task 1: Fix the authenticated CCCX envelope

**Interfaces:** Consumes ADR-0041 D83 and SG9’s shared Argon2id/AES-GCM envelope; produces exact framing, canonical header/golden bytes, KDF, nonce/tag, AAD, inner digest and auth-failure semantics.

- [ ] Define big-endian `magic[5] || headerLength[4] || headerUtf8[headerLength] || ciphertext`, header bound `1..4096`, strict JCS-only header and the exact 216-byte fixed salt/nonce golden vector.
- [ ] Fix unpadded case-sensitive base64url, lowercase hash hex, Argon2id v1.3 parameters, 12-byte nonce, 16-byte tag and header-byte AAD.
- [ ] Keep `innerPayloadSha256[32] || deterministicZip[*]` inside ciphertext; never expose payload hash, salt or nonce in logs, journal, filename or stable import identity.
- [ ] Define wrong-password/auth-failure behavior without oracle and make every failure non-mutating.

### Task 2: Define deterministic ZIP geometry and semantic manifest

**Interfaces:** Consumes S1 logical schema and ADR-0041 portability; produces deterministic ZIP, exact header geometry, manifest bijection, schema/migration digest, canonical JSONL, tagged SQL types, hashes and attachment addressing.

- [ ] Restrict members/paths; allow `manifest.json` first then raw UTF-8 total ordering; allow zero-row/zero-byte members; cap classic ZIP members at 65,535.
- [ ] Define local fixed fields separately from central fixed fields (`versionMadeBy`, `versionNeeded`, flags, method, times, CRC, sizes, name/extra/comment lengths, disk start, attrs, offsets); compare only fields present in both. Require in-bounds non-overlap, exact single EOCD at EOF, no ZIP64/descriptors/extras/comments.
- [ ] Define manifest v1 and the exact JCS input object for `schemaDigest`; include semantic pii/secret/identity/attachment/FK flags, ordered migrationSet IDs/digest, tables, attachments and exclusions.
- [ ] Define exact `foreignKeys` (`columns`, `targetColumns`, `targetTable`) and `attachmentRefs` (`column`, `multiple`, `required`) descriptors, raw UTF-8 total sorting and strict descriptor/member bijection.
- [ ] Define canonical `int64`, exact decimal tagged object `{"type":"decimal","coefficient":"<canonical signed integer>","scale":<uint>}`, `blob`, `timestamp` values; require nonempty primaryKey or versioned portableRowKey, typed PK tuple ordering, JCS JSONL/LF rules, source logical hash vs target physical hash and attachment plaintext SHA/size/content-type checks.
- [ ] Define supported schema range/parity, unknown table/column/type, PK/type mismatch and no silent migration/drop behavior.

### Task 3: Define snapshot export, mapping and target-key re-encryption

**Interfaces:** Consumes S9 `SecretStore`/PII key version and S1 atomic `Database.batch()`; produces snapshot/pin consistency, no-key-export, in-memory PII conversion, encrypted-only staging and explicit mapping.

- [ ] Require consistent Cloud Postgres or Local DB transaction snapshot and immutable Storage/filesystem pins across deterministic two-pass export. Use only encrypted spool when replay is impossible; prohibit plaintext temporary residue.
- [ ] Require target keys before first dependent staging: `PII_ENC_KEY`, `PII_KEY_VERSION`, `FILE_ENC_KEY`; reference S9 vault envelope rather than duplicating it.
- [ ] Keep PII values out of journal/progress/errors and reject manifest/data carrying secret material or credentials.
- [ ] Require empty isolated namespace, injective+bijection `{sourceStableId,targetStableId}` mapping with persisted reverse map, explicit FK remapping and no generated IDs/dropped rows.
- [ ] Verify re-encrypted objects by decrypted plaintext/content SHA and size; permit randomized target vault/object ciphertext while source logical/member/attachment hashes remain equal.

### Task 4: Define shadow transaction, durable journal and storage sequence

**Interfaces:** Consumes Tasks 1–3; produces DB-backed framed journal, durable lease/fencing, exclusive/path/durability controls, local/cloud promotion and single pointer invariant.

- [ ] Specify frame bytes `version || sequence || bodyLength || bodyJcs || bodySha256`; create and durably commit journal/lock before shadow namespace or staging, acquire target PII/FILE keys before first dependent staging, and write a frame before every side effect.
- [ ] Specify durable DB lease/fencing across processes and Cloud, nofollow/exclusive path creation, private ownership, file/parent fsync and per-file source-member→target-path provenance.
- [ ] Stage encrypted files and pending shadow rows outside normal query/audit/trigger paths; use S1 atomic batch for pending DB writes.
- [ ] Define Local encrypted atomic rename and Cloud private conditional put (`If-None-Match:*`) with expected plaintext SHA/size metadata. Define Cloud export/import both through Postgres/Storage adapters and unreferenced encrypted orphan handling.
- [ ] Require one DB transaction—the irreversible commit point—to write pointer, complete marker, manifest hash and source/target mapping metadata; before commit normal query/write sees no shadow and after commit recovery never rolls back later mutable active changes.

### Task 5: Close crash/failure matrix and mode directions

**Interfaces:** Consumes Tasks 1–4 and D76; produces restart behavior, error/state semantics, all six cross-mode directions and same-mode no-op rule.

- [ ] Cover journal/lock/key acquisition, shadow creation, decrypt/validation, ZIP geometry, stage fsync, DB batch, local rename, Cloud conditional put, pointer+complete transaction, disk-full, permission and cleanup failures.
- [ ] Require recovery to verify frame checksum/sequence, provenance, plaintext/content hashes and immutable shadow/staged row sets before resume; if complete marker exists, append missing final journal frame without revalidating/rolling back mutable active state. Otherwise rollback shadow rows/pointer and encrypted orphans while leaving original active namespace untouched.
- [ ] Define `RECOVERY_BLOCKED` whenever journal integrity or plaintext absence cannot be proven; encrypted quarantine is allowed but plaintext residue is never allowed.
- [ ] Fix all error codes and constrain logs to random importId, code, phase, timestamp; never log hash, password, key, PII, row body, URL or stable fingerprint.
- [ ] Document Cloud↔Single, Cloud↔Office, Single↔Office and reverse directions, target identity/key/schema ownership, and Single→Office/Cloud first implementation priority.

### Task 6: Close fixtures, completion gate and commit

**Interfaces:** Consumes complete CCCX contract; produces executable fixture definitions, expected verdicts and the two committed documentation files.

- [ ] Define golden fixture with exact header bytes, fixed snapshot rows, zero-row/zero-byte members, attachment bytes and expected equal ZIP logical/member hashes across two exports; only random envelope values differ.
- [ ] Define crypto/tamper fixture for passphrase length, canonical/base64url/hex checks, header/tag/inner digest flips and zero state mutation.
- [ ] Define ZIP fixture for descriptor/member duplicates, local-central common-field mismatch, invalid separate fixed fields, bad offsets/overlap, trailing EOCD, ZIP64/descriptors, path traversal and cap overflow.
- [ ] Define compatibility fixture for exact schema/migration digest, tagged-type errors, unknown columns, duplicate PK, empty/non-stable primaryKey, missing portableRowKey, missing exclusions, identity map non-injective/non-bijective, FK dangling/ambiguous and both-way attachment references.
- [ ] Define crash fixture for every journal/lock/key/shadow boundary, stage fsync, DB batch, local rename, Cloud put, pointer+complete transaction, disk-full/permission; expected result is original unchanged or verified complete only.
- [ ] Define six-direction round-trip fixture with explicit identity/FK mappings and separate source logical/target physical hashes; target vault/object ciphertext differences are accepted only after plaintext hash verification. Exact active state is a no-op after full revalidation; diverged/deleted/corrupt active state rebuilds a fresh empty shadow and atomically cuts over with an explicit repair audit, never a partial conflict.
- [ ] Record `pnpm test:contracts --cccx=golden|crypto|zip|compatibility|crash|roundtrip` and `pnpm guard:cccx`, failing on plaintext spool/residue, stable fingerprint/import ID, partial visibility, normal audit/trigger exposure or weakened assertions.
- [ ] Mark the document `확정` only because the contract is complete; reserve `구현 검증 완료` for E3-7 runtime evidence.
- [ ] Commit only `docs/specs/S10-cccx-format.md` and `docs/superpowers/plans/2026-09-02-SG10-cccx.md`; do not run formatters, linters, builds or project-wide tests. Report the amended commit hash to parent.
