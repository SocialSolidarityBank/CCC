# SG12 설치·릴리스 계약 Implementation Plan

> **For agentic workers:** This documentation ticket closes the SG12 contract in one pass. The parent session owns repository-wide validation after this branch is committed.

**Goal:** Define the installable artifact families, signed manifest/bundle, formal release evidence, coordinated update/rollback transaction, and redacted diagnostics required for CCC Open Pilot v0.3.

**Architecture:** Community Cloud uses one `ccc cloud` command surface; Local Single uses Electron/NSIS; Local Office uses separate server and client installers; Processing Agent ships as a separate Windows installer. A manifest is signed by an embedded Ed25519 release trust store, a ReleaseBundle is signed by an offline root, Windows payloads additionally use Authenticode, and every update stages, drains writes, backs up through SG10, atomically swaps, and negotiates peer health before becoming known-good.

**Tech Stack:** Markdown contract, TypeScript manifest/bundle/trust/model/diagnostic shapes, Ed25519, Authenticode, CycloneDX 1.6 SBOM, SG8 AudioStore, SG9 Recovery Kit, SG10 `.cccx`, SG11 Supabase Edge, synthetic clean-machine fixtures.

**Spec:** `docs/specs/S12-install-release.md`, grounded in ADR-0041 D76-D83, ADR-0042 D84, and `CCC_OPEN_PILOT_PLAN.md` SG12.

## Global Constraints

- Community Cloud, Local Single, and Local Office are all formal implementation modes.
- STT is `off` immediately after installation in all modes; `sttEngine` remains `null` before STT-G1~STT-G3 and Q approval.
- The five artifact families are `community-cloud-cli`, `local-single`, `local-office-server`, `local-office-client`, and `processing-agent`.
- Local Single, Office server/client, and Agent target Windows 11+ x64; Cloud CLI targets macOS 14+ arm64/x64, Windows 11+ x64, and Ubuntu 22.04+ x64.
- The v1 manifest has exactly `{ version, sequence, channel, artifactUrl, artifactSha256, artifactBytes, minSchemaVersion, maxSchemaVersion, publishedAt, expiresAt, signingKeyId, ed25519Signature }`; every signed object is parsed with duplicate-key rejection and a closed exact schema, cloned, stripped of exactly its one signature property, JCS-canonicalized as UTF-8, prefixed with its fixed domain, and signed/verified with lowercase hashes and fixed unpadded base64url.
- Artifact identity is bound by the updater's immutable expected `(family, mode, platform, arch)` tuple and strict URL basename parser; identity is not a user-controlled manifest field.
- Formal bundles are offline-root-signed `ReleaseBundleV1` indexes containing all five families, each manifest URL/hash/size, a signed latest-sequence floor, and exact API/protocol peer compatibility.
- The `community-cloud-cli` artifact embeds closed `EdgeComponentManifestV1` with every Edge function/template/migration path, component bytes/hash, aggregate hash, schema/protocol; ReleaseBundle binds its manifest hash and CLI deploys only verified staged bytes, checks local component details, and compares only aggregate hash to the S11 receipt.
- Unknown, revoked, invalid, expired, future-dated, wrong-origin, wrong-identity, wrong-hash, wrong-size, downgraded, and schema-incompatible artifacts never apply.
- Stable installations never transition to beta/dev, even at higher version/sequence; beta/dev to stable transitions are monotonic only.
- Clean machines and every online install/update fetch the signed latest-sequence floor and TLS-authenticated server `Date` from one pinned HTTPS origin; the bundled installer pins a nondecreasing factory floor. Missing proof fails closed. Offline install/update are forbidden; only exact local-ledger-bound known-good rollback may run offline using persisted trusted time/floor.
- Windows PE files are discovered by parsed PE header regardless of extension and require trusted Authenticode with timestamp and pinned CCC publisher identity; self-signed/test-signed or unverifiable payloads never apply.
- Highest-seen version/sequence is monotonic across channels per `(family, mode, platform, arch)` ledger; channel transitions never lower either value.
- Trust-store mutations require an offline-root-signed `TrustStoreUpdateV1` with monotonic `sequence`/`prevSequence`, previous/result digest, explicit operations, issued/expiry times, and an atomic update ledger. ReleaseBundle never mutates keys.
- Staging/cache are service-owned and ACL-protected; symlink/reparse/hardlink entries are forbidden; recursive extraction never runs code; hash/sign/file-ID are checked on the same open handle immediately before promotion.
- Updates acquire a maintenance write barrier, drain in-flight writes without loss, hold the barrier through backup, coordinated health, or rollback, and release it only after a known-good result.
- Updates must complete verified SG10 backup before replacement; failed health restores the exact prior known-good bundle/cache and backup.
- Formal release requires Windows signature evidence, CycloneDX SBOM/NOTICE, conditional-license assessment/evidence, Agent-owned Python SBOM, and a passing synthetic restore drill.
- The E10-2 signed model manifest binds exact model ID/revision/hash/origin/license/size/runtime compatibility.
- Doctor/report collect and redact at source; secrets, URLs, tokens, PII, original audio, provider raw errors, and command arguments never appear in output.
- SG8 audio lifecycle, SG9 key and Recovery Kit, SG10 encryption/journal, and SG11 Edge template are referenced contracts, not redefined here.
- This branch changes only the canonical SG12 spec and this ticket-local plan. No application code, master plan, PR, ticket state, or external credentials are changed.
