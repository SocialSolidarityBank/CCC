# E5-9 장문 AI Packet Implementation Plan

**Goal:** S15 계약에 따라 transcript, manual_note, goal 재료를 24,000 Unicode code point 청크로 처리하고 개인정보 재검증, 부분 실패, 근거 보존, 누락 재생성을 구현한다.

**Scope:** 공통 AI runtime의 장문 packet planner/caller/merger, `apps/api`의 결과·승인·누락 UI/API 연결, S15 계약 fixture. S6 masking/revalidation, S5 Agent job/credential, SG8 AudioStore, SG10 portability의 기존 계약을 호출하고 재정의하지 않는다. provider 추가, fallback, 리스크 확정·GAS 산정은 범위 밖이다.

## Tasks

1. **정확한 source와 call-level provider schema를 연결한다.**
   - `originKind: transcript | manual_note | goal`을 discriminator로 두고 planner가 duplicate sourceRef와 같은 originKind의 복수 source를 거부한다. manual_note와 goal은 transport `kind: text_context`를 유지하되 서로 다른 origin으로 구분한다.
   - `LongAiProviderRequest`에는 mode/schema, planHash, exact requestHash, callId, provider identity, 1~3개 unique material을 넣는다. provider result는 per-chunk result 배열이 아니라 한 grouped-call `content` payload로 정의한다.
   - provider-local evidence를 evidence-generic grounded types에 적용하고 성공 content가 empty여도 허용한다. evidence에는 기준 chunk와 모든 contributing chunk ID를 보존한다.

2. **canonical source와 구간을 검증한다.**
   - S6 `MaskedSourceSnapshot`만 source body로 읽고 `Array.from(text).length`와 code point slice로 좌표를 계산한다. NFC와 Unicode whitespace-run 축약은 identity 전용이며 snapshot text와 evidence quote는 변경하지 않는다.
   - transcript segment 시간 좌표와 문자 좌표, 반열린 included/excluded interval을 검증한다. 시간 경계가 segment 중간이면 `unsupported`가 아니라 `failed` outcome으로, privacy exclusion은 `blocked`, `excluded_by_user`만 중립 제외로 기록한다.

3. **결정론적 planner와 계획 저장을 구현한다.**
   - 재료별 24,000 code point 상한과 같은 included interval 안의 500 overlap을 적용하고 excluded interval을 건너뛰어 overlap하지 않는다. tail은 버리지 않으며 astral 문자와 24,000 초과 단일 segment를 처리한다.
   - ordered material descriptors, global char/time range, sorted purposes, snapshot hash, pipeline version을 포함한 모든 chunk descriptor를 persist한다. chunkId는 descriptor canonical SHA-256이다.
   - planHash는 ordered descriptors/purposes, snapshot/pipeline, consent evidence, provider/model/adapter/prompt/schema/config identities를 포함한다. 동일 planHash와 requestHash가 아니면 result를 재사용하지 않는다.

4. **request hash, grouped call, privacy gate를 배선한다.**
   - requestHash를 실제 ordered chunk ID, masked material UTF-8 bytes, material origin/kind와 included/excluded policy의 JCS SHA-256으로 계산한다. callId와 idempotency key를 exact requestHash에 바인딩한다.
   - Core가 grouped call의 per-chunk outcomes를 소유한다. 호출 직전 S6 검증 실패 chunk는 provider에서 제외하고 blocked로 남긴다. 성공한 call-level content는 성공한 included chunk에만 적용한다.
   - 호출 직전, response 직후, persist 직전에 S6 pipeline version, snapshot hash, vault 대조, identifier scan, consent와 consent evidence를 모두 검증한다. grouped call의 어느 chunk든 privacy/stale 검증에 실패하면 response를 폐기하고 call의 모든 included chunk를 원자적으로 blocked 처리한다. schema/evidence 실패는 전체 response와 call chunks를 원자적으로 failed 처리한다.

5. **bounded retry와 immutable call attempts를 구현한다.**
   - timeout/network/429/5xx만 grouped call을 총 3회 이내(초기 1회 + retry 2회, backoff 1초·4초 상한) 재시도한다. privacy/schema/입력/그 밖의 4xx는 retry하지 않고 failed/blocked로 기록한다.
   - AttemptReceipt는 call-level ordered chunkIds, requestHash, idempotency key, attemptId를 append-only로 남긴다. grouped call의 `submittedAttempts`는 0~3이며 실제 provider submission 수와 같고, `providerBillingUnits`는 관찰된 per-attempt billable receipt 합계, 관찰 불가가 있으면 null이다. stale discard도 이미 제출됐다면 과금 가능하다. per-chunk outcome은 attemptId를 참조하고 first valid success만 채택한다. 늦은 duplicate success와 provider fallback은 금지한다.

6. **persisted grounded merge와 discrepancy call을 구현한다.**
   - provider-local offset을 전역 snapshot offset으로 정확히 한 번 번역하고 provider-local content/evidence를 저장하거나 UI에 직접 노출하지 않는다. Provider는 evidenceId를 만들지 않으며 Core가 membership/span 검증 뒤 `SHA256(JCS(callId, chunkId, sourceRef, global spans/times, quoteHash))`로 persisted evidenceId를 파생한다.
   - evidence-generic claim, oneLiner, question, contrast, risk, promise와 `{kind,leftEvidence,rightEvidence}` discrepancy pair를 사용한다. origin-aware contrast axes는 missing_from_memo=transcript, missing_from_transcript=manual_note, undiscussed_session_goal=goal로 고정한다. factual claim과 risk는 transcript-only, promise는 manual_note/transcript, goal-derived output은 immutable goalRef와 goal-material evidence 및 논의 transcript evidence를 보존한다. validator가 source/origin/quote 관계를 확인한다.
   - generate response에는 discrepancy를 넣지 않는다. `LongDiscrepancyRequest`가 current/prior approved masked comparison chunks로 S5 `AIProvider.detectDiscrepancies`를 별도 호출하며 동일 SG6 3단 gate, requestHash, callId, idempotency와 별도 `LongDiscrepancyAttemptReceipt`를 적용한다. 결과는 `GroundedDiscrepancyPair`와 `supported | unsupported | failed` 상태로 병합한다.
   - response의 일부 item만 필터해 성공 처리하지 않는다. mixed-invalid response는 전체 grouped call chunks를 failed로 만들고 partial을 유지한다.
   - output family마다 identity는 family, 모든 semantics(사실 claim section, contrast axis, risk type, immutable goalRef, promise key, discrepancy kind), canonical text, 정렬한 전체 provenance tuple 집합이다. 같은 identity만 evidence union하고 strict evidence subset/다른 span은 별도 output으로 보존한다. 전체 sort 마지막 tie-breaker는 chunkId다.

7. **상태 파생, CAS regeneration, UI를 연결한다.**
   - persisted outcome key 집합이 plan의 모든 non-user-excluded descriptor와 같고 `succeeded`, `failed`, `blocked`, `not_applicable`이 서로 겹치지 않으며 합집합이 되게 한다. unsupported/privacy descriptor도 failed/blocked로 남기고 structurally unsupported만 not_applicable이다. provider request에는 eligible included chunk만 넣는다. `excluded_by_user` descriptor는 plan/outcome에 넣지 않고 `excludedIntervals`에만 보존한다. state는 outcomes와 content completeness에서만 파생한다. missingSections non-empty 또는 discrepancy unsupported/failed이면 partial, 성공이 없으면 blocked, 모든 조건을 만족할 때만 complete다.
   - `regenerateMissing(expectedDraftVersion, expectedPlanHash, callId, chunkIds)`는 lifecycle이 pending인 일치 요청만 허용하고 succeeded/approved와 mismatch는 거부한다. `regenerateMissingSections`는 succeeded지만 empty content로 missingSections가 있는 경우에 한해 CAS 검증 후 새 requestHash/callId/key로 유효 subset을 재계획하고 기존 성공 output/attempt를 불변으로 둔다. `retryDiscrepancy`는 discrepancy call에만 같은 CAS와 새 request identity를 적용한다. subset 재생성은 `supersedesCallId` link를 남긴다.
   - partial은 origin별 문자·시간 누락, failed/blocked와 discrepancy unsupported/failed를 고정 표시하고 승인 가능 상태로 보이지 않게 한다. blocked는 본문을 표시하지 않는다. approved draft와 evidence는 immutable이며 empty content도 coverage와 missingSections로 명시한다.

8. **S15 계약 fixture와 검증을 추가한다.**
   - astral 48,500 code point timed transcript, 24,001 manual_note, 50,001 goal, duplicate source/origin, excluded_by_user/unsupported/privacy 구간, pre/post/persist 각각 하나의 stale gate fixture, retry success/failure, mixed-invalid response, grouped outcomes, dedupe, CAS subset regeneration, discrepancy unsupported/failed, missingSections regeneration, retryDiscrepancy fixture를 만든다.
   - 계획 좌표·ID·순서, sourceRef/origin uniqueness, exact requestHash, payload 비전송, 3단 privacy gate, exact-hash reuse, idempotency/first valid success, immutable call attempts, submitted/billing aggregation including stale discard, evidence ID derivation and global/local coordinates, origin-aware contrast axes, goal relation, disjoint/exhaustive outcomes, state and approval blocking을 검증한다.
   - S15 문서의 명령과 기대 판정을 그대로 사용하고 기존 테스트나 assertion을 삭제·skip·완화하지 않는다.

## Acceptance

- 세 discriminator material과 call-level request/result schema가 sourceRef/origin uniqueness, empty success content, evidence-generic grounded output, discrepancy pair/state까지 정의되고 동작한다.
- 재료별 payload가 24,000 code points 이하이며 astral offsets와 tail, included/excluded interval, 500 overlap, deterministic chunkId/order를 보존한다.
- 모든 call의 pre-call, post-response, pre-persist SG6 검증이 atomic grouped-call outcome과 stale discard를 보장하며 unmasked/excluded text가 provider에 도달하지 않는다.
- planHash와 exact requestHash가 아니면 결과를 재사용하지 않고 provider idempotency key, 총 3회 bounded retry, immutable call attempts, actual-submission billing, first valid success-only, no fallback을 지킨다.
- mixed-invalid response는 grouped-call chunks 전체를 failed/partial로 만들고 일부 유효 item을 성공 처리하지 않는다. 모든 persisted factual field가 global source evidence와 character/time range를 가진다.
- discrepancy는 generate와 분리된 detectDiscrepancies call이며 supported/unsupported/failed와 양쪽 evidence pair를 보존한다. origin-aware contrast axes와 goalRef relation을 validator가 거부·통과한다.
- outcome sets가 eligible descriptors에 대해 disjoint/exhaustive이고 state가 파생되며, CAS subset regeneration은 새 call/key와 supersession link를 만들고 draftVersion+planHash+callId mismatch 및 succeeded/approved 불변성 위반을 거부한다.
- persisted/UI에는 provider-local type이나 provider-generated evidenceId가 노출되지 않는다. missingSections, excluded_by_user, failed/blocked, discrepancy 상태가 구분되고 complete-looking 또는 승인 가능 상태를 만들지 않는다.

## Verification

부모 worktree가 병렬 티켓을 모두 받은 뒤 S15 문서의 명령을 실행한다. 이 worktree에서는 formatter, linter, build, test 또는 project-wide validation을 실행하지 않는다.
