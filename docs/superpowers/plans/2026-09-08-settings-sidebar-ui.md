# 설정 전용 사이드바 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인된 다섯 묶음과 독립 메뉴 둘을 설정 전용 사이드바로 구현하고, 19개 화면을 가상 데이터로 검수한 뒤 제공된 API에 연결한다.

**Architecture:** 화면과 API 연결만 이 작업이 소유한다. 먼저 기존 독립 프리뷰를 승인된 구조로 교체하고, 업무 클라이언트와 API 계약이 합류하면 같은 화면 설계를 실제 컴포넌트로 구현한다. 프리뷰의 시연 상태를 운영 응답이나 접근 권한으로 사용하지 않는다.

**Tech Stack:** 현재 프리뷰는 Bun 정적 서버와 HTML/CSS/JavaScript. 현재 화면 부품은 Next.js/React `apps/web`의 Wire 계열이며, 정식 업무 클라이언트 목표는 ADR-0041의 Vite/React `apps/client`다.

**Spec:** `CONTEXT.md`의 확정 메뉴 용어, `DESIGN.md` §4-5, `DESIGN-RULES.md`, 이 문서의 승인 결정 표. 2026-09-08 사용자가 메뉴 명칭과 구성을 승인했다. 세부 화면의 시각 승인은 별도다.

## Global Constraints

- 화면과 배선만 수정한다. 인증 엔진, DB, 저장소, 마이그레이션, 백업 엔진, AI 호출, 사업 정책, 프리뷰 격리 저장 서버는 `ccc-222-postgres` 세션 소유다. 그 워크트리를 수정하지 않는다.
- 실제 업무 클라이언트 기반을 이번 UI 작업에서 별도로 만들지 않는다. Cloudflare를 지나는 Next 서버 액션을 새 정식 상담 데이터 경로로 확대하지 않는다(D80).
- 실제 구현 전 격리 작업 공간을 확인한다. 공유 루트의 사용자 변경과 다른 세션의 변경을 덮어쓰지 않는다.
- 디자인 값은 `DESIGN-RULES.md`를 재사용한다. 손 카드, 새 색, 역할별 상세 설명의 반복, 카드 안 카드, 새 UI 라이브러리를 추가하지 않는다.
- 화면에 있는 모든 값은 가상 자료로 채운 프리뷰가 기본이다. 비어 있음, 꺼짐, 준비 중, 실패는 별도 상태다.
- 운영에서 프리뷰 역할 선택과 전체 둘러보기를 활성화하지 않는다. 메뉴 숨김은 서버 권한 검사의 대체물이 아니다.
- 기술 관리자는 연결 준비, 기관 관리자는 AI 키와 최종 시작을 담당한다. 겸임자는 두 동작을 한 흐름에서 할 수 있다. 과거 기술 관리자 전용 AI 메뉴 정책으로 되돌리지 않는다.
- STT는 `off`, 승인 전 `sttEngine`은 `null`. 설치 설정과 사업 처리 경로 중 더 좁은 범위만 사용한다. Azure는 마스킹 전 원음, OpenAI는 가려진 텍스트가 나간다는 차이를 입력 옆에 표시한다.
- 메모리 설정에는 기능 설정과 처리 상태만 둔다. 당사자 이름, 상담 원문, 요약 원문, 근거 인용, `memory.md`, 항목별 승인/정정 UI를 넣지 않는다.
- 외부 연결을 시연하면 반드시 시연임을 표시한다. 지원하지 않는 서버 작업에 성공 응답을 만들지 않는다. 키·연결 문자열은 URL, 로그, 브라우저 저장소에 남기지 않는다.
- 처음 연결과 복잡한 변경은 질문 하나, 입력, 확인, 다음의 짧은 단계로 진행한다. 간단한 변경은 그 자리에서 한다. 단계 이동을 실제 적용으로 취급하지 않는다.
- 변경 영향은 데스크톱 입력 옆, 모바일 입력 아래. 선택 전후와 실제 적용 결과를 구분하며 실패/409에서는 입력값을 보존한다.
- 프리뷰의 방문자별 저장, 같은 브라우저 7일 유지, 초기화는 서버 제공 후 연결한다. 미연결 상태를 구현 완료로 표시하지 않는다. 사용자 초기화 요청은 프리뷰에만 재확인 없이 적용한다.
- 새 권한 역할을 만들지 않는다. 서버 역할 식별자는 `institution-admin`, `technical-admin`, `supervisor`, `worker`다. `worker`의 화면 이름은 실무자다.

### 실제 API 연결의 착수 조건

아래는 API 요구 목록이지 기존 엔드포인트가 존재한다는 주장이 아니다. 임의 경로나 응답 타입을 만들어 호출하지 않는다.

1. 합류된 클라이언트에서 인증된 신원과 역할 합, 요청 취소/오류 처리, 라우터가 제공될 것.
2. 모듈별 조회 가능 범위, 변경 가능 동작, 실제 지원 여부를 구분할 것. capability의 기능 가용성과 사람의 권한을 같은 것으로 보지 않을 것.
3. 기관 정보의 부분 수정, 사업 표와 도입 확인, 동의 문안 버전, 보관 검토, 감사 조회, 내보내기 범위를 담당 API가 강제할 것.
4. AI 키 입력/교체와 최종 시작의 기관 관리자 권한을 서버에서 강제할 것. 현재 메뉴 이름만 바꿔 이 전제를 충족시켰다고 하지 않을 것.
5. DB 사전 점검은 읽기 전용이며 적용은 별도 승인/백업/실행 흐름일 것. 파일 저장, 백업, 복원, 업데이트는 각각 실제 상태/작업 결과 계약을 제공할 것.
6. 프리뷰 전체 보기는 가상 신원과 자료만 사용하며 운영 토큰과 섞이지 않을 것. 방문자별 격리, 만료, 초기화 계약을 제공할 것.

미충족 항목은 해당 동작의 연결을 막는다. 가상 화면 검수는 먼저 할 수 있고, 다른 지원된 기능까지 막지는 않는다.

## 2. 승인된 19개 메뉴와 화면 범위

ID는 이 계획에서 정한 내부 식별자다. URL에는 이 식별자와 화면 상태만 사용하며 원문이나 키는 넣지 않는다.

| ID | 묶음 | 메뉴 | 화면의 핵심 내용과 동작 | 기존 소스 또는 연결 전제 |
| --- | --- | --- | --- | --- |
| institution | 기관 관리 | 기관 정보 | 기관 이름과 기본정보 조회/수정 | `getOrganizationProfile`; 부분 수정 계약 필요 |
| programs | 기관 관리 | 사업 관리 | 사업 등록, 기본정보, 담당 구성, 저장/처리 조건, 도입 확인, 운영 상태 | 기존 온보딩 이름 설정과 다름. 사업 API 필요 |
| accounts | 기관 관리 | 계정 및 권한 | 초대, 계정 상태, 역할, 팀 감독과 배정 관리 | `admin/users`, `admin/invite`, `admin/assign`; 승인된 권한 계약으로 연결 |
| consent | 기록 관리 | 동의서 설정 | 기관 동의 항목, 문안, 버전 설정 | 당사자 동의 체크 API로 대체 금지 |
| retention | 기록 관리 | 보관 및 파기 | 보관 기준, 검토 대상, 보존/파기 결정 | 보존 시계/상한/파기 승인 API 필요 |
| exports | 기록 관리 | 기록 내보내기 | 권한에 맞는 범위 선택, 파일 생성 결과와 이력 | 실제 내보내기 API 필요. 백업 파일과 구분 |
| audit | 기록 관리 | 열람 및 변경 이력 | 조회/변경/복호화/내보내기의 감사 이력 | 감사 조회 API 필요. 기술 관리자에게 상담 자료를 보내지 않음 |
| speech | AI 연결 및 설정 | 음성 인식 연결 | off/local/azure, 승인 상태, 경로 동의와 연결 확인 | capability 및 STT 설정 계약 필요 |
| ai | AI 연결 및 설정 | AI 에이전트 연결 | OpenAI 연결, 키 설정, 준비 결과, 최종 사용 시작 | `getAiProviderStatus`, `activateAiProviderRuntime`는 기존 일부 기능이며 신규 권한 계약 필요 |
| agent | AI 연결 및 설정 | 로컬 에이전트 설정 | 기관 PC 프로그램 설치, 연결, 마스킹 준비, 연결 끊김 | 설치 및 Agent 상태 계약 필요. 설치 CTA는 로컬 에이전트 설치 |
| memory | AI 연결 및 설정 | AI 메모리 설정 | 기관 기능 설정과 처리 상태 | 합류된 메모리 API 필요. 당사자별 내용/승인 대기 없음 |
| database | 저장 및 백업 | 데이터베이스 연결 | 현재 저장 DB, 읽기 전용 점검, 이전 준비와 승인 상태 | 사전 점검/이전 서비스 필요. 입력 중 연결 전환 금지 |
| storage | 저장 및 백업 | 저장 위치 설정 | 원음/첨부파일 저장 위치와 사용 상태 | AudioStore 등 담당 서비스의 안전한 응답 필요 |
| backup | 저장 및 백업 | 백업 및 복원 | 백업 이력, 검증 결과, 복원/이전 승인과 실행 상태 | 기관 관리자 승인과 기술 관리자 실행을 분리한 계약 필요 |
| security | 시스템 관리 | 보안 설정 | 기관 로그인 보호와 다중 인증 설정 | 모드별 인증 API 필요. 계정/업무 역할 부여와 구분 |
| system | 시스템 관리 | 시스템 상태 | DB, AI, Agent 상태와 처리 지연/오류 | capability로 알 수 없는 진단은 별도 API 필요. 설정 변경은 각 메뉴로 연결 |
| updates | 시스템 관리 | 업데이트 | 현재/새 버전, 서명 확인, 백업, 적용과 복구 결과 | 실제 릴리스 서비스 필요 |
| account | 독립 메뉴 | 내 정보 | 본인 이름, 소속, 역할 합, 계정 정보 | `getMyIdentity`; 구 단일 `role`로 겸임을 축약하지 않음 |
| guide | 독립 메뉴 | 사용 가이드 | 초기 설정 순서, 기능별 사용법, 역할 설명, 문제 해결 | 기존 매뉴얼 재사용; 각 화면의 관련 절 링크를 제공 |

공통으로 목록에서 기능 미지원과 권한 없음을 구분한다. 운영에서 권한 없는 메뉴/빈 묶음은 숨긴다. 기능 자체가 미지원이면 권한 있는 사람에게 준비 상태와 이유를 표시하되 실행 버튼으로 성공을 가장하지 않는다. 이 표는 모든 역할의 세부 API 권한을 새로 확정하는 표가 아니다.
