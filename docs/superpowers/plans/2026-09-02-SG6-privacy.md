# SG6 Privacy Packet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent가 직접 식별자를 남기지 않고 준식별자를 명시적으로 일반화한 S5 `MaskedSource`를 만들며, 코어가 NER health, pipeline 증명, 모든 material hash, 결과 시점 동의를 다시 확인한 뒤에만 외부 호출을 시작하게 한다.

**Architecture:** 서버는 claim-bound mask dictionary를 Agent에 전달한다. Agent는 원음 전사 또는 source text에 직접값 치환을 먼저 적용한 뒤 고정 NER와 준식별자 규칙을 적용하고, S5의 `AudioResult` 또는 `TextResult`만 제출한다. 코어는 Packet bytes를 다시 쓰지 않고 detection-only로 금고 값을 검사하며, 모든 requested·counterpart·historical·derived material을 검증한 뒤 consent revision과 material hash에 묶인 egress authorization을 선형화한다.

**Tech Stack:** Python 3.12 Processing Agent, TypeScript 5.9, Web Crypto SHA-256, JCS, Cloudflare Workers, D1·암호화 SQLite·PostgreSQL adapter, Vitest, Python unittest

**Spec:** `docs/specs/S6-privacy-packet.md`

## Global Constraints

- S5의 `MaskedSource`, `AudioResult`, `TextResult`, `ResultRequest`, `ReleaseRequest` 필드와 이름을 그대로 소비한다. 별도 v1 결과 형식을 만들지 않는다.
- 정식 NER은 `FrameByFrame/korean-pii-e5-base` revision `a308c54b4407819624a5661e31e162a269f39818`, `PRIVATE_PERSON`, `PRIVATE_ADDRESS`만 사용한다.
- Install NER smoke는 N corpus의 4+4 entity와 음성 2건으로 load·label·determinism만 확인하며 production을 승인하지 않는다. E5-4 release qualification은 최소 500개 층화 conversational synthetic item과 200개 hard negative, 각 label Wilson 95% lower precision·recall `>= 0.90`, overgeneralization Wilson 95% upper `<= 0.05` receipt가 있어야 한다. receipt가 없거나 stale이면 production authorization을 열지 않는다.
- Agent는 server-supplied mask dictionary를 처리 중 메모리에서만 사용한다. 원음, 미마스킹 전사, PII, NER span, dictionary, 동의 원문은 Agent 밖으로 내보내지 않는다.
- 코어는 Packet bytes를 다시 쓰지 않는다. 등록 PII 잔류는 `registered_pii_detected`로 거부하고 phone/email/account와 한국어 존칭·로마자 인명, 도로명·지번·건물·동·호·우편번호 후보를 deterministic blocker로 검사한다. NER mask가 덮지 않은 후보는 `residual_identifier_candidate`로 분류해 `unmasked_identifier_detected`를 반환한다. 미탐지 식별자 잔여 위험은 0이 아니며 R3 동의 고지에서 공개한다.
- E5-5 소유 snapshot 행은 pipeline version/hash, NER attestation id/result hash, E5-4 release qualification receipt id, evidence hash, material hash/type을 매번 보존한다. 하나라도 없는 legacy row는 provider material이 될 수 없다.
- provider 시도마다 requested, counterpart, historical, derived-summary를 전부 검증한다. 하나라도 실패하면 전체 call을 만들지 않는다.
- consent revision, 정렬된 material hash 집합, provider, expiresAt에 묶인 authorization의 CAS가 egress linearization point다. withdrawal commit 뒤 새 call은 시작하지 않는다.
- NER health, route, allowlist, consent의 pre-STT 실패는 Azure 0회·OpenAI 0회다. 이미 authorization된 Azure STT 뒤 발견한 privacy 실패는 Azure 1회까지 감사할 수 있고 OpenAI는 0회다.
- `local_ner_unavailable`은 S5 release의 reprocessable infrastructure blocked 상태이며 attempt를 소진시키는 영구 실패가 아니다.
- 외부 OpenAI `generate`, `regenerate`, `detect_discrepancies` 요청은 세 모드에서 모두 AI Packet과 JSON `store:false`를 사용한다. LLM이 꺼진 Local 성공 flow는 OpenAI를 호출하지 않는다.
- 일곱 fail-closed code와 화면 문구는 `docs/specs/S6-privacy-packet.md` 표를 문자 단위로 사용한다.
- 로그와 예외에는 code, session ID hash, timestamp 외 원문·감지값·위치·quote·PII를 넣지 않는다.
- S6 스펙의 `확정`은 문서 계약·fixture·명령이 닫힌 상태이며 구현 검증 결과를 뜻하지 않는다.

## Interfaces

S6는 S5의 다음 결과 필드를 소비한다.

```ts
interface MaskedSource {
  maskedText: string;
  sha256: string;
  maskingPipelineVersion: string;
  maskingPipelineHash: string;
  nerAvailable: true;
  nerAttestationId: string;
  nerAttestationResultHash: string;
  evidenceHash: string;
  evidence: Array<{
    id: string;
    sourceRef: string;
    sourceSha256: string;
    evidenceQuote: string;
    sourceStart: number;
    sourceEnd: number;
  }>;
}
```

`nerAvailable=false`이면 `ResultRequest` 대신 S5 `ReleaseRequest { outcome: 'blocked', reason: 'local_ner_unavailable' }`로 보고한다. 이 release는 attempt를 소진하지 않는 infrastructure blocked 상태이며 fresh passing NER attestation 뒤 재처리한다. provider gate는 다음 authorization record를 만든다.

S5 audio `AgentJob.audio`는 `rawAudioSha256`과 `egressAuthorizationId`를 함께 제공한다. claim·audio endpoint와 두 필드의 발행은 E5-1a가, Azure authorization과 STT 실행은 E5-3이 소유한다.

`POST /pipeline/jobs/:jobId/mask-dictionary`는 TLS 위에서 S5 `MaskDictionaryRequest { claimToken, attempt }`만 받고, 일치하는 live claim에 대해 1회만 응답한다. 응답은 5분 이내 만료, `Cache-Control: no-store`, memory-only zeroize 계약을 따른다. endpoint와 일회성 메모리 저장은 E5-1a와 E5-4가 공동 소유한다.

```ts
interface MaskDictionaryEntry {
  field: string;
  sourceValue: string;
  replacement: string;
}
interface MaskDictionaryResponse {
  dictionaryId: string;
  jobId: string;
  expiresAt: string;
  oneTime: true;
  entries: MaskDictionaryEntry[];
}
```

S5 audio `AgentJob.audio.egressAuthorizationId`는 Azure egress 행을 가리킨다. S5 Azure tuple과 OpenAI tuple을 구분하는 discriminated union은 다음과 같다.

```ts
interface AzureEgressAuthorization {
  egressAuthorizationId: string;
  tuple: {
    orgId: string;
    jobId: string;
    claimTokenHash: string;
    attempt: number;
    rawAudioSha256: string;
    consentRevision: string;
    provider: 'azure';
  };
  status: 'authorized';
  expiresAt: string;
}
interface OpenAiEgressAuthorization {
  egressAuthorizationId: string;
  tuple: {
    provider: 'openai';
    orgId: string;
    supportCaseId: string;
    sessionId: string;
    workItemId: string;
    actorId: string;
    operation: 'generate' | 'regenerate' | 'detect_discrepancies';
    materialHashes: string[];
    consentRevision: string;
  };
  status: 'authorized';
  expiresAt: string;
}
type EgressAuthorization = AzureEgressAuthorization | OpenAiEgressAuthorization;
```

## Task 3: Consent linearization and Azure/OpenAI call boundary

**Files:**
- Modify: `db/gateway.ts`
- Modify: `apps/api/src/request-handler.ts`
- Test: `apps/api/test/agent-privacy-linearization.test.ts`
- Test: `apps/api/test/privacy-packet.test.ts`

**Interfaces:**
- Consumes: Task 2 complete material set and current S7 consent revision.
- Produces: CAS-linearized `EgressAuthorization`, withdrawal ordering, per-provider call counts.

- [ ] **Step 1: result-time consent revision을 authorization에 묶는다**

현재 적용 6영역 동의, `consentRevision`, `effectiveAt`, 목적·케이스 연결, all material hashes, provider config을 한 transaction에서 확인해 `status='authorized'` 행을 commit한다. `expiresAt`은 consent `validUntil`, Azure job lease, 5분 auth TTL 중 가장 이른 시각이다. 영속 status는 `authorized | in_flight | completed | revoked | expired`이며, 생성 응답은 `authorized`로 좁혀 반환한다.

- [ ] **Step 2: provider별 egress CAS를 구현한다**
Azure는 `beginAzureEgress({ egressAuthorizationId, claimToken, attempt })`, OpenAI는 `beginOpenAiEgress({ egressAuthorizationId, actorId, operation })`만 사용한다. 두 API는 저장된 work item의 org·case·session·job·material hash·provider config와 현재 consent revision/effectiveAt을 재검증하고 `authorized → in_flight` CAS를 수행한다. raw claim token은 인증 채널로 받고 서버가 hash해 tuple의 `claimTokenHash`와 비교한다. CAS 성공 응답 state는 `in_flight`이고 성공 전 provider SDK·HTTP 호출은 0회다. withdrawal commit이 먼저면 authorization은 `revoked`가 되어 새 call을 시작하지 않는다. 허가된 OpenAI JSON에는 `store:false`를 포함한다.

- [ ] **Step 3: G10 race와 호출 수를 검증한다**

S6 G10과 natural-expiry 변형을 barrier-controlled race로 실행해 DB winner에 따른 call count를 확인한다. pre-STT health·consent·route 실패는 Azure 0회·OpenAI 0회, authorized Azure 이후의 privacy failure는 Azure 1회 이하·감사 1건·OpenAI 0회여야 한다. 담당 실무자의 `generate`, `regenerate`, `detect_discrepancies`는 각각 OpenAI tuple의 operation과 JSON `store:false`로 실행하고, 동의 철회 또는 `validUntil` 만료가 먼저 commit되면 모든 operation의 OpenAI 호출은 0회여야 한다.
