# SG11 Supabase 서울 프로젝트와 Edge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 기관 소유 Supabase 서울 프로젝트를 변경 없이 점검한 뒤 idempotent하게 설치하고, PostgreSQL·Auth·RLS·private Storage·cron·Edge 경계를 구현 가능한 계약으로 고정한다.

**Architecture:** ADR-0042의 read-only `plan`을 모든 적용보다 앞에 둔다. 새 프로젝트에는 PostgreSQL `0001_baseline.sql`과 `0002_supabase_platform.sql`을 순서대로 적용하고 migration checksum ledger와 hash-only install receipt를 남긴다. Edge는 공통 `handleRequest`의 얇은 Deno wrapper만 맡고, DB는 API-only role과 org-scoped RLS로 보호하며 audio byte는 Supabase Storage 경로로 직접 흐르게 한다.

**Tech Stack:** Supabase Management API, Supabase PostgreSQL, Supabase Auth, private Storage, `pg_cron`, `pg_net`, Deno `serve`, TypeScript, SHA-256 fingerprints, pinned Supabase CLI 2.116.0

**Spec:** `docs/specs/S11-supabase-edge-template.md`

## Global Constraints

- Community Cloud는 기관이 소유한 `ap-northeast-2`(Seoul) Supabase 프로젝트 하나를 사용한다.
- Supabase Edge는 globally distributed이며 project Seoul은 hard Edge residency 보장이 아니다. browser/API와 `pg_net`은 `x-region: ap-northeast-2`(불가 시 `forceFunctionRegion`)을 보내고, 응답 `x-sb-edge-region`과 함수 내부 `SB_REGION`을 receipt/log에 기록한다. mismatch는 실패·alert하며 자동 reroute하지 않는다.
- 첫 공개 동작은 ADR-0042의 read-only `plan`이며, plan 전후 지문이 바뀌면 적용하지 않는다.
- `SUPABASE_ACCESS_TOKEN`은 환경변수에서만 받으며, DB 연결 문자열·service role key·JWT signing key는 명령행에 두지 않는다.
- 신규 설치는 공급자 기본 객체만 있는 깨끗한 프로젝트에 한정하고, 기존 업무 table·row·object·grant·cron이 있으면 0 write로 거부한다. 단, 동일 `installationId` journal과 ownership tag가 있는 미완성 자원만 resume/reconcile한다.
- 소유 검증은 기관 관리자 승인 S2 signed install manifest의 `institutionId`·`projectRef`·`expectedOwnerOrgId` binding과 Management API의 관찰 owner organization ID가 정확히 일치할 때만 통과한다. manifest가 없거나 owner가 다르면 0 write다.
- JSON Edge body는 `EDGE_JSON_BODY_MAX_BYTES = 1_048_576`(1 MiB) 이하만 허용하며, exact route schema의 unknown/nested blob·base64·byte-array field를 거부한다. oversized body는 전체 buffer 전에 거부한다.
- Scheduler는 S2 Vault credential adapter가 발급한 짧은 audience·route-scoped token, `jti` nonce replay store, no-Origin server authentication과 명시된 401/403 규칙을 사용한다.
- PostgreSQL은 `migrations/postgres/0001_baseline.sql`에서 시작하고, 이후 forward migration은 논리 ID와 checksum을 함께 관리한다. 과거 SQLite migration을 재생하지 않는다.
- `ccc_api`는 `NOBYPASSRLS`, `NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`인 DB 연결 전용 role이며 table owner가 아니다.
- 업무 table의 RLS는 default deny다. `anon`과 `authenticated`에는 grant가 없고, API 요청은 transaction-local `app.org_id`가 일치할 때만 같은 기관 row를 읽는다.
- Supabase Auth의 claims·issuer·audience·JWKS·MFA 규칙은 S2/E4-2를 정본으로 사용하며 설치 중 실사용자 계정을 자동 생성하지 않는다.
- `ccc-audio`는 private bucket이다. audio byte는 Edge, Cloudflare Worker, API gateway를 통과하지 않는다.
- Edge의 CPU 상한은 invocation당 2초, memory 상한은 256 MB, bundle 상한은 20 MB다. Edge에 NER, STT, LLM, 모델 파일, 원음 buffer를 넣지 않는다.
- CORS는 canonical `CCC_CLIENT_ORIGIN` 하나만 허용하며 `*`, origin reflection, credential cookie를 사용하지 않는다.
- Edge log, stdout, stderr, receipt에는 PII, 원문, JWT, URL, token, key, 공급자 원문 오류를 남기지 않는다. D81 허용 필드(code, session ID hash, timestamp)에 비식별 `x-sb-edge-region`/`SB_REGION` evidence만 추가한다.
- 오디오 보관 시계·claim·signed URL·삭제 증거는 S8/E5-6이 소유하고, `.cccx` envelope와 암호화는 S10이 소유한다. 이 계획에서 해당 정의를 복제하지 않는다.
- `확정`은 인터페이스·규칙·fixture·검증 명령이 문서에 완결된 상태이며 실제 적용·배포·복원 성공을 뜻하지 않는다.

## 구현자 인터페이스

- `plan(projectRef, tokenFromEnv, signedManifest) -> PlanReport`: 프로젝트 소유·리전·깨끗함·지원 버전과 pre/post fingerprint를 읽는다. 변경은 0건이어야 한다.
- `apply(projectRef, tokenFromEnv, signedManifest) -> InstallReceipt`: `planned → installing → installed|rollback_failed` durable journal, plan 재검증, advisory lock, per-step ownership tag/idempotency key, 순서가 있는 migration, 플랫폼 선언, 최종 fingerprint, hash-only receipt를 수행한다.
- `doctor(projectRef) -> DriftReport`: receipt와 live 선언 상태의 hash 차이만 category와 stable code로 보고하며 자동 repair하지 않는다.
- `rollback(projectRef, targetVersion, signedManifest, backup) -> InstallReceipt`: S12 서명·sequence, installId/projectRef/manifest digest, 대상 release history, schema/provider/backup compatibility를 확인하고 검증된 조합으로 복원한다. 임의의 down migration은 실행하지 않는다.
- Edge wrapper는 exact route JSON schema와 1 MiB body cap을 사용하며, audio MIME·multipart·binary·base64/blob/byte-array body에는 고정 code를 반환한다.
- `StorageSigner`만 `SUPABASE_SERVICE_ROLE_KEY`를 읽으며 business DB client/import와 분리된 allowlist adapter다. 계약상 설치 migration은 `0001_baseline`, `0002_supabase_platform`, S8 소유 `0003_audio_objects` 순서이며 각 ID와 SHA-256을 ledger에 기록한다.

### Task 2: PostgreSQL baseline, forward migration, API-only RLS

**Files:**
- Modify: `docs/specs/S11-supabase-edge-template.md`

**Interfaces:**
- Consumes: S1 Database 포트와 parity 규칙, E3-4/E3-5.
- Produces: `0001_baseline.sql`, `0002_supabase_platform.sql`, S8 소유 `0003_audio_objects.sql`의 적용 순서와 role/RLS contract.

- [ ] `0001_baseline.sql`이 현재 logical schema의 기준선이며 SQLite 45개 migration을 번역 재생하지 않는다고 고정한다. baseline 전에 논리 migration이 아닌 bootstrap metadata transaction으로 journal/resource map/schema migration ledger를 만들고 `planned` 상태를 commit한다.
- [ ] `0002_supabase_platform.sql`은 bootstrap metadata를 다시 만들지 않고 private receipt/release history, `ccc_schema_owner`, `ccc_api`, grants/revokes, RLS, platform metadata를 소유한다고 고정한다.
- [ ] `ccc_api`의 `NOBYPASSRLS`, 비-superuser, 비-owner 조건과 transaction-local `app.org_id`/`app.actor_id` 경계를 적는다.
- [ ] `anon`, `authenticated`, API role without org, other-org API role의 direct-read 기대 결과를 규칙표로 닫는다.
- [ ] S8의 `0003_audio_objects.sql`과 원음 lifetime을 참조만 하며 정의를 중복하지 않는다.

### Task 3: Auth, private Storage, cron, Edge 제한

**Files:**
- Modify: `docs/specs/S11-supabase-edge-template.md`

**Interfaces:**
- Consumes: S2/E4-2 Auth and Scheduler credential contracts, S8/E5-6 AudioStore, E6-2/E6-3/E6-4 Edge·Storage·pairing ports.
- Produces: Auth provider 설정, `ccc-audio` private bucket, `ccc_scheduler_tick`, Edge request/CORS/resource contract.

- [ ] anonymous signup과 공개 signup을 끄고, email/password·invite·Auth user mapping·관리자 MFA는 S2/E4-2를 참조하도록 한다.
- [ ] `ccc-audio`를 `public=false`로 고정하고, `StorageSigner`만 service role key를 읽는 전용 function으로 분리한다. signer에는 business DB client/import가 없고 bucket/key/action/principal allowlist만 둔다.
- [ ] browser signed upload와 Agent claim-scoped GET만 허용하며 service role key와 signed GET을 browser에 주지 않는다고 적는다.
- [ ] `pg_cron`/`pg_net`의 단일 `ccc_scheduler_tick`, `* * * * *` schedule, S2 Vault credential adapter, 짧은 audience/route-scoped token, `jti` replay store, no-Origin과 401/403 규칙을 고정한다.
- [ ] Edge globally distributed caveat, `x-region: ap-northeast-2` 또는 `forceFunctionRegion`, response `x-sb-edge-region`, in-function `SB_REGION`, mismatch failure/alert/no-reroute와 residual international-transfer risk(S14/E9-3)를 고정한다.
- [ ] Edge는 SG6-validated masked AI Packet 또는 exact business JSON만 받고 original audio/unmasked text를 받지 않는다고 고정한다.
- [ ] Edge의 Deno wrapper, CPU 2초, memory 256 MB, bundle 20 MB, NER/STT/LLM/audio 금지를 고정한다.
- [ ] 모든 JSON route의 exact schema/keys/types, 1 MiB pre-buffer cap, unknown/nested blob/base64/byte-array rejection, exact-origin CORS의 canonicalization, 허용 methods/headers, `Vary: Origin`, `credentials=false`, mismatch 403/no ACAO와 `Cache-Control: no-store`를 고정한다.
- [ ] audio/multipart/binary body를 `AUDIO_BODY_FORBIDDEN`으로 거부하고 Edge log 허용 필드에 code·session ID hash·timestamp와 비식별 region evidence만 둔다.
