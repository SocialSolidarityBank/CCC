# 일정 화면 다중 뷰 설계 (일간 · 주간 · 월간)

- 상태: 승인 (2026-08-24, Q 그릴링). 티켓 **CCC-133**.
- 관계: **D75(ADR-0039)의 "현재 주간 + 별도 월 선택" 범위 전환과 본문의 ISO 주차 묶음을 대체**한다. 화면 이름 `일정` 하나, 사이드바 축(D35), 접근 권한(D7), 오늘 묶음 상태 유지(CCC-66), 미래 날짜 예정만(CCC-57), 이동 규칙(D47 ① · D54), 당사자 카드 계약은 그대로다.

## 배경

D75 는 '다가오는 일정'과 '전체 일정' 두 화면을 하나로 합치면서 범위를 현재 주간과 월 선택 둘로 두었다. 합친 것까지는 맞았지만 범위가 둘뿐이라 "오늘 하루만 보고 싶다"에 답이 없었고, 주간은 항상 이번 주로 고정이라 지난 주나 다음 주로 옮겨 갈 길이 없었다. 기간을 옮기는 조작이 월에만 있었던 것이다.

## 결정

1. **뷰는 셋이다. 일간, 주간, 월간.** 기본은 주간이다. 전부 서버 렌더이며 클라이언트 상태를 만들지 않는다(D75 가 없앤 것을 되살리지 않는다).
2. **범위는 URL 이 갖는다.** `?view=day&date=YYYY-MM-DD` · `?view=week&date=YYYY-MM-DD`(그 날짜가 속한 ISO 월요일-일요일 주간) · `?view=month&month=YYYY-MM`. 어긋난 값은 **조용히 버리고** 기관 시간대의 오늘과 이번 달로 떨어진다. 오류 화면을 내지 않는다.
3. **구 링크를 살린다.** `?range=month` 는 월 뷰로 옮기고 `month` 를 그대로 살린다. 그 밖의 `range` 값은 주간이다. `/programs/:type/schedule/all` 은 `?view=month` 리다이렉트만 남는다.
4. **기간 내비는 하나의 업무 바로 통합한다**(2026-08-25 Q 후속 개정). `minmax(0,1fr) auto minmax(0,1fr)` 세 칸에서 왼쪽은 `[오늘]+보기 선택창`, 가운데는 기간 이동, 오른쪽은 `당사자 등록+상담 등록`이다. 양쪽 칸의 실제 내용 폭이 달라도 기간 이동 묶음은 페이지 정중앙에 고정된다.
5. **이전·다음은 원형 면 없이 작은 화살표만 보인다.** 두 화살표는 32px 고정 슬롯에 놓여 일간·주간·월간의 기간 문자열 길이가 달라도 위치가 움직이지 않는다. 화살표는 16px glyph에서 2px 굵기이며 날짜 사이 간격은 양쪽 모두 `--space-2`다. 날짜는 14/500, 자간 0이다.
6. **이동 폭은 뷰가 정한다.** 일간 하루, 주간 7일, 월간 한 달이며 달과 해 경계를 넘는다. `[오늘]`은 보던 뷰를 유지한 채 기간 파라미터만 뗀다.
7. **본문은 날짜 → 카드 두 층이다.** 세 뷰 모두 일정이 있는 날짜만 시간순으로 그린다. 주차 제목은 본문에서 뺀다(내비가 이미 기간 이름을 말한다).

## 기간 이름과 배치

- 기간 이름은 **세 뷰 모두 한 줄**이고 날짜만 말한다. 일간 `2026년 8월 24일(월)` · 주간 `2026년 8월 24일(월)-8월 30일(일)` · 월간 `2026년 8월`.
- **주차 번호는 적지 않는다**(2026-08-24 Q 개정, 구 `N째 주` 두 줄 라벨 대체). 실무자에게는 몇째 주인지보다 어느 날짜인지가 중요하다. 주간 범위는 시작에 연도를 붙이고 끝은 달부터 적되 해가 바뀔 때만 연도를 다시 붙인다.
- **업무 바는 테두리 있는 면 하나로 묶는다.** `--line` 1px 아웃라인 + `--radius-card` 12 + `--panel` 면이며 그림자는 두지 않는다. 안에 카드를 다시 깔지 않는다.
- 붙박이 툴바, 페이드, 스크롤 앵커, 달력 격자, 시간 격자, 날짜 띠, 필터는 **두지 않는다**.
- 실제 본문 컨테이너가 760px 이하이면 업무 바를 **조작·기간·행동 세 줄**로 쌓는다. 이 규칙은 768px 데스크톱에서 사이드바가 본문을 좁히는 경우도 잡는다. 기간은 자기 줄 중앙, 등록 행동 둘은 같은 폭이다. 기간 이름은 14/500을 유지하고 아주 좁은 폭에서만 두 줄로 풀어 전문을 보여 준다.

## 2026-08-25 후속 정제

- 공통 입력값은 input·select·textarea 모두 14/400 `--ink`로 통일한다.
- 날짜 묶음 제목(`.record-section-title.schedule-day-heading`)은 16px다.
- 지난 일정은 amber·lime 색을 쓰지 않는다. 두 색은 밝은 면 위 글자 대비가 각각 2.32:1, 2.21:1이고 주의·성공 의미를 잘못 보탠다. 지난 일정은 `--muted` 중립 면을 쓰고 자식 전체 opacity를 제거해 텍스트 대비를 보존한다.
- 일정과 당사자 목록은 같은 아웃라인 업무 바(`.work-toolbar`)를 쓴다. 일정은 등록 행동 둘을 오른쪽 안에 넣고, 당사자 목록은 보이는 검색 라벨 없이 검색창과 등록 행동 둘을 한 줄에 둔다. 767px 이하는 같은 바 안에서 줄만 나눠 넘침을 막는다.
- 2026-08-25 최종 밀도: 당사자 검색 아래 구분선은 없애고 검색 폭 상한은 540px로 둔다. 일정 보기 선택창은 실제 렌더 폭 254px의 약 1/3인 84px로 고정한다. 기간 이름은 22ch, 화살표와 라벨의 grid gap은 `--space-2`다.
- 같은 날 후속 형태 조정: 모든 `.wire-button`은 `--radius-pill` 알약으로 바꾼다. 선택창·검색창과 기간 이동 화살표는 기존 형태를 유지한다.
- 선택창 실측 교정: `.schedule-nav .schedule-view-select`에 폭·flex-basis 84px를 함께 고정하고 좌측 패딩은 8px다. 검색과 선택은 공용 `WireToolbarField`를 쓰며, 화면에 숨긴 접근성 라벨은 유지한다.

## 뷰별 펼침

| 뷰 | 지난 날짜 | 오늘 | 미래 날짜 |
| --- | --- | --- | --- |
| 일간 | 카드만 (날짜 이름은 내비가 갖는다) | 카드만 | 카드만 |
| 주간 | 접힘 줄 (날짜, 이름, 건수) | 펼친 구획 (날짜 제목, 건수, 그리드) | 펼친 구획 |
| 월간 | 접힘 줄 | 접힘 줄, **기본 펼침** | 접힘 줄 |

- 월간은 모든 날짜가 날짜 단위 아코디언이고 **기관 시간대의 오늘만** 열려 있다. 오늘이 없는 달은 전부 닫힌 채로 연다.
- 흐림은 **지난 줄과 완료 카드**에만 건다. 미래 줄은 흐리지 않는다.
- 카드 그리드는 768 이상 고정 2열(홀수 마지막 칸은 빈다), 모바일 1열이다.

## 데이터

새 SQL, 새 마이그레이션, 새 엔드포인트, 새 색은 **0** 이다. 게이트웨이의 `getTodaySchedules(date, days)` 가 이미 임의 창을 받고 기존 두 함수가 그 위의 얇은 래퍼다.

| 뷰 | 경로 |
| --- | --- |
| 일간 | `getTodaySchedules(date)` 하루 |
| 주간 | `getUpcomingSchedules(ISO 월요일)` 8일 창을 받아 **끝의 다음 월요일 하루를 잘라** 월-일 7일로 맞춘다 |
| 월간 | `getMonthSchedules(month)` 한 달 |

접근 범위(담당 활성 배정 또는 활성 기관 관리자)와 감사는 셋이 같은 게이트웨이를 지나므로 그대로다.

상태 규칙은 기존 결정을 일반화한다. 지난 날짜는 완료, 취소, 불참을 전부 보여 주고(D54), 오늘은 상태를 거르지 않으며(CCC-66), 내일 이후는 예정만 남는다(CCC-57). 임의 주간으로 옮겨 가도 이 기준은 '오늘'이 정한다.

## 하지 않는 것

- 달력 격자와 시간 격자를 만들지 않는다. 본문은 날짜별 목록이다(D75 의 기각 이유가 그대로 유효하다).
- 필터를 두지 않는다. 기간 전환이 곧 필터다.
- 전사 전문 뷰어처럼 이 화면 밖의 것을 끌어오지 않는다.
- 시간순 정렬 토글을 되살리지 않는다. 날짜 묶음 제목이 순서를 이미 말한다.
