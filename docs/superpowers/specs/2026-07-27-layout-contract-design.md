## 0. 한 줄 정의

`DESIGN.md`가 색·컴포넌트에는 20개가 넘는 계약을 두면서 **레이아웃에는 3줄만 두고 있어서**, 생성 도구와 사람이 매번 페이지 폭·여백을 새로 발명한다. 이 스펙은 레이아웃을 색 토큰만큼 촘촘한 계약으로 승격하고, 그 계약을 **1440 캔버스에서 역산한 숫자**로 채운다.

## 3. 가로 프레임 — 1440에서 역산

**모든 숫자는 1440 캔버스에서 나온다.** 시안 실측 1280은 "그날 캔버스가 1280이었다"는 사실일 뿐 결정이 아니므로, 여기서 파생된 값(글 폭 960)은 채택하지 않는다.

| 층 | 값 | 도출 |
| --- | --- | --- |
| 전체 캔버스 | **1440** | 데스크톱 기준 프레임 (맥북 프로 14 = 1512, 일반 노트북 = 1440) |
| 사이드바 | **240** | 기존 `--sidebar-width` 유지. 화면 **왼쪽 끝에 붙인다** |
| 본문 영역 | 1200 | 1440 − 240 |
| 페이지 컨테이너 | **max-width 1120**, `margin-inline:auto` | 1200 안에서 좌우 40씩 남는다 — 별도 마진 토큰 없이 중앙 정렬 잔여로 생긴다 |
| 컨테이너 패딩 | **좌우 40** | |
| **글 폭** | **1040** | 1120 − 80. 한 줄 약 65자 |

- `box-sizing:border-box`이므로 **1120에는 패딩 40이 포함된다.** 이 한 문장이 계약에 반드시 들어간다 — 이게 빠져서 1040이라 적고 960이 나오는 사고가 났다.
- 1360 아래로 내려가면 중앙 정렬 잔여 40이 먼저 사라지고 패딩 40이 남는다. 글 폭은 그때부터 화면을 따라 줄어든다.
- 사이드바는 왼쪽 끝 고정이므로 **왼쪽 바깥 여백은 존재하지 않는다.** 40은 본문 영역 안의 중앙 정렬 잔여다.

### 한글 읽기 폭 근거

16px 한글은 글자 폭이 약 16px이라 **폭이 곧 글자 수**다. 1040 → 약 65자. 한글 본문 상한선(60~70자) 안이다. 이 제약은 **전폭 한 줄로 흐르는 요소**(설명 문장·목록 행·리스크 배너)에만 걸린다. 카드가 2열로 갈리는 구간은 열당 510이라 무관하다.

## 4. 카드 그리드

**gap 20 고정. 열 개수를 지정하지 않는다 — 최소 폭이 열 수를 만든다.**

| 그리드 | 최소 폭 | 1440에서 | 상위 열 방지 | 접히는 지점 |
| --- | --- | --- | --- | --- |
| **표준** | **420** | 2열 · 각 510 | 3열엔 1300 필요 → 1040 안에서 불가 | 1열 = 화면 1180 미만 |
| **조밀** | **280** | 3열 · 각 333 | 4열엔 1180 필요 → 1040 안에서 불가 | **1열 = 화면 1200 미만 (2열을 건너뛴다)** |

접히는 지점은 글 폭 기준으로 표준 2열 860 · 조밀 3열 880이고, 위 표는 여기에 사이드바 240과 패딩 80을 더해 화면 폭으로 환산한 값이다.

**조밀 그리드는 3열 아니면 1열이다.** 2열이 되면 3개짜리 묶음(GAS 세부 목표)이 둘 + 외톨이 하나로 앉아 읽는 순서가 꺾인다. 880(=280×3+20×2) 아래로는 2열을 거치지 않고 곧장 한 줄에 하나씩 간다. 구현은 `@container (max-width:879px){.grid-dense{grid-template-columns:minmax(0,1fr)}}`.

- **표준** = 브리핑 아코디언, 일반 정보 카드. `DESIGN.md` §4의 "카드 그리드 2열"을 최소 폭으로 강제한다.
- **조밀** = GAS 게이지, 정보 필드, 기록지 보조 레일. D33의 "진행 중 세부 목표 최대 3개 가로 배치"를 최소 폭으로 강제한다.

### 실제 화면에서의 거동

| 화면 폭 | 글 폭 | 표준 | 조밀(GAS) |
| --- | --- | --- | --- |
| 1440 | 1040 | 2열 · 510 | 3열 · 333 |
| 1280 (맥북) | 960 | 2열 · 470 | 3열 · 306 |
| 1200 | 880 | 2열 · 430 | 3열 · 280 |
| 1024 (태블릿) | 704 | 1열 | 1열 |
| 767 (모바일 경계) | 735 | 1열 | 1열 |
| 390 (휴대폰) | 358 | 1열 | 1열 |

### 규칙

- CSS는 `repeat(auto-fit, minmax(var(--grid-min), 1fr))` 한 줄. **`grid-template-columns: repeat(<숫자>, ...)`로 열 수를 직접 쓰지 않는다.**
- **표준과 조밀은 별개 그리드다.** 최소 폭은 카드가 아니라 그리드 트랙에 걸리므로, 카드에 클래스를 붙여도 트랙 최소 폭은 바뀌지 않는다. 한 컨테이너 안에 두 종류를 섞지 않는다.
- **"최대 N열" 조항을 두지 않는다.** 최소 폭이 이미 상한을 만든다 — 중복 규칙은 어긋난다.
- 열 수를 바꾸고 싶으면 **본문 폭을 고치지 카드 최소 폭을 건드리지 않는다.** 최소 폭은 `DESIGN.md` §4·§5가 정한 열 수(표준 2 / 조밀 3)의 결과이지 취향이 아니다.
- 넓게 써야 하는 카드는 `grid-column: span 2`. **해제 조건은 화면 폭이 아니라 그리드 폭이다** — `@container (max-width:859px){.span-2{grid-column:auto}}`. 859는 표준 2열 하한 860 바로 아래다. 카드별 표준/조밀/span2 배정은 `DESIGN.md` §5 컴포넌트 계약에 카드마다 적는다.

### 4-1. 아코디언 행 높이 (2026-07-27 PM 확정)

두 가지를 동시에 만족해야 한다.

1. **접으면 그 행이 실제로 좁아진다** — 빈 자리를 남겨 두지 않는다.
2. **둘 다 펼치면 큰 쪽에 높이를 맞춘다** — 나란한 카드가 들쭉날쭉하지 않게.

답은 행 높이를 박는 것이 아니라 **카드마다 정렬을 다르게 주는 것**이다. 행 높이는 그대로 내용이 정한다.

```css
.grid[data-rows="acc"] > details[open]      { align-self: stretch }  /* 행 높이를 채운다 = 서로 같아진다 */
.grid[data-rows="acc"] > details:not([open]){ align-self: start   }  /* 제 요약 줄만큼만 = 빈 상자가 안 생긴다 */
```

**자바스크립트로 높이를 재서 박지 않는다.** 처음엔 각 행의 "다 열었을 때 최댓값"을 재서 `grid-template-rows`에 박았는데, 그러면 ① 다 접어도 행이 안 줄어 빈 자리가 남고 ② 내용이 바뀌는 순간 박아 둔 값이 거짓이 된다. CSS 두 줄이 같은 일을 더 정확하게 한다.

### 무엇이 아코디언인가

**전체 목표 아래는 전부 카드 아코디언이다** — 진행 중인 세부 목표(GAS) · 상담 준비 자료 4장 · 추가 정보. 여섯이 같은 조각(`details.acc`)이라 접힌 높이도 57로 같다.

> 섹션을 통째로 `<details>`로 바꿔 제목 줄을 `<summary>`로 만드는 안을 먼저 시도했다가 버렸다. 구조를 새로 만들면 스타일도 새로 만들어야 하고, 실제로 그 CSS가 안 먹어 브라우저 기본 삼각형이 나오고 제목·아이콘·배지가 세 줄로 흩어졌다. **이미 있는 조각을 쓰면 새로 깨질 자리가 없다.**

접히지 않는 것은 둘뿐이다. **리스크 배너**(D9가 접힘 불가로 못 박음)와 **전체 목표**(한 줄이라 접을 게 없다).

**여닫기 버튼은 페이지에 하나만 둔다.** 자리는 전체 목표 아래, 첫 아코디언 바로 위다 — HERO 바로 아래는 D9가 리스크 배너에 준 자리라 쓸 수 없고, 이 줄이 다루는 대상이 바로 아래부터 시작하기 때문이기도 하다. 오른쪽 끝 정렬에 고스트 sm.

라벨은 **지금 상태가 아니라 누르면 일어날 일**을 가리킨다. 하나라도 접혀 있으면 `전체 펼치기`, 전부 열려 있으면 `전체 접기`다. 섞인 상태에서 누르면 **전부 펼쳐진다** — 접는 쪽이 기본이면 뭔가를 보려던 사람의 화면이 오히려 닫힌다.

| --- | --- | --- |
| 전부 열림 | 480 | **180 / 180** · **280 / 280** — 행마다 큰 쪽에 맞음 |
| 하나만 접음 | 471 | **57** / 171 · 280 / 280 — 접힌 카드만 짧아짐 |

## 5. 세로 리듬

이전 초안의 32는 `DESIGN.md` §3-4의 "섹션 간 24"(시안 관찰값)와 충돌하므로 **폐기한다.** 새 숫자 없이 기존 사다리만 쓴다.

| 자리 | 값 |
| --- | --- |
| 페이지 헤더 아래 | **40** (본문 패딩과 같은 값) |
| 섹션 사이 | **24** (§3-4 그대로) |
| 섹션 제목 ↔ 내용 | **16** |
| 카드 사이 (gap) | **20** |

**섹션 제목은 카드 밖에 h2 18/700로 둔다.** 카드 안에 14px 라벨로 넣으면 같은 층의 다른 섹션들과 크기가 어긋나 무게가 달라 보인다(전체 목표가 그랬다). 카드 안 14/700 민트 deep 라벨은 **필드 이름** 전용이고 섹션 제목이 아니다.

사다리는 **16 / 20 / 24 / 40** 넷으로 끝난다. 카드 안쪽 패딩(헤더 16·24, 본문 20·24, 단순 카드 24)과 사이드바 내부(패딩 24 · 항목 간격 4 · 블록 간격 32)는 §3-4 관찰값 그대로 둔다.

## 6. 브레이크포인트 — 768 하나

앱 안 5벌(1120·900·768·640·359)을 **768 하나로 수렴**시킨다.

| 폐기 값 | 어디로 흡수되나 |
| --- | --- |
| 1120 (`wire-container` 거터) | `.wire-container` 폐기와 함께 사라진다 (§14 미결 1) |
| 900 (기록지 200px 레일 접힘) | 레일을 **조밀 그리드(280)에 편입** → 자동으로 접힌다 |
| 640 (`wire-container` 거터 + 헤더 띠) | `.wire-container`·`AppHeader` 폐기와 함께 사라진다 |
| 359 (초협폭 보정) | 실사용 기기가 확인되기 전엔 규칙이 아니라 추측이므로 제외 |

**경계 정의**: `@media (max-width: 767px)`를 쓴다. 즉 **768px은 데스크톱**이다. `max-width:768px`과 "768 미만"이 1px 어긋나는 사고를 막기 위해 값 하나로 못 박는다.

### 768 미만

| 항목 | 값 |
| --- | --- |
| 사이드바 | → **드로어로 숨긴다**. 상단에 높이 **56** 손잡이 바(햄버거 + 조직명, 스티키)만 남고, 누르면 왼쪽에서 폭 **280**(최대 82vw) 패널이 밀려 들어오며 스크림이 뒤를 덮는다 |
| 컨테이너 패딩 | 세로 24 · 가로 16 |
| 그리드 | **1열 강제 규칙을 두지 않는다** — 최소 폭이 이미 접는다. `span 2`만 해제한다 |
| 페이지 헤더 행동 버튼 | 세로 쌓기 · 전폭 (이미 코드에 있으나 문서에 없던 규칙) |

**사이드바를 눕히지 않고 숨기는 이유**: 상단 가로 줄로 눕히면 조직명·사업 전환기·메뉴 4개가 한 줄에 밀려 들어가 어느 것도 읽히지 않는다(구 `base.css` 방식이 그랬다). 좁은 화면에서 장소 전환은 자주 하는 동작이 아니므로 평소엔 감추고 부를 때만 꺼내며, 그만큼 본문이 화면을 온전히 쓴다. 이 상단 바는 **락 #8이 금지한 '상단 헤더 띠'가 아니다** — 데스크톱에는 없고, 내용은 드로어 손잡이뿐이다.

> 구현 주의: 시안은 체크박스로 여닫지만 **실제 구현은 버튼 + `aria-expanded`**로 만든다. 체크박스는 `display:none`이라 키보드 초점을 받지 못한다. 열렸을 때 초점 가두기와 `Esc` 닫기도 필요하다.

모바일에 별도의 1열 강제를 두지 않는 이유는, 이미 §4의 규칙이 그 일을 하기 때문이다. 표준은 최소 폭 420이 접고, 조밀은 "3열 아니면 1열" 규칙이 접는다. 화면 폭을 기준으로 한 번 더 강제하면 같은 결정이 두 곳에 생기고, 둘이 어긋나는 날 어느 쪽이 맞는지 알 수 없게 된다. **접는 주체는 언제나 폭이다.**

## 7. 페이지 헤더 슬롯

ADR-0014의 축이 **"사이드바 = 장소 / 페이지 우상단 = 행동"**인데 계약이 없었다. 도구가 가장 많이 오해하는 자리다.

**페이지 헤더도 카드다** (2026-07-27 PM 확정). 캔버스 위에 맨 글자를 얹으면 그 글자만 어느 카드에도 속하지 않아 좌우 정렬 기준이 사라지고, 행동 버튼도 허공에 뜬다. **화면의 모든 글자는 카드 안에 있다** — 예외는 섹션 제목뿐이며, 그것은 카드 여러 장을 묶는 이름이라 어느 한 장에 들어갈 수 없다.

- 카드 계약 그대로: 흰 배경 · radius 12 · `--shadow-soft` · 패딩 24
- **이름 표기는 세로 가운데로 맞춘다.** `DESIGN.md` §5는 `이름 (가명 ID)`를 텍스트 노드 2개 + 간격 4로 만들라고만 정했는데, 그대로 두면 28px 이름과 16px ID가 **기준선(baseline)에 걸려 ID가 아래로 처져 보인다.** 이름 묶음을 `inline-flex` + `align-items:center`로 두어 이름·가명 ID·상태 배지 세 조각의 세로 중심을 하나로 맞춘다(실측 세 조각 모두 중심 82px).
- 링크로 만든 버튼(`<a class="btn">`)은 **밑줄을 끈다.** `base.css`는 `.nav a`와 `.row`에서만 밑줄을 껐다.
- 구성: 좌측(제목 28/700 + 설명 16/400) · 우측(행동 버튼) · `align-items: center`
- 행동 버튼 **최대 2개**. 순서는 **세컨더리 → 프라이머리**(오른쪽 끝이 주 행동). 3개 이상이 필요하면 그중 하나는 페이지 안으로 내리거나 메뉴로 접는다
- 헤더 아래 간격 40
- 768 미만: 세로 쌓기 · 버튼 전폭

## 14. 미결 사항 (CCC-18 착수 전 확정 필요)

1. **12열 그리드 대체 어휘.** `.wire-container`가 콘텐츠 820 + 12열(50)·거터 20을 만들고 `wire-col-3/4/6/12`를 제공한다. **참여자 등록 · 상담 등록 · 인테이크 위저드 · 프로그램 일정 카드 · kit 페이지 5곳이 쓴다.** 이 계약의 auto-fit 어휘에는 "폼 필드 반칸"에 해당하는 표현이 없다. 대체안 후보: `.field-grid{repeat(2,minmax(0,1fr));gap 16}` + `wire-col-*` → 신규 어휘 매핑표. **확정 전 `.wire-container` 삭제 금지.**
2. **빈 상태 계약이 3개로 갈려 있다.** `layout.tsx:91`(가로 flex·좌측 정렬·min-height 92) / `base.css:176`(세로·가운데·패딩 40/24) / `DESIGN.md:195`(아이콘 28 + 제목 + 설명 34자폭 + 세컨더리). 하나로 정하고, **페이지 전체가 빈 상태일 때 세로 가운데인지 상단 고정인지**도 정한다.
3. **가로 스크롤 탈출구.** 레포 전체에 `overflow-x` 규칙이 0건이다. `.case-row`는 5열 그리드라 좁아지면 압축될 뿐 탈출구가 없다. 표·긴 목록은 자체 `overflow-x:auto` 컨테이너를 갖는다는 규칙이 필요하다.
4. ~~인쇄(`@media print`)~~ → **후속 티켓으로 분리 (2026-07-27 Q 결정)**. 레포 전체에 인쇄 규칙이 0건이고 실제 출력 요구가 확인되지 않았다. 지금 정하면 화면 규칙이 두 벌이 되므로, 요구가 확인된 뒤 별도 티켓으로 다룬다.
5. **긴 문자열 줄바꿈 기준.** 한글 이름, 긴 사업명, 가명 ID, 이메일이 좁은 열에서 어떻게 끊기는지 규정이 없다.

## 15. 프레임 검증 결과 — 구현 함정 4건 (2026-07-27 실측)

목업을 만들어 재 보니 계약대로 쓴 CSS가 계약대로 렌더되지 않는 자리가 넷 있었다. **넷 다 숫자가 아니라 구현 방식의 문제**이며, CCC-18에서 같은 실수를 반복하지 않도록 여기 남긴다.

1. **`.main{min-width:0}`이 없으면 본문이 부푼다.** flex 항목의 최소 폭은 내용물이 정하는데, 그리드 트랙 최소 폭(420×2+20 = 860)이 그 값을 끌어올려 본문이 사이드바를 밀어낸다. 1024에서 컨테이너가 784가 아니라 **848**로 나왔다. 가로 스크롤도 함께 생긴다.
2. **`grid-column: span 2`는 열 수를 되끌어올린다.** 뷰포트 기준으로 해제하면 "아직 데스크톱인데 그리드는 1열"인 구간(1024)에서 span 2가 살아남아 스스로 2열을 요구한다. 1024에서 표준 열이 1이 아니라 **2**로 나왔다. 해제는 **컨테이너 질의**로 한다(§4).
3. **`minmax(420px, 1fr)`는 휴대폰에서 삐져나간다.** 트랙이 420 아래로 못 내려가기 때문이다. `minmax(min(420px, 100%), 1fr)`로 쓴다.
4. **리스크 배너가 카드로 안 그려지고 있었다.** `artifacts/design-system-v2/screens/base.css:216`이 **존재하지 않는 토큰 `--gradient-risk`**를 참조해 `background` 선언 전체가 무효가 됐고, 배경도 테두리도 없이 맨 글자가 캔버스에 떠서 다른 카드와 좌우가 어긋나 보였다. D34가 배너 테두리를 `--gradient-brand`로 바꿀 때 남은 자국이다. **`design/tokens.css`에 `--gradient-risk`는 없다** — CCC-18에서 `base.css`(또는 그 후신)를 옮길 때 같이 고친다.
   > 교훈: CSS는 없는 변수를 만나면 그 선언만 조용히 버린다. 오류도 경고도 없다. 토큰 이름을 바꿀 때 참조처를 전수 검색하지 않으면 이렇게 한 조각만 소리 없이 사라진다.

부수로, 검증 도구 자체에서도 두 가지를 배웠다. 계약값을 표로 박아 두면 스크롤바 15px 때문에 화면 폭이 1425가 되는 순간 조회가 빗나가 **검사가 조용히 꺼진다** — 표 대신 계산식을 옮겨야 한다. 그리고 모바일 판정을 `clientWidth < 768`로 하면 CSS의 미디어 질의와 최대 15px 어긋나므로 `matchMedia`로 CSS에게 직접 물어야 한다.

## 17. 설명 팝오버 — 개념을 알아야 읽히는 이름 옆에

GAS처럼 **이름만 봐서는 뜻을 모르는 항목**이 화면에 여럿 있다(GAS·확장 슬롯·승인 대기·가명 ID). 설명을 화면에 늘어놓으면 밀도가 무너지고, 안 적으면 신입 상담사가 못 읽는다. 부를 때만 뜨는 작은 창으로 푼다.

- **손잡이**: 이름 오른쪽에 18px 원형 `i`. 테두리 `--sub` 1px, 호버 시 `--ink`. 커서 `help`
- **창**: 손잡이 아래 간격 8, 가운데 정렬. 폭 **최대 280**, 패딩 16, radius 12, `--shadow-soft` + 떠 있는 그림자. 제목 14/700 `--ink` + 본문 14/400 `--sub`
- **층**: `--z-dropdown`(30) — 카드 위, 모달 아래 (§9)
- **여는 조건**: `:hover`와 **`:focus-within`을 반드시 함께** 건다. 호버 전용으로 만들면 키보드·터치 사용자에게는 영영 보이지 않는다
- **마크업**: 손잡이는 `<button>`(`div`가 아니다 — 초점을 받아야 한다), 창은 `role="tooltip"`, 손잡이에 `aria-describedby`
- **넣지 않는 것**: 조작·링크·입력. 설명 문장만 둔다. 조작이 필요하면 그것은 팝오버가 아니라 모달이다

> 이 컴포넌트는 **읽는 사람을 위한 것이지 기록을 위한 것이 아니다.** 용어의 정본은 `artifacts/glossary-v1.html`이고, 팝오버는 거기서 한 문단을 가져와 보여줄 뿐이다. 두 곳에 각각 쓰면 갈라진다.

## 18. 자동 생성 필드 — 확장 슬롯의 화면 규칙

수급 여부·가구원 수처럼 **사업마다 다른 항목**은 항목 풀에서 골라 붙인다(확장 슬롯, `CLAUDE.md` §3). 사람이 배치를 정하지 않는다 — **항목의 종류(type)가 배치를 정한다.**

| type | 보기 모드 | 편집 모드 | 자리 |
| --- | --- | --- | --- |
| `text` | 값 16/700 | 입력칸 (§8 컨트롤) | 조밀 그리드 한 칸 |
| `choice` | 값 16/700 | select | 조밀 그리드 한 칸 |
| `number` | 값 16/700 + 단위, **숫자 자간** | 입력칸 | 조밀 그리드 한 칸 |
| `date` | 값 16/700, **숫자 자간** | 날짜 선택기 | 조밀 그리드 한 칸 |
| `text-long` | 값 16/400, 줄높이 1.6 | textarea | **한 줄 전체**(`grid-column:1/-1`) |

- 공통 껍데기는 `DESIGN.md` §5의 **정보 필드** 그대로다: 라벨 14/700 민트 deep(위) + 값(아래), 간격 4.
- 배치는 **조밀 그리드(280)** 하나뿐이다. 항목이 몇 개든 폭이 열 수를 정한다(§4). 항목 개수에 따라 열을 바꾸지 않는다.
- `number`·`date`는 `--tracking-numeric`를 쓴다. 숫자가 섞인 한글 문장에는 쓰지 않는다.
- **긴 글만 줄을 통째로 쓴다.** 한 칸(333)에 넣으면 서너 글자마다 줄이 바뀐다.
- 확장 슬롯이므로 **통계와 브리핑 요약에는 들어가지 않는다**(`CLAUDE.md` §3). 화면에만 있다.

> 이 규칙의 값어치는 "항목이 늘어도 레이아웃 결정이 늘지 않는다"는 것이다. 새 항목을 붙이는 사람은 type만 고르면 되고, 어디에 어떻게 놓을지는 아무도 다시 정하지 않는다.

## 19. 브리핑 이어보기

`자세한 상담 기록 보기`는 **브리핑의 아래쪽 끝**이다. 별개 화면으로 가는 버튼이 아니라 "여기서 더 자세히"다.

- 자리: 페이지 **맨 아래**, 전폭 행
- 모양: 카드 계약(흰 배경·radius 12·`--shadow-soft`) · 패딩 20/24 · 좌측 제목 16/700 + 설명 14/400 · 우측 오른쪽 꺾쇠
- 문안: 제목 `자세한 상담 기록 보기` / 설명 `위 브리핑을 펼친 전체 기록과 1~N회차 이력`
- 꺾쇠는 **오른쪽**을 가리킨다. 아코디언의 아래쪽 꺾쇠와 같은 모양을 쓰면 "펼쳐진다"로 읽힌다

## 20. 사이드바 내부 (2026-07-27 PM 확정)

폭 240과 배경(`--gradient-sidebar`)은 §3·`DESIGN.md` §4 그대로다. 안쪽 규칙만 더한다.

**세 덩어리를 구분선으로 가른다** — 조직 | 사업 | 메뉴. 셋의 성격이 다르기 때문이다: *어디 소속인가* / *무엇을 보고 있나* / *어디로 가나*. 간격만으로는 "사업"이 메뉴의 첫 항목처럼 읽힌다.

- 선은 `1px solid var(--line-sidebar)`, 위아래 여백 **16씩**
- **`--line` 을 쓰지 않는 이유**: `--line`(#E7E5E4)은 흰 카드 위에서 쓰라고 만든 값이라 파스텔 그라데이션 바탕에서는 거의 보이지 않는다. **`--line-sidebar: rgba(61, 52, 69, 0.16)`** 를 신설한다 — 새 색조를 들이는 게 아니라 `--ink`를 옅게 깐 것이고, `--line-action`(잉크 50%)이 이미 쓰는 방식이라 D34의 "새 색 도입 금지"에 걸리지 않는다
- 그래서 블록 사이 총 간격은 **32** — `DESIGN.md` §3-4의 "사이드바 블록 간격 32"가 그대로 지켜진다. 선이 그 32를 반씩 나눠 가질 뿐이다

**사업 전환기는 알약이 아니라 직사각형 + radius 6이다.** 이건 행동을 하는 버튼이 아니라 **값을 고르는 컨트롤**이다. `DESIGN.md` §5의 입력칸·select와 같은 모양이어야 "누르면 목록이 열린다"로 읽힌다. 알약은 행동 버튼(§7 행동 슬롯)의 모양이므로 여기 쓰면 축이 섞인다.

| 조각 | 계약 |
| --- | --- |
| 조직명 | 32px 마크 + 16/700, 아래 구분선 |
| 사업 라벨 | 14/700 `--sub` |
| 사업 전환기 | 높이 40 · **radius 6** · 흰 배경 · `--line-control` 1px · 전폭 · 우측 꺾쇠, 아래 구분선 |
| 메뉴 항목 | 높이 40 · radius 6 · 14/700 · 항목 간격 4 · 활성은 블루 tint 배경 + blue-deep 글자 |
| 사용자 | 14/700 `--sub`, `margin-top:auto`로 바닥에 붙임 |
