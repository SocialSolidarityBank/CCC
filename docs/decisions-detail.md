- **D47 유형 칩과 blue 배지 대체**: 기본 상담은 민트, 인테이크는 라벤더를 쓴다(같은 날 Q 후속 결정, 구 라임/앰버 대체). 형제 배지 variation의 기본 배정 순서는 민트, 라벤더, 코랄, 시안, 라이트마젠타(`#D96BC8`)이고 라임과 앰버는 최후순위 폴리백이다. blue 채움 배지는 `TimeAxisBadge`가 만드는 오늘, 날짜, 주차, 기한에만 쓰고 나머지 정보와 상태 배지는 neutral이다.

D55 의 "두 버튼 테두리는 같은 세기"는 그대로이며 값만 면을 따라간다(라이트에서 두 값이 같아 **라이트 렌더는 변하지 않는다**). 함께 토큰이 된 것: **`--scrim`**(화면에 rgba 리터럴로 두 번 박혀 있었고, 다크에서 그대로면 어두운 화면 위에 보라 장막이 한 겹 더 앉는다). ****토글은 사이드바 발치**에 있다(로그아웃과 같은 서버 액션 폼). `prefers-color-scheme` 만 일부러 안 붙였다** — 팀 검수는 미리보기 환경에서 이뤄지는데 자동 감지를 켜면 OS 가 다크인 검수자에게 **Q 가 아직 보지 않은 팔레트**가 나가고, 색값이 명시적으로 동결된 시스템에서 그건 사고다. 승인되면 미디어 쿼리 한 블록으로 켠다. **강제 장치 2건**: `guard:tokens` 의 **dark-parity 검사**(라이트에서 원시 색값으로 선언된 토큰은 다크에 대응이 있거나 허용목록에 사유와 함께 있어야 한다 — `--gradient-sidebar` 하나만 빠져도 어두운 화면에 흰 사이드바가 켜지는데 30개 값을 눈으로 훑어 찾을 수는 없다)와 `pnpm design:contrast`(§9 표의 숫자를 사람이 손계산해 왔다 — 틀려도 아무도 모르고 색이 바뀌면 표만 낡는다). `green` **§9 접근성 예외 7건이 다크에서는 전부 해소된다** — deep/tint 1.76~2.11 → **8.53~9.20**, 리스크 2.72 → **7.46**, 경계 1.28~1.32 → **3.02**. 어두운 면 위에서는 밝은 파스텔이 유리하고 다크 값은 Q 동결 대상이 아니라 기준을 넘도록 고를 수 있었기 때문이다. 따라서 **§9 는 라이트 전용 표가 된다**. `green` **그라데이션 테두리 3종**(리스크 배너·펼친 회차 카드·위기 아코디언)을 `/kit` 에 상설로 두고 두 테마 모두 확인했다 — 배경 2겹으로 만들어져 다크에서 가장 깨지기 쉬운 셋인데 킷에 자리가 없었다. `yellow` 폼이 긴 화면(인테이크 위저드·상담 기록 작성)의 다크 렌더는 아직 안 봤다. 상세 ADR-0026 |
