## 2. 지금 개발 착수 가능한 게이트 (자문 회신 불요)

자문이 뒤집을 수 있는 부분은 "설정값"으로 빼서, 구조는 지금 만들고 숫자·문구만 나중에 바꾼다.

### G1. ① 하드 게이트 + 긴급 등록 예외

- 등록 화면(`/participants/new`): ① 체크 필수화. 미체크 시 제출 차단 + "긴급 등록" 전환 버튼
- 긴급 등록: 사유 텍스트 필수 입력, `support_cases`에 긴급 플래그·보완 기한(기본 14일, **설정값** — 자문 질문 8로 확정), 만료 전 담당 실무자 알림
- API: `createSupportCase`에 ① 검증 추가(긴급 플래그 없으면 `consent_privacy` 필수)
- **기존 당사자의 추가 참여 사업 생성 흐름에도 동일 적용**: D44에 따라 두 번째 사업은 동의 3종이 미체크로 시작하므로, 해당 UI에도 ① 필수 체크·긴급 등록 버튼을 동일하게 배치(서버 검증만으로 막으면 화면에서 원인 없는 실패로 보임)
- 감사: 긴급 등록 생성·보완·만료 전건 `record_consent` 계열로 기록(D14)
- 테스트로 고정: ① 없음 + 긴급 아님 → 거부 / 긴급 → 허용 + 기한 생성
- 완료 기준: 기존 데이터 중 ① 미기록 케이스 목록화(마이그레이션 대상 아님, 보완 대상 리포트만)

### G2. 보존 상한 5년

- `support_cases`에 파기 예정일 계산 로직: `closed_at + 5년`(자문 반영용 **전역 설정값** — 기관별 변동은 허용하지 않음. 허용하려면 문안 3절을 "기관 규정에 따르되 최장 5년"식으로 먼저 재기술해야 함)
- 아카이브 전환(기존 D32 cron)에 더해, 상한 도래 케이스를 "파기 검토 큐"로 올리는 배치 추가 — 자동 삭제가 아니라 기관 관리자 확인 후 파기(기존 단건 파기 경로 재사용)
- 다른 법령 보존·법적 보류(litigation hold) 예외 플래그 1개
- 완료 기준: 상한 도래 → 큐 적재 → 관리자 파기 → pii_vault 삭제 + 가명 기록 보존이 테스트로 고정

### G3. 민감정보 마스킹 확대

- Mac Mini 2차 마스킹(NER)에 질병명·진단명 카테고리 추가: 사전(한국 질병명·정신건강 용어) + NER 병행, 치환 토큰은 `[질환]` 계열
- 원칙: 구체 병명만 치환, 상담 맥락 문장은 보존(브리핑 품질 유지)
- 마스킹 로그(무엇을 몇 건 치환했는지 집계만, 원문 저장 금지)로 검증 가능하게
- 완료 기준: 병명 포함 테스트 문장 셋에서 치환율 측정 + 문안 v0.3의 "구체적인 질병명 등" 문구는 이 게이트 배포 후에만 사용(문안 ⟦구현 연동⟧ 주석과 연동)

### G4. 문안 v0.3 화면 반영

- 동의가 나타나는 4곳(등록·당사자 정보·인테이크 읽기 전용·PR #5 자기 가입 폼)의 아코디언 문안을 v0.3으로 교체
- 단, v0.3도 DRAFT — 화면에는 "법률 검토 전 초안" 배지 유지, G3 배포 전에는 5절의 질병명 문구 제외한 변형 사용
- 완료 기준: 4곳 문안 단일 소스(하드코딩 4벌 금지 — 상수/마크다운 1곳에서 읽기) + **표시본 빌드**: ⟦법률 검토⟧·⟦구현 연동⟧ 내부 주석과 버전 이력·DRAFT 머리말을 제거한 화면용 본문을 생성하는 단계 포함(원본 md를 그대로 렌더하면 내부 주석이 당사자 화면에 노출됨)

### G5. 운영 준비 2건 (Q 액션, 코드 아님)

- 개인정보 처리방침 존재 여부 확인 → 없으면 작성 과제 등록(질문 3 고지 갈음 경로의 전제)

## 4. 권장 착수 순서

1. **G1**(① 게이트) — 법적 공백을 매일 줄이는 항목, 다른 게이트와 독립
2. **G3**(마스킹 확대) — R1+R4 결합 리스크를 기술적으로 낮추는 항목
3. **G2**(보존 상한) — 구조만 먼저, 숫자는 설정값
4. **G4**(문안 교체) — G3와 문구 연동 주의
5. G5는 병행(Q 액션)

각 게이트 완료 시 커밋 단위를 분리하고, 자문 회신이 오면 설정값(보완 기한·보존 상한·문구)만 조정한다.
