## 2. 지금 개발 착수 가능한 게이트 (자문 회신 불요)

자문이 뒤집을 수 있는 부분은 "설정값"으로 빼서, 구조는 지금 만들고 숫자·문구만 나중에 바꾼다.

### G1. ① 하드 게이트 + 긴급 등록 예외

- 등록 화면(`/participants/new`): ① 체크 필수화. 미체크 시 제출 차단 + "긴급 등록" 전환 버튼
- 긴급 등록: 사유 텍스트 필수 입력, `support_cases`에 긴급 플래그·보완 기한(기본 14일, **설정값** — 자문 질문 8로 확정), 만료 전 담당 실무자 알림
- API: `createSupportCase`에 ① 검증 추가(긴급 플래그 없으면 `consent_privacy` 필수)
- **기존 당사자의 추가 참여 사업 생성 흐름에도 동일 적용**: D44에 따라 두 번째 사업은 동의 3종이 미체크로 시작하므로, 해당 UI에도 ① 필수 체크·긴급 등록 버튼을 동일하게 배치(서버 검증만으로 막으면 화면에서 원인 없는 실패로 보임)
- 감사: 긴급 등록 생성·보완·만료 전건 `record_consent` 계열로 기록(D14)
- 테스트로 고정: ① 없음 + 긴급 아님 → 거부 / 긴급 → 허용 + 기한 생성
- 완료 기준: 기존 데이터 중 ① 미기록 케이스 목록화(마이그레이션 대상 아님, 보완 대상 리포트만)

### G2. 보존 상한 5년

- `support_cases`에 파기 예정일 계산 로직: `closed_at + 5년`(자문 반영용 **전역 설정값** — 기관별 변동은 허용하지 않음. 허용하려면 문안 3절을 "기관 규정에 따르되 최장 5년"식으로 먼저 재기술해야 함)
- 아카이브 전환(기존 D32 cron)에 더해, 상한 도래 케이스를 "파기 검토 큐"로 올리는 배치 추가 — 자동 삭제가 아니라 기관 관리자 확인 후 파기(기존 단건 파기 경로 재사용)
- 다른 법령 보존·법적 보류(litigation hold) 예외 플래그 1개
- 완료 기준: 상한 도래 → 큐 적재 → 관리자 파기 → pii_vault 삭제 + 가명 기록 보존이 테스트로 고정

### G3. 민감정보 마스킹 확대

- Mac Mini 2차 마스킹(NER)에 질병명·진단명 카테고리 추가: 사전(한국 질병명·정신건강 용어) + NER 병행, 치환 토큰은 `[질환]` 계열
- 원칙: 구체 병명만 치환, 상담 맥락 문장은 보존(브리핑 품질 유지)
- 마스킹 로그(무엇을 몇 건 치환했는지 집계만, 원문 저장 금지)로 검증 가능하게
- 완료 기준: 병명 포함 테스트 문장 셋에서 치환율 측정 + 문안 v0.3의 "구체적인 질병명 등" 문구는 이 게이트 배포 후에만 사용(문안 ⟦구현 연동⟧ 주석과 연동)

### G4. 문안 v0.3 화면 반영

- 동의가 나타나는 4곳(등록·당사자 정보·인테이크 읽기 전용·PR #5 자기 가입 폼)의 아코디언 문안을 v0.3으로 교체
- 단, v0.3도 DRAFT — 화면에는 "법률 검토 전 초안" 배지 유지, G3 배포 전에는 5절의 질병명 문구 제외한 변형 사용
- 완료 기준: 4곳 문안 단일 소스(하드코딩 4벌 금지 — 상수/마크다운 1곳에서 읽기) + **표시본 빌드**: ⟦법률 검토⟧·⟦구현 연동⟧ 내부 주석과 버전 이력·DRAFT 머리말을 제거한 화면용 본문을 생성하는 단계 포함(원본 md를 그대로 렌더하면 내부 주석이 당사자 화면에 노출됨)

### L2 개방 기록 (2026-07-29, Q 결정)

**결정**: L2를 Q 권한으로 해제하고 PR #5(당사자 초대·자기 가입)를 법률 회신 전에 머지한다.

**근거(Q)**: 서비스 출시 계획이 아직 없고 지금 단계의 목표는 기능 완성이다. 현재 검토된 수준으로 내부 운영에는 충분하다.

**이 결정이 성립하는 사실 조건** — 아래가 깨지면 재검토 대상이다:
- 배포된 것은 **화면 흐름 프로토타입**이다(D39): 실제 인증·이메일 발송이 없고 가입 데이터는 가상 시드 전용이다.
- **미리보기에 공개 표면이 없다**(ADR-0016 개정, PR #5 자체 커밋): 미리보기 환경에서 `/join` 공개 경로는 차단되고 팀에게는 실무자 화면(초대 링크 발급)만 보인다.
- 화면의 동의 문안은 여전히 **DRAFT 배지**를 달고 있다(L1 미해제).

**그대로 잠겨 있는 것**: L1(동의서 확정본)·L3(전자서명·당사자 직접 작성 구현)·L4(수령자 명시)는 회신 전까지 유효하다. **실제 당사자를 대상으로 한 운영 개시는 이 결정의 범위가 아니다** — 그때는 L1이 선행해야 한다.

### 법률 검토 트랙 종료 기록 (2026-07-30, Q 결정)

**결정**: 동의서 법률 검토(자문 의뢰)를 **MVP 범위에서 진행하지 않는다**. 현행 문안(v0.2/v0.3 초안)으로 MVP 구현에는 충분하다고 판단, 검토 의뢰 작업을 닫는다.

**이 결정의 효과**:
- 패킷 v1.1(`legal-review-packet-v1.md`)은 **전달하지 않고 보존**한다 — 향후 검토 재개 시 그대로 쓴다.
- G1~G4는 자문 회신을 기다리지 않고 **설정값 기본값(보완 기한 14일·보존 상한 5년·현행 문구)으로 구현·운영**한다. 설정값 분리는 유지 — 나중에 검토가 재개되면 숫자·문구만 바꾼다.
- **L1·L3·L4는 해제가 아니라 동결이다**: 동의서 확정본(DRAFT 배지 제거), 전자서명·당사자 직접 작성, 5절 수령자 명시는 여는 조건이 사라진 것이 아니라 **재개 조건이 바뀐 것** — 실제 당사자 대상 운영 개시 전에 법률 검토를 재개해야 열린다(L2 개방 기록의 "운영 개시는 L1 선행" 원칙 유지).
- 화면의 **DRAFT 배지는 유지**한다(문안이 확정본이 된 것이 아니다).

**성립 조건**(L2 개방 기록과 동일): 서비스 출시 계획 없음, 화면 흐름 프로토타입 단계, 가상 시드 전용. 실제 당사자 운영을 시작하려는 시점에 이 기록이 재검토 트리거다.

## 4. 권장 착수 순서

1. **G1**(① 게이트) — 법적 공백을 매일 줄이는 항목, 다른 게이트와 독립
2. **G3**(마스킹 확대) — R1+R4 결합 리스크를 기술적으로 낮추는 항목
3. **G2**(보존 상한) — 구조만 먼저, 숫자는 설정값
4. **G4**(문안 교체) — G3와 문구 연동 주의
5. G5는 병행(Q 액션)

각 게이트 완료 시 커밋 단위를 분리하고, 자문 회신이 오면 설정값(보완 기한·보존 상한·문구)만 조정한다.

### 이 결정으로 남는 리스크 (알고 받아들인다)

- `red` **D32 아카이브 전환이 구현돼 있지 않다.** 확정 결정은 "보관 기간 경과 시 파기하지 말고 아카이브 전환"인데, 코드의 cron 은 여전히 **즉시 파기**한다(`archive` 라는 말이 gateway·API·마이그레이션에 0건). G2 의 법적 보류가 최악의 경우(법령상 보존 의무 건까지 지워지는 것)를 막지만 **그 코드는 아직 main 에 없다**(브랜치에만 있다). 실서비스 개시 전 필수 항목이다.
  - **이 cron 이 실제로 어디서 도는지는 확인하지 않았다** — Cloudflare 계정 미개설이라 배포되지 않았을 가능성이 크지만 검증된 사실이 아니다. 재개 시 첫 확인 항목.
- 화면의 **DRAFT 배지 유지**, **L1·L3·L4 동결 유지** — §3 그대로다. 실제 당사자 대상 운영 개시는 여전히 L1(문안 확정) 선행이다.
- 설정값 3종은 기본값으로 굳는다: 보완 기한 14일 · 보존 상한 5년 · 현행 문안. **설정값 분리는 유지**했으므로 재개 시 숫자·문구만 바꾼다.

### 재개 트리거와 첫 3가지

**트리거**: 실제 당사자를 대상으로 서비스를 열려고 하는 시점(§3 법률 검토 종료 기록과 같은 트리거).

재개하면 순서는 이렇게 된다.

1. **D32 아카이브 전환** — 위 `red` 항목. G2 브랜치(`262928c`)를 살릴지 다시 설계할지 먼저 판단한다.
2. **G2 완료 기준 테스트 + 머지** — 착수 함정: 금고(`participant_pii_vault`)의 UPDATE 가드가 엄격해 테스트에서 `t.db` 직접 UPDATE 로는 `purge_due` 를 넣을 수 없다. `closeSupportCase` 계열 경로로 픽스처를 만들어야 한다.
3. **G4 문안 반영** — G3 가 배포된 뒤에야 질병명 문구를 쓸 수 있다. 그리고 **등록 화면 폴더(`participants/new/`)를 UI 수정 레인 B 와 함께 지나므로 순서를 맞춰야 한다**(등록 화면을 두 번 뜯지 않게).

**성립 조건**: §3과 동일 — 서비스 출시 계획 없음, 화면 흐름 프로토타입 단계, 가상 시드 전용. 이 조건이 깨지는 순간 이 기록이 재개 트리거다.
