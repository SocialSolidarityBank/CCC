PROPOSED FRONTEND CONTRACT RULES FOR ALL MISSING OPERATIONS
These are design requirements, NOT new exported types or existing response wrappers.
- Treat permission, capability, saved configuration, in-progress operation and read failure as different dimensions. Example local view model: {permission:'allowed',capability:{available:false,reason:'unverified'},load:{state:'ready'},value:{sttMode:'off',sttEngine:null}}. The same user's read may instead be {load:{state:'failed',httpStatus:503}} without any replacement value. This model is NOT an extension to CapabilityManifest and must not be sent to its exact-key decoder (C:29-30,152 onward).
- Module permissions must be server-derived from active actor roles and relationships. The preview's all/admin/tech/lead/counselor/both values are dummy UI selectors, not production credentials. The production role identifier for 실무자 is worker, with counselor only in existing legacy directory/action-owner contracts.
- An unimplemented write has no successful response example. The row's proposed request/response fields only become callable after owner approval, durable implementation and Main-scheduled runtime verification.
- General form failures preserve nonsecret input. Secret fields are never echoed or placed in URL, logs, browser storage or retry persistence; clear on successful replacement. Do not turn 403/409/503/network failure into a success badge or normal disabled setting.
- Impactful prepare/check/approve/execute operations must bind the same immutable plan/config version. Example PROPOSED backup view: {planId:'plan-demo',approval:{state:'required'},execution:{state:'not_started'}}. TA cannot approve it; IA approval cannot mark execution completed. The real engine must supply durable observed result and safe failure. No operation ID or version is claimed implemented here.
- Program policy is an upper bound intersected with installed capability and consent, not a new local AI capability. Before saving installation STT/LLM changes, frontend needs affected-program count and re-confirmation impact; after save, re-confirmation remains pending. Client calculation is not server enforcement.
- Six consent domains (docs/adr/0040-community-cloud-policy.md:229-242): 개인정보 수집·이용, 민감정보 처리, 상담 녹음, 외부 STT 처리, 외부 LLM·국외 처리, 음성 원본 보유기간. Each consent event preserves domain/decision/provider/purpose/notice version/hash/effective time/recorder append-only. Institution notice editing must not mutate participant consent history. Local STT needs recording consent; Azure additionally external-STT consent. Existing two-boolean consent is not a six-domain implementation.
- Memory settings must be a separate content-free projection supplied by its owner, e.g. PROPOSED {enabled:false,processing:{state:'off',pendingCount:0},revision:'opaque'}. Do not project a case-memory response and hide its text in CSS. No case content may enter the settings response at all.

RISKY GAPS AND FOUNDATION CONTACT QUESTIONS
A. Identity/auth migration seam, high overlap
   HI:78-85 projects canonical Actor to legacy role; TA-only and role-pending have no business role and throw 403. Do NOT fix by projecting TA to admin: that would open PII, directory and AI operations. Canonical R:111 roles includes worker, not counselor. G:9366-9370 maps only IA/TA/practitioner; resolveDirectoryActorByPrincipal separately adds supervisor from team_supervisor_grants (G:9430-9439), while listMyRoles at G:9601-9622 does not. Thus supervisor role can be lost in /me. Also legacy users.role mutation need not mutate active role assignments. Main must ask auth owner for accepted canonical gateway transition and self/directory DTOs before accounts/security/TA diagnostics work.
B. AI policy split
   Frontend TA-only menu (admin-format.ts:35) and backend legacy-admin gate (G:3001) conflict with approved IA key/final start. Need exact ownership of secret write port, preparation probe and final activation; don't create a browser-to-env shim. Current activation resolves provider before its explicit gateway permission lookup (H:2977-2979), so failed readiness is not evidence a caller was authorized. Activation is separate SQL registration/activation with prior retirement logic; don't claim cross-step transactional behavior from this research.
C. Database/storage/install services
   R interfaces are deliberately narrow. There is no reason to add backup methods to Database or writable keys to CoreSecretStore solely for settings. Main must obtain existing owner plan/apply/doctor/backup/restore/update contracts, exact files and integration base. Relevant shared files likely include contracts/runtime.ts, database.ts, install-manifest.ts, http-api/identity.ts and capabilities.ts, gateway Env/access mapping and migration families. Based on local source plus lane contract, this is likely overlap, not verified work in another checkout.
D. Programs and consent
   The current branch has case program_type and organization display names, not institution-program admission enforcement. Current shared consent prose still contains old 30-day audio wording, and docs/manual/project-admission-check.md:28 still assigns AI key/start to TA. Main owns common docs and must reconcile those with six-domain/7-day/IA policy. Menu copy cannot enforce admission or repair consent history.
E. Clinical-memory seam
   No memory module here. Main must obtain the memory owner's institution settings/status DTO and permission decision after its integration. G's officialization hooks and H:1855-1867,1878-1884 plus /pipeline/jobs result handling are likely clinical-memory integration areas. Do not edit hooks, scheduler, queues, AI provider generation, case source projection or migrations for a settings-only toggle.
F. Export/audit are not trivial HTTP wrappers
   listAuditLog is unbounded, lacks canonical subject fields and may disclose opaque target IDs that include invite credentials; exportCase returns broad domain objects and requires practitioner assignment. Exposing these without minimization and paging would turn internal assumptions into public API risk. Both require dedicated contracts after auth/foundation handoff.
