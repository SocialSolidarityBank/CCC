## 실제 구현의 E2E 수용 기준

1. 사람 검색과 사업 변경 시 다른 사람의 사업·일정·입력값을 조용히 유지하지 않는다.
2. 권한 없는 case ID를 직접 전달하면 조회와 저장 모두 거부하고 그 사업 상세를 노출하지 않는다.
3. 미기록 일정 두 건 중 두 번째를 고르면 두 번째의 날짜·목표·질문만 전달되고, 저장도 그 일정만 연결한다.
4. 예약 없음이면 입력한 상담 일시로 기록만 만들고 기존 예약은 생성·완료·변경하지 않는다.
5. 기록지를 열기만 해서는 업무 데이터가 생기지 않는다. 기존 감사 기록은 유지한다.
6. 읽기 전용/종결 케이스의 선택이 기록·예약·종결 변경 권한을 주지 않는다.
7. 다른 일정 선택의 초안을 섞거나 버전 충돌 때 입력을 지우지 않는다.
8. 인테이크는 기존 전용 양식과 수정 흐름을 유지하며 기본 상담으로 변환하지 않는다.
9. 리포트의 모든 값과 처음/현재/진척은 올바른 원문 회차에 연결되고, 근거 없는 섹션은 생략한다.
10. 월간 달력의 이동·오늘·이벤트 진입이 현재 사업과 날짜 범위를 유지한다.

위 항목은 실제 API·저장 경계의 구현 완료 조건이다. 시안 브라우저 동작 확인과 실제 백엔드 E2E 통과를 같은 결과로 취급하지 않는다.

여백을 강제하는 방식은 다음 세 가지를 제안한다. 이번에는 시안 내부에만 적용했고 운영 규칙은 변경하지 않았다.

1. `ccc-preview`는 앱(`apps/web`)을 배포하고, 이 시안은 `artifacts/2026-09-09-workflow-prototypes/`의 정적 HTML이라 앱 라우트에 없다. 지금 배포해도 시안은 뜨지 않는다.
2. 이 작업 폴더는 커밋이 없고 `origin/main`보다 두 커밋 뒤다(HEAD `feca860`, main `17ca585`). 수동 배포는 프리뷰를 main보다 옛 코드로 되돌린다.

대신 로컬 주소로 본다. 서버는 이 프로젝트에 붙은 상시 프로세스 `ccc-workflow-mockups`이고, 자리는 `http://127.0.0.1:3106`이다.

| 화면 | 주소 |
|---|---|
| 당사자 페이지 | `http://127.0.0.1:3106/participant.html` |
| 전체 상담 리포트 | `http://127.0.0.1:3106/participant.html?tab=report` |
| 당사자 관리 | `http://127.0.0.1:3106/participants.html` |
| 상담 기록하기 | `http://127.0.0.1:3106/record-entry.html?example=filled` |
| 일정 등록하기 | `http://127.0.0.1:3106/schedule-new.html` |
| 일정 보기 | `http://127.0.0.1:3106/schedule.html` |

서버가 꺼졌으면 이 폴더에서 다시 띄운다.

```sh
python3 -m http.server 3106 --bind 127.0.0.1 --directory artifacts/2026-09-09-workflow-prototypes
```

시안을 고친 뒤에는 생성기를 다시 돌린다.

```sh
NODE_PATH="$PWD/apps/web/node_modules" bun artifacts/2026-09-09-workflow-prototypes/bundle.mjs
NODE_PATH="$PWD/apps/web/node_modules" bun artifacts/2026-09-09-workflow-prototypes/generate.mjs
```

앱 소스에서 바뀐 것은 공용 아이콘 `record`(펜) 한 종뿐이고 운영 화면은 아직 쓰지 않는다. 프리뷰와 운영에 올라간 것은 없다.
