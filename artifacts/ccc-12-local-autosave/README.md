# CCC-12 로컬 자동 저장·복원 — 렌더 증거

완료 기준 1번("작성 중 브라우저를 강제 종료 후 다시 열면 이어쓰기 배너가 뜨고 내용이 복원된다")은
단위 테스트가 임시본을 심어 재현하므로 **실제 새로고침 경로를 덮지 못한다.** 그래서 로컬 스택에
실제 브라우저를 붙여 한 번 더 확인했다. 2026-07-26.

| 파일 | 무엇 |
| --- | --- |
| `restore-banner.png` | 메모를 쓰고 새로고침한 직후. "작성하던 기록이 있습니다" 배너 + 이어쓰기/새로 시작 |
| `resumed.png` | 이어쓰기를 누른 뒤. 본문과 파생 상태(필수 채움 카운트, 6영역 위기 아코디언)가 함께 복원됨 |

## 확인한 것 12건 (전부 통과)

- 자동 저장 상태가 상시 표시된다(입력 전 `자동 저장 대기` → 입력 후 `자동 저장됨 HH:mm`)
- 메모 도움말이 임시 보관 사실을 밝힌다(문구와 동작이 어긋나지 않는다)
- 임시본이 참여 사업당 1건만 생긴다(`ccc:draft:v1:record:<caseId>`)
- **새로고침 후 배너가 뜨고, 고르기 전에는 본문을 덮어쓰지 않는다**
- 이어쓰기를 누르면 본문 + 파생 상태가 함께 돌아온다
- '새로 시작'을 누르면 임시본이 지워지고 배너가 사라진다

## 재현 절차

`docs/ops.md` "로컬 프리뷰"대로 D1 마이그레이션·프리로드·시드를 넣고 API·웹을 띄운 뒤,
기록 작성 화면에서 수기 메모를 입력하고 새로고침한다.

`yellow` 그 절차의 1단계가 읽는 `scripts/seed/out/local-preload.sql` 은 **시드 생성이 만들어
주지 않는다**(문서에 이미 적혀 있는 결함). `scripts/seed/preload-data.ts` 의
`preloadStatements()` 등가 SQL 로 직접 만들어 넣어야 다음 단계가 통과한다.

또 하나 — 시드 생성 명령은 **레포 루트에서** 돌려야 한다. `apps/api` 에서 돌리면 vitest 가
`include: scripts/seed/generate.ts` 를 못 찾아 "No test files found" 로 끝난다.
