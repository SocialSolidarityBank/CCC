## 1. Azure 전사를 켜기 위한 설치 서명 (가장 중요)

전사는 Azure 한 경로만 씁니다. 지금 코드는 다 있고, **설치 때 서명과 등록이 없어서 닫혀 있습니다.**

할 일은 설치 도구를 돌릴 때 두 값을 넣는 것입니다.

- 승인 엔진 목록에 `azure-speech-koreacentral` 추가
- STT 모드를 `azure`로 서명

이 두 개가 없으면 서버가 전사 요청을 거부합니다. 화면에서 켜는 스위치가 아니라 **설치 서명에 들어가는 값**입니다.
설치를 돌리실 때 저에게 알려 주시면 필요한 입력 형식을 그 자리에서 정리해 드립니다.

참고 문서
- STT 조건: `docs/specs/S13-stt-qualification-v2.md`
- 설치와 릴리스: `docs/specs/S12-install-release.md`

## 2. 처리 장비 한 대 지정

AI를 켜면 기관 PC 한 대가 반드시 필요합니다. 그 PC가 가림 처리와 전사를 맡습니다.

확인해 주실 것 세 가지
- 어느 PC인지 (기관 소유, 상담 자료를 다루는 장비)
- 상담 시간대에 켜져 있는지
- 그 PC에 Agent를 붙일 때 발급되는 연결 토큰을 Q가 보관할지

이 PC가 없으면 전사와 AI 요약이 아예 돌지 않습니다.

## 3. 외부 전사 동의 확인 (기관 판단)

전사를 하려면 **마스킹 전 원음이 Azure로 나갑니다.** 그래서 세 가지가 필요합니다.

- 당사자 동의서에 외부 전사가 포함돼 있는지
- 기관이 Azure를 쓰기로 정했는지
- 전송 뒤 원음 삭제 증거를 남기는 절차를 기관이 받아들이는지

이건 기술이 아니라 기관 판단입니다. **9월 17일까지 안 되면 전사를 끄고 수기 기록으로 출고하고 실사용일을 조정하는 것이 제 권고입니다.**

참고 문서
- 동의 6영역: `docs/specs/S7-consent-six-domains.md`
- 원음 생애주기: `docs/specs/S8-audio-lifecycle-store.md`

알려 주실 것

관리자는 기관 전체를 조회하고 CSV로 반출할 수 있지만, **기록 작성과 수정과 AI 승인은 자기 담당 사례만** 됩니다. 관리자도 담당으로 배정될 수 있습니다.

## 이미 끝난 것 (Q가 안 해도 됩니다)

- Azure 음성 키: Infisical RELAYER 프로젝트 `prod` 경로 `/` 에 `AZURE_SPEECH_KEY` 로 이미 있고, Azure 서울 리소스의 KEY 1과 값이 같습니다. 새로 넣을 것 없습니다.
- 역할 권한: 관리자 기관 전체 조회와 반출 허용, 작성과 수정과 AI 승인은 담당 사례만, 팀 감독 권한은 API까지 차단. 기존 계정 자동 승격 없음.
- CSV 반출: 서버와 화면 모두 연결했고 실제로 돌려 확인했습니다. 선택한 사례의 모든 탭과 전체 회차 244행, 한글과 줄바꿈과 따옴표 보존, 다른 사업 자료 섞임 없음, 권한 없는 요청 거부와 다운로드 감사 기록.
- 제외 기능: 화면에서 안 보이게 처리 완료. 서버와 백그라운드 차단은 지금 작업 중입니다.
