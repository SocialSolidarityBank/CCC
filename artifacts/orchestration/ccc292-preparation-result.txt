Ordinary HTTP parser currently uses ValidationError/400 invalid_request for malformed bodies; freeze the actual mapping consistently rather than claiming all malformed input already yields a S5 422.
- Wrong token/attempt or invalidated source/map generation: 409 stale_claim; expired current lease: 409 lease_expired. No registry update, snapshot, new draft or outbound call. A cancelled job retains its existing consent_not_effective terminal meaning.
- Same registration retry: exact same logical registration/assigned numbers, no duplicate allocation or TTL extension. Same dictionary retry under a live tuple: identical logical dictionary and bytes; changed inputs/map under that old identity refuse dictionary_already_consumed, not a silently different response.
- Same name without adequate identity evidence: no merge and no inferred stable identity. Emit generic masked entity; recognized distinct people/institutions remain distinct within the case.
- Explicit full event/deadline date with known counseling date: deterministic relative representation. Leap/year boundary and time-zone date are covered. DOB follows its existing protected treatment; incomplete/ambiguous date is generalized/masked, never guessed. Relative input remains relative. Case date edits invalidate the binding even when other text is unchanged.
- NER health/receipt absent, expired or invalid: local_ner_unavailable and existing reprocessable S5 lifecycle; no synthetic passing receipt in production. Pipeline pair not allowed: masking_pipeline_version_mismatch. Missing mandatory material/provenance: masking_snapshot_missing; unsupported packet: explicit schema/version refusal, no fallback.
- Registered name/alias/PII residual: registered_pii_detected; independent residual candidate: unmasked_identifier_detected. Changed text/hash/evidence/Unicode offset: evidence_hash_mismatch according to frozen contract. Validation is detection-only; rejected result is not repaired and accepted.
- Source edit/date edit/goal closure/intake revision/PII correction/map update while processing: invalidate only affected current dependencies and claims under the case fence. Old success is not new-revision success. Fresh work uses the current source; failed enqueue must not leave stale material eligible.
- Valid same-payload result replay: no second snapshot/official result/provider effect. A hash assertion cannot bypass original actor/attempt/content binding. Different payload: result_conflict. After purge/withdrawal/supersession, no replay can resume recording downstream or create a new authorization.
- Withdrawal wins before result/egress CAS: cancel required work and revoke authorization atomically, reject result, external call count zero. Egress CAS wins first: record that already-authorized call honestly; later withdrawal prevents new calls and new invalid result acceptance. Do not promise cancellation of a network request already started.
- AI-off or memory setting off: no new external processing; manual canonical records/permissions remain intact. Memory remains excluded from product inputs, and missing work must not be presented as successful zero results.
- Case close/archive: stop new eligible map/Agent use; archive is reversible protected storage, not deletion. Other active cases prevent beneficiary-wide archival/purge under current retention rules.
- Approved scoped purge: same authorization/fence revokes claims/authorizations and records content-free scope/lineage tombstones; remove attributable map original/aliases, source/history, snapshots/evidence, quotes/drafts/memory/links/indexes and temporary material. No completion while attributable content or failed deletion remains. Shared/foreign-case material without proven attribution is not deleted. Bypass-free ordinary reads cannot reach tombstoned content during cleanup.
- Re-register/new case after purge: new case namespace; old tombstone survives archive-row cleanup. New legitimate data is distinguished by generation/lineage, not deleted because a beneficiary identifier was previously purged. No old claim/number identity is resurrected.
- Restore retained, never-purged data: validate old backup before modification, restore to hidden namespace, target-key re-encrypt, apply independent current purge history, verify retained references, recheck purge head at pointer/complete CAS, then reopen with fresh claims/qualification. An old unqualified mask is history, not automatically eligible.
- Restore missing/tampered/wrong-org/stale purge history or ambiguous remap: RECOVERY_BLOCKED, no visible pointer or complete marker. Corrupt backup still fails its original integrity code even if affected rows would later be purged. Crash before cutover remains hidden/recoverable; crash after verified pointer+complete does not roll back subsequent legitimate writes. New purge between verification and cutover must be incorporated or block reopen.
