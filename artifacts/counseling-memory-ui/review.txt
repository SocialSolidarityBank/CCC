확실한 문제

1. 정정 대상만 바뀌고 다른 기억의 정정 내용과 이유가 남는다.
자리: prototype.tsx:91-93, 197-201
심각도: 중간
실물 재현: 기본 대상 '자동이체 날짜 변경'을 '고정 지출 정리'로 바꾸면 본문은 '자동이체 날짜는 아직 바꾸지 않았습니다...'이고 이유도 3회차 변경 계획인 채 그대로 남는다. 제출 처리도 대상과 내용의 대응을 드러내지 않고 확인했다는 결과만 낸다.
문제: 사용자 입력을 보존하는 것과 다른 대상에 같은 입력을 붙이는 것은 다르다. 현재 시안은 엉뚱한 기억을 정정하는 상호작용을 정상 흐름처럼 보여 준다. 실제 저장이나 운영 데이터 손실은 없다.
근거: 검수 기준 6 '정보의 자리'; brief:18 가상 입력/결과 계약. 기존 memory-correction.tsx:37-40은 대상 변경 시 해당 항목의 본문으로 전환한다.
제안: 대상별 초안을 유지하거나 대상 변경 시 미확인 입력 처리와 새 대상의 현재 내용을 명시한다.
등급: 확실

2. '기록 없음' 상태에 구체적인 마지막 반영 시각이 표시된다.
자리: prototype.tsx:177-179
심각도: 중간
실물 재현: 기억 상세를 empty로 전환하면 '아직 기억이 없습니다'와 '마지막 반영 2026-09-07 17:10'이 동시에 표시된다.
문제: 최초 기억이 없는 상태와 이미 기억을 생성했던 상태가 섞인다. 상태 비교 시안의 의미가 불명확해진다.
근거: 검수 기준 6 '정보의 자리'; DESIGN-RULES '디자인 미리보기의 기본 상태'의 양립 불가 조건은 별도 상태로 표시한다는 계약.
제안: 실제 마지막 반영이 있는 상태에서만 해당 시각을 표시한다.
등급: 확실

3. 회차별 정리의 상담 유형과 회차를 일반 항목 제목으로 표시한다.
자리: prototype.tsx:168-169
심각도: 낮음
실물: briefing A/B/C, 1280/390 전부에서 '기본 상담 3회차', '기본 상담 2회차'가 굵은 일반 제목이다. HERO 밖의 분류/회차 표시인데 배지가 아니다.
근거: DESIGN-RULES §1 '상태 낱말은 배지로 올린다'의 '3회차' 예시와 §4 상담 유형 색 의미. HERO 라벨/값 예외는 이 카드에 적용되지 않는다.
제안: 회차 분류와 상담 유형은 기존 배지 어휘로 내고 실제 상담 핵심 문장은 본문으로 유지한다.
등급: 확실

판단이 필요한 사항

4. 기억 관찰은 보이지만 정정 대상에서 선택할 수 없다.
자리: prototype.tsx:182, 189, 193, 199
현재 세 안 모두 기억 관찰을 보여 주지만 정정 선택지는 evidence의 명시된 내용 3개뿐이다. 기존 MemoryCorrection은 전달된 items 전체를 대상으로 한다. 관찰을 바로잡는 흐름도 비교하려는 시안인지, 이번 시안에서 명시된 내용만 정정하는 것인지 결정이 필요하다. 항목별 수정 버튼을 추가하라는 뜻은 아니다.
근거: 검수 기준 6; brief:15 '더 보기 > 기억 정정' 계약.
제안: 관찰도 선택 가능하게 하거나 시안 정정 대상의 제한을 명시한다.
등급: 판단 필요

5. AI 질문이 아직 확인하지 않은 변경 완료를 전제한다.
자리: prototype.tsx:60-61
제목은 '변경 여부 확인', 이유는 '바꾸기로 한 계획만 기록'인데 질문은 '날짜를 바꾸면서 어려웠던 점이 있었나요?'다. 완료 여부를 묻기 전에 실행을 전제로 읽힐 수 있다. 진단이나 지원 판단 위반은 아니며 질문 문안의 의미 검토 사항이다.
근거: 검수 기준 6; 근거 원문 prototype.tsx:32의 '변경 완료 여부는 아직 확인하지 않았다'.
제안: 변경 여부를 먼저 묻고 어려움은 그다음 질문으로 둔다.
등급: 판단 필요

수정된 계획 위험의 확인
- B에서 실무자 질문이 맥락 요약보다 먼저 보인다. 초기 우선순위 지적은 해소됐다.
- B의 근거는 각 항목에 묶여 있으며 모바일에서도 내용 다음 해당 근거 순서다.
- A/C 형제 구획의 구분선과 A/B 항목 사이 구분선을 실제 스크린샷에서 확인했다.
- C 기본 화면에 '맥락 3개 펼쳐 보기'가 있다.
- HERO 정보는 배지 없이 라벨/값으로 표시된다.
- live ready → updating에서 정정 대상과 본문이 유지된다.
- live unavailable에서 정정 폼, 인용, 과거 기억이 사라진다. 운영 자료 누출로 판정한 사항은 없다.
- 정정 닫기를 실행하면 '더 보기'로 포커스가 돌아온다.
- 기관 설정에 과거 공식 기록 처리와 비용, 끈 뒤 기존 기억 보존, AI 연결과 동의를 대신하지 않는 설명이 있다. 범위도 기관 전체다.
- page.tsx:7의 production notFound와 이 세 파일에 업무 API 호출이 없는 것을 코드에서 확인했다. production 서버는 실행하지 않았다.

사용자 선택이며 결함이 아닌 것
- A의 통합 밀도, B의 독립 카드와 펼친 근거, C의 압축과 추가 펼침은 이번에 비교하려는 설계 축이다.
- B가 더 길고 C가 클릭 한 번을 더 요구한다는 이유만으로 규칙 위반으로 세지 않았다.
- B의 가상 인용을 기본 펼침으로 보여 주는 것은 요청된 비교 구조다. 운영 근거 표시 규칙을 변경 승인한 것으로 해석하지 않는다.

캡처 주의
제공된 전체 페이지 스크린샷은 고정 비교 바를 촬영 시작 뷰포트의 하단 위치에 합성하므로 mobile briefing의 전체 목표, mobile memory의 현재 기억 헤더, desktop memory의 안내 일부를 가린다. 실제 브라우저에서는 스크롤해서 해당 내용을 읽을 수 있었다. 이를 영구적인 내용 접근 불가 결함으로 세지 않았다. 사용자에게 보낼 정적 비교 이미지에는 비교 바가 핵심 문구를 덮지 않는 별도 캡처가 필요하다.

확실 3건, 판단 필요 2건.
