# 기능 레인 순서

순서는 **프런트엔드 먼저, 디자인 다음**이다(2026-09-09 Q). 화면 작업 자체의 순서는
`design-lane` 스킬이 갖고, 이 파일은 **레인 사이의 순서**만 갖는다.

**여기에 소유 목록과 디자인 규칙은 없다.** 소유 정본은 `CLAUDE.md` 의 레인 예외 절들이고
규칙 정본은 `DESIGN-RULES.md` 다. 사본을 두면 둘 중 하나가 뒤처진다(ADR-0033 유지 규약).

## 왜 이 순서인가

- 화면 작업은 관문이 무겁다(값·조합·실측·격리 검수). 계약이 흔들린 상태로 들어가면 그 비용을
  두 번 낸다.
- design 레인은 워크트리 하나라 한 번에 한 브랜치만 쓴다. 그 레인을 계약 탐색에 쓰면 다른
  화면 작업이 멈춘다.
- 계약 확인은 대부분 읽기다. 읽기는 어느 레인에서 해도 상대 레인을 막지 않는다.

## 워크트리 지도

| 워크트리 | 성격 | 소유를 정하는 곳 |
| --- | --- | --- |
| `.worktrees/frontend` | 상설 프런트엔드 레인 | `CLAUDE.md` "업무 클라이언트 프런트엔드 레인 예외" |
| `.worktrees/design-adjustments` | 상설 화면 레인 | `~/.omp/agent/AGENTS.md` "CCC design ownership lock" |
| `.worktrees/stt-client` | STT 시험 화면 | `CLAUDE.md` "STT 클라이언트 독립 레인 예외" |
| 그 밖 | 티켓별 임시 레인 | 티켓 |

워크트리를 새로 파거나 브랜치를 갈 때는 `branch-worktree-gate` 순서를 먼저 돈다. 상설 레인은
관계없는 일을 얹는 자리가 아니다.

## 1. 프런트엔드 레인에서 끝내는 것

- **API 계약 실측.** 라우터와 gateway 를 읽어 경로, 메서드, 헤더, 상한, 거부 코드와 HTTP
  상태를 확인한다. 스펙 문서만 읽고 넘기지 않는다. 문서와 코드가 다르면 코드가 사실이다.
- **거부 코드가 화면까지 닿는지 확인.** 서버가 코드를 주더라도 `apps/web/app/lib/api.ts` 의
  `ApiErrorCode` 목록에 없으면 상태 코드로 뭉개진다. 이 목록은 프런트엔드 레인 소유다.
- **읽기 함수와 자기 소유 화면.** 소유 경로는 위 지도가 가리키는 절이 정한다.
- **잠금 확인.** 이 기능이 지금 켜질 수 있는지 본다(설치 기본값, 승인 게이트, 동의, Agent
  상태). 켜질 수 없으면 **화면을 짓기 전에 그 사실을 먼저 보고한다.** 켤 수 없는 버튼을
  만드는 것은 완성이 아니다.

## 2. 인계 패킷, 착수 직전까지

패킷은 `docs/superpowers/plans/<날짜>-<주제>-design-handoff.md` 에 둔다. 여덟 칸을 채운다.

1. 목표 한 줄
2. 붙을 자리(파일 경로와 화면 URL, 후보가 둘이면 제약과 함께 둘 다)
3. API 계약(경로, 헤더, 상한, 응답)
4. 거부와 상태 전체(코드, HTTP 상태, 화면이 그려야 하는 경우 목록)
5. 문구 초안
6. 적용되는 `DESIGN-RULES.md` 절 번호
7. 수용 기준(무엇을 렌더해 보이면 끝인가)
8. 손대지 말 것과 선행 조건, 각 선행 조건의 소유자

**여덟 칸을 못 채우면 인계하지 않는다.** 빈 칸이 곧 프런트엔드 레인에 남은 일이다.

## 3. design 레인이 받는다

패킷은 `design-lane` 1단계 계획의 입력이다. 배치, 위계, 색, 문안, 검수, 최종 수정은 전부
그 레인에서 끝난다. 프런트엔드 레인이 배치표를 대신 그리지 않는다.

## 4. 되돌려 보내는 기준

| 검수·구현에서 나온 문제 | 어디서 고치나 |
| --- | --- |
| 응답에 값이 없다, 거부 이유를 구분할 수 없다, 상태가 계약에 없다 | 프런트엔드 레인 |
| 배치, 위계, 색, 문안, 여백, 정렬 | design 레인 |
| 규칙 자체를 바꿔야 한다 | 티켓. `DESIGN.md` 와 `DESIGN-RULES.md` 를 같은 커밋에서 고친다 |

## 레인 규칙

- 각 레인은 자기 워크트리에서만 파일과 git 작업을 한다. 상대 레인의 checkout, reset, clean,
  stash, 미커밋 파일 정리는 금지다.
- 소유 밖 파일이 필요해지면 **먼저** `CLAUDE.md` 에 예외 조항을 올린다. 구두 승인만으로는
  성립하지 않는다(선례: PR #316, #317).
- 인계는 메시지가 아니라 파일이다. 상대 레인 워크트리에 파일을 쓰지 않고, 레포에 커밋된
  패킷 경로를 넘긴다.
