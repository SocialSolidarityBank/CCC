## 1. 상담기록지 (확정: 2026-09-12)

### 1-1. 배경

- 글로벌 기록 형식(SOAP, DAP, BIRP, GIRP)의 공통 뼈대는 사실 → 판단 → 계획이고, 릴레이어 카드 4종(사실, 확인할 것, 약속한 일, 판단·평가)이 이 뼈대와 1:1로 맞는다. 기록지 구획을 카드 4종에 맞춘다.
- 현재 화면은 좌측 레일 3개 + 본문 11구획(필수 3). 제안은 레일 없음 + 7구획(꼭 손대는 칸 6개).
- 시트 짧은 안([0]~[5])을 바탕으로 하되, 아래 4가지를 고쳤다. (a) [4] 바뀐 숫자(대출 특화) → 달라진 것(영역 선택 + 한 줄), (b) [0]에 지난 [3] 물어볼 것도 올림, (c) `* (본인)`, `? ` 기호 문법 → 한 줄 입력 + 버튼, (d) 세부 목표 닫는 자리([6]) 추가.

### 1-3. 화면 순서와 작성 시점

- 본문은 오늘 → 다음 순서. 이전 기록([0])은 데스크톱 좌측 보조 패널, 모바일은 메모 위 접힌 띠. 메모칸을 아래로 밀어내지 않는다.
- 현재 코드의 `record-side` 레일은 없애지 않고 [0] 용도로 바꾼다.
- 상담 중: [1]만 펼침. 나머지 접힘.
- 상담 끝난 뒤: [0] 결과 버튼, [2], [3], [5] 긴급도 펼침.
- 해당될 때만: [4], [5] 의견, [6]. "추가" 버튼으로 펼침.
- [1] 저장 후 AI 정리은 [2]~[5] 아래에 "제안" 표시로 붙고, 승인한 것만 카드가 된다. 사람이 직접 적은 [2]~[5]는 즉시 공식 기록.

### 1-4. 영역 목록 통일 (결정)

- 현재 코드 `apps/web/app/lib/life-area-labels.ts`의 6영역(경제·생계, 주거, 일·고용·학업, 건강, 심리·정서, 가족·관계·돌봄)과 시트 인테이크 2부의 9영역(경제·재정, 일·고용, 주거, 신체건강, 심리·정서, 가족·관계, 돌봄·양육, 법률·행정, 기타)이 두 벌이다.
- 결정: 시트 9영역으로 통일한다. 인테이크, 기록지 [4], 전체 리포트 상황변화가 같은 목록을 쓴다.
- 영향 범위: `LifeAreaKey`, `lifeAreaOrder`, 지난 회차 스냅샷(`latestLifeAreaSnapshot`), 15초 페이지의 영역 표시, 기존 저장 데이터의 키 대응표(economy→경제·재정, employment→일·고용, housing→주거, health→신체건강, mental_health→심리·정서, family→가족·관계 + 돌봄·양육 분리는 수동 확인).
- 영역별 상태값(괜찮음/긴장/위기/해당없음/답변거부)은 기록지에서 없앤다. [4]는 영역 + 한 줄만 받는다.

### 1-5. 없어지는 것

- 레일의 체크리스트와 바로가기. 이번 상담 목표와 미해결 액션 카드는 [0]으로 용도 변경. 필수 진척은 저장 버튼 옆으로.
- "30초 안에" 같은 시간 약속 문구. 대신 "상담 내용만 적어도 저장할 수 있습니다".
- 오늘 확인할 질문(저장 안 하는 체크) → [3]으로.
- 회차 템플릿 항목(준비 중) → 삭제.
- 위기·안전 확인 서술 → [5] 의견으로.
- 리스크 플래그 6종 체크박스 → [5] 긴급도 아래 접힌 체크로 이동(확정). 별도 구획 아님.
- 미해결 액션 처리 메모 → "못 함"일 때만 열리는 "계속한다/그만둔다(사유)" 한 줄로 대체 (확정).

### 1-8. ASTRA 피드백 검수 결과 (2026-09-12)

받아들인 것: 빈칸 = 미확인(변화 없음 아님), 과거 값에 마지막 확인 회차 표시 / 미해결 전체를 올림 / 결과를 진행 중과 확인 안 함으로 구분 / 못 함 ≠ 포기, 사유 별도 / 이전 기록은 보조 패널 / 확정 경고는 접지 않음, 무입력을 안정으로 기록하지 않음 / 지원욕구 ≠ 합의 목표 / 15초와 전량 표시는 양립 불가, 상단 압축 + 건수 + 전체 목록, 안전은 예외 / 30초 문구 삭제 / 화면과 JSON 분리 정의.

유지한 것: [4] 달라진 것은 추가 기록 아래 선택 항목으로 남김(AI 꺼진 기관의 리포트 재료, 인테이크 영역 값 갱신 경로). 영역 모듈 선택 2 + 상세 1 구조. 화면 이름은 ASTRA의 "답해야 하는 질문" 틀을 받되 "확인" 중복을 피해 아래로.

화면 이름 (제안, Q 확인): 첫 상담 기록하기 / 상담 기록하기 / 상담 전 톺아보기(구 15초 페이지) / 경과 리포트(구 전체 리포트) / 기록 열람.

정의서(`CCC_15초페이지_전체리포트_정의.md`)에서 함께 고칠 해석 규칙:
- 실천과제 "아무 언급이 없으면 진행중" → "마지막 확인 N회차, 이번 미확인".
- 상황변화 "처음 / 지금" → "처음 확인된 상태 / 마지막으로 확인된 상태" + 회차.
- 대목표: 전체 목표가 있으면 그것. 없으면 1순위 지원욕구를 보여 주되 "합의 목표 아님, 신청 시 욕구" 표시.
- 약속 카드는 결과가 나와도 지우지 않고 결과와 확인 회차를 연결한다. 사실 카드는 파생.
- 내용 불일치의 화면 표현은 "일치하지 않는 기록". 시간에 따른 변화를 오류처럼 보이지 않게.

## 2. 인테이크 (제안: 2026-09-12, Q 확인 대기)

### 2-1. 방향

- 문항을 줄이지 않고 구조를 세 층으로 나눠 해당하는 것만 보이게 한다. 현재 4부 55문항 전 항목 필수 한 화면 → 항상 보이는 칸 28개 + 영역 모듈(고른 영역만) + 사업 모듈(기관이 붙인 것만).
- "전 항목 필수, 무응답 허용" 원칙은 유지. 접혀서 안 보이는 모듈은 필수 계산에서 뺀다. (전 항목 필수 규칙의 적용 범위 변경이므로 ADR 한 줄 필요, ASTRA 지적)
- 대출 특화는 두 곳뿐: `인테이크_대출부채` 반복표, 4-3 주요 지원방향 선택지. 나머지는 범용.
- 코드 참조: `apps/web/app/participants/[beneficiaryId]/programs/[supportCaseId]/records/intake/intake-questions.ts` (424줄), `PRD/intake-questionnaire-v1.md`

## 3. 화면 이름 (확정 방향, 2026-09-12)

### 3-0. 이름 규칙 7가지

1. 화면 이름은 명사로 끝낸다. 동사형은 버튼에만 ("상담 등록" 화면, "등록하기" 버튼).
2. 한 화면은 한 질문에 답한다.
3. 같은 대상은 같은 머리말(당사자 ~, 상담 ~, 사례 ~, 실무자 ~, 기관 ~).
4. 사람은 "목록"을 붙인다(당사자 목록, 실무자 목록). 시간은 "일정", 내용은 "기록". 상세 "~정보", 생성 "~등록", 편집 "~수정".
5. 카드 이름(사실, 확인할 것, 약속한 일, 판단)과 겹치는 낱말은 화면 이름에 쓰지 않는다. "확인" 포함.
6. 용어는 병기(인테이크) → 표준 한글(사례, 종결, 위기도) → 쉬운 우리말(톺아보기) 순서.
7. 경로와 코드 식별자는 바꾸지 않는다. 화면 라벨, 메뉴, 가이드, 랜딩만.

UX 라이팅 규칙 (2026-09-12, 토스 가이드·GOV.UK·Material 공통점 기준. 인격: 차분하고 정확한 동료):
8. 버튼은 짧은 동사 명사형(저장, 등록, 초대, 승인, 반려, 재생성). "-하기"는 행동 시작에만(시작하기, 체험하기).
9. 문체: 화면 안내, 빈 화면, 오류는 해요체. 동의서와 법적 고지는 합니다체. (Q 확인: 현재 코드 안내문은 합니다체)
10. 결과 먼저, 이유 함께. 막힌 기능은 이유와 계속 가능한 행동을 같은 자리에(U07, U09).
11. 부정은 부정문으로. "확인 못 함"을 돌려 말하지 않는다.
12. 감정어, 느낌표 금지.

`apps/web`(Next.js)이 아니라 `apps/client`의 `src/business/navigation.ts`를 정본으로 삼는다. 사이드바 16개와 화면 제목은 그 파일에 있다.

### 3-2. 용어 원칙 (교과서·공공 매뉴얼 대조, 2026-09-12)

순서: 교과서에 병기 표기가 있으면 병기 → 표준 한글이 있으면 한글 → 둘 다 없으면 쉬운 우리말.

| 구분 | 낱말 | 처리 |
|---|---|---|
| 현장이 영어 그대로 씀 | 인테이크, 클라이언트, 슈퍼비전, 라포, 스크리닝 | 인테이크는 병기. 클라이언트 대신 당사자를 쓰는 이유(권리 주체)를 용어집에 명시. 슈퍼비전은 그대로 |
| 표준 한글이 있음 | 케이스→사례/참여 사업, 액션→할 일(문서는 실천과제), 모니터링→점검, 리퍼→의뢰 | 화면 라벨 교체. 코드 식별자 유지 |
| 개발 용어 | 플래그, 브리핑, 허브, 스냅샷, 배너, 워크인, STT, LLM | 3-1 표대로 |

확정 (2026-09-12):
1. 긴급도(안정/주의/위기) → **위기도**. 기록지 [5], 인테이크 4-3, 리포트 라벨 모두. 코드 `summary_urgency` 등 식별자 유지.
2. 전체 목표/세부 목표 → **장기목표/단기목표**. 위계(ADR-0032 D62)는 유지, 이름만. 이번 상담 목표는 그대로. ADR-0032에 한 줄 개정.

코드 식별자와 ADR 용어는 바꾸지 않는다. 화면 라벨, 가이드, 랜딩 문구만 바꾼다(G01, G08).

## 4. 내용 불일치 정의 (상담 전 톺아보기)

- 전사 대조(같은 회차, AI 정리이 전사에 근거하는지)는 AI 정리 검토 화면의 대조 3종(R2)이다. 글로벌 기준: Abridge Linked Evidence. 내용 불일치가 아니다. STT off 기관에서는 작동하지 않는다.
- 내용 불일치는 회차 간 비교이며, 글로벌 기준은 의료 pre-charting의 reconciliation(구조화 값 대조, care gaps)이다. 자유 글 모순 검출을 제품 기능으로 내세운 글로벌 서비스는 2026-09-12 조사에서 찾지 못함.

| 항목 | 정의 |
|---|---|
| 비교 대상 | 공식 기록의 사실 카드 + 구조화 값(인테이크 영역 값, 기록지 [4], 약속 결과, 숫자). 승인 전 AI 정리 제외 |

| AI 정리 검토 (`…/review`) | ① 당사자 카드 + 재료 상태(전사/메모/목표 있음·없음, "지난 N회차 요약 참고") ② 위험 신호 제안(근거, 맞음/틀림) ③ 핵심 한 줄, 요약(문장별 근거 인용) ④ 대조: 메모에서 누락된 것 / 녹음에서 누락된 것 / 다루지 않은 목표 ⑤ 다음까지 하기로 한 것 제안 → 할 일로 등록(담당·기한은 사람) ⑥ 다음에 물어볼 것 제안 ⑦ 승인 불가 조건 → 승인/반려/재생성 | 순서: 위험 → 내용 → 대조 → 후속 → 결정. 라벨: 대조 3종 → 풀어쓰기(6-C 확정), 액션으로 등록 → 할 일로 등록, 확인할 질문 → 다음에 물어볼 것, "지난 회차 요약 참고" 표시 신설(6-C 확정) |
| 사례 종결 (`…/close`) | ① 종결 사유, 종결일 ② 남은 할 일 처리(끝냄/그만둠 사유/이관) ③ 활성 단기목표 닫기(달성/중단) ④ 파기 예정일과 범위(동의 문안과 같은 말) | 케이스 종결 → 사례 종결. 파기 범위 문구 = 동의서(1차 점검 3-1) |

### 8-3. 실무자와 기관 (베타 클라이언트 기준)

`/admin/*` 페이지는 없다. `/settings?module=…` 모듈 8개와 독립 페이지 3개로 구성된다.

| 화면 | 경로 | 구획 | 바뀌는 것 |
|---|---|---|---|
| 내 정보 | `/settings` (`module=account`) | 내 계정, 배정 요청 수락 | 상담 기억은 여기가 아니라 기관 모듈. 앞선 제안 철회 |
| 기관 준비 | `/onboarding` | 기관 이름 → 첫 사업 → **사업 모듈 선택** → 실무자 초대 | 모듈 단계 추가 |
| 기관 정보 | `?module=institution-profile` | 기관 이름, 사업 표시 이름, 사업 목록, 사업별 모듈 켜기 | 사업 모듈 켜기, 선택지 관리(주요 지원방향 문구) 추가 |
| 사용자와 역할 | `?module=accounts` | 이름, 역할(겹칠 수 있음), 담당 당사자 수, 활성·비활성 | 이름 유지. "실무자 목록" 제안 철회 |
| 담당 배정 요청 | `?module=assignments` | 요청 수락(공동 담당 또는 이관) | 이관 안내 추가: "남은 할 일 N건, 물어볼 것 N건이 새 담당에게 넘어가요"(U12) |
| 실무자 초대 | `/staff-invites` | 초대 링크, 이메일 문안 복사 | 경로 확인만. `/admin/invite` 아님 |
| 연결 상태 | `?module=system` | 서버가 확인한 연결 상태. AI 회사, STT(녹취록 작성) 경로와 엔진, 사업별 상태와 막힌 이유 | AI 설정을 새로 만들지 않고 이 모듈에 넣음. 상태는 사업별(D87). "가린 자료만 미국 OpenAI로 가고 오남용 감시로 최대 30일 보관될 수 있어요"(P07), "Azure는 가리기 전 녹음 파일이 나가요"(P06) |
| 기관 상담 기억 | `?module=memory` | 기관 전체 설정, 처리 대기·조건 확인 필요·처리 실패·마지막 성공 | 이미 구현됨. "화면에는 나오지 않아요" 한 줄 추가. 그림자 모드(A09)는 별도 결정 |
| 감사 기록 | `?module=audit` | 누가 무엇을 열고 바꿨는지 | **신설 아님.** 위쪽에 이번 달 집계(담당 아닌 당사자 열람 N, 개인정보 복호화 N, 내보내기 N)와 "월간 점검 보고서 내려받기"만 추가(1차 점검 3-6) |
| 개인정보 보유기간 | `?module=retention-policy` | "이 값은 파기 시점이 아닙니다" | 사례 종결의 파기 안내와 같은 말을 쓰도록 맞춤 |
| 개인정보 보존 검토 | `?module=retention` | "파기는 서버 설정과 관리자 확인을 모두 요구합니다" | 사례 종결에서 이 화면으로 연결 |

### 8-5. 와이어프레임에서 추가로 정한 것 (2026-09-12)

1. 상담 등록: 사례를 고르는 순간 동의 상태를 보여 준다. AI 동의 없으면 "이 사례는 AI 정리이 안 만들어져요"(U09).
2. AI 정리 검토: 승인 불가 조건(화자 구분 체크, 전사 신뢰 불가 구간 수)은 승인 버튼 바로 위. 상단 안내 제거.
3. 사례 종결: 파기 범위 문구는 실제 파기 규칙(`0041_pii_retention_lifecycle.sql`)과 동의서가 맞춰진 뒤 확정. 그 전에는 화면에 범위를 적지 않는다(1차 점검 3-1).
4. 홈 할 일 띠: "맞음/틀림 미정 위험 신호"는 AI 켠 기관만. AI 꺼진 기관은 두 칸.
5. AI 설정: 상태는 사업별(D87 사업 도입 확인 단위). 막힌 이유와 푸는 곳을 같은 줄에(U07). "엔진별 상태" 제거.
6. AI 설정: AI 회사 아래 "가린 자료만 미국 OpenAI로 가고, 오남용 감시로 최대 30일 보관될 수 있어요" 표기(P07). Azure 선택 시 "가리기 전 원음이 나가요"(P06).
7. 설정 > 상담 기억: "화면에는 나오지 않아요" 명시. 그림자 모드(A09) 결정 전까지 켜기·끄기만.
