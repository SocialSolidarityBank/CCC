## 2. 다시 결정하지 않는 기준 (원문이 확정값으로 못 박은 것)

1. Community Cloud, Local Single, Local Office 세 모드는 최종 정식 구현 범위다. Cloud를 먼저 연결하는 순서가 나머지 제외를 뜻하지 않는다.
2. 수기 메모는 저장 즉시 공식 기록이다. AI 초안만 사람이 검토하고 승인한 뒤 공식 기록이 된다. 승인 전 초안은 브리핑, 통계, 보고서 재료가 아니다.
3. 동의는 여섯 영역이다(개인정보, 민감정보, 녹음, 외부 STT, 외부 LLM과 국외 처리, 원음 보유기간). 예전 동의를 자동으로 승격하지 않는다.
4. STT 선택지는 off, local, azure 셋이다. 세 모드 모두 설치 기본값은 off다. AI를 쓰려면 기관 PC의 Agent가 필요하다. AI가 꺼져도 수기 업무는 이어지지만, 사업 미확인이나 개인정보 근거 미충족까지 면제되지는 않는다.
5. OpenAI에는 검증된 마스킹 스냅샷만 보내고 store:false를 쓴다. 허용된 Azure STT에는 마스킹 전 원음이 나갈 수 있다. 공급자 자동 전환은 없다.
6. 원음은 다음 영업일 첫 Agent 처리 기회 뒤 즉시 삭제한다. 미처리 기한은 "첫 기회+24시간"과 "업로드+7일" 중 이른 시점이다. 7일은 기본 보관기간이 아니라 절대 상한이다(D85).
7. 상담 기억은 한 사업의 케이스에 한정된 내부 보조 맥락이다. 직접 출력, 독립 상세, 정정 화면은 별도 결정이다. 이 문서는 그 화면을 되살리지 않는다.
8. 진단, 지원 지속과 중단 판단, GAS 채점, 액션과 리스크 확정은 AI의 일이 아니다. 감정 계산과 AI 자동 양식 조립도 재개하지 않는다.

## 6. 검증을 자기확신으로 끝내지 않는 방법 (원문 요약)

1. 정답은 모델 출력이나 개발자 기대로 만들지 않는다. 현장 전문가가 독립적으로 만들고 다른 검토자가 이견을 확인한다.
2. AI가 표시한 것만 평가하지 않는다. 오탐과 전체 정답 중 놓친 것을 모두 세고, 자료 없음이나 처리 막힘은 정상 0건과 분리한다.
3. 문항, 정답, 기준값, 모델, 설정, 자료 hash와 분석 방법을 실행 전에 고정한다. 기존 S13 기준은 소급 변경하지 않는다.
4. 기존 방식과 새 방식 비교에는 난도가 비슷한 다른 사례를 쓰고 순서를 나눈다. 실패, 중단, 도움 개입도 결과에 포함한다.
5. 기능적 성공, 의미 정확성, 사용성, 시간 절감, 당사자 경험은 따로 보고한다. 참고 사례(Beam의 Magic Notes 검증 보고서)의 성과를 릴레이어 성과로 옮기지 않는다.

## 7. 추가로 고민할 부분 (원문 요약)

- 기록이 입력되지 않으면 AI도 맥락을 복원할 수 없다. "기존 시스템에 기록을 안 남긴다"는 팀 의견을 대표 통계로 쓰지 말고 B02, U14에서 확인한다.
- 기관 소유는 통제권을 주지만 운영 역량을 주지 않는다. "기관이 책임진다"와 "도움 없이 운영할 수 있다"는 다른 약속이다.
- 가림을 강하게 하면 도움에 필요한 맥락도 약해진다. 가림 후 유용성과 잔여 식별 위험을 각각 평가한다.
- 승인된 공식 기록도 현실의 진실을 보장하지 않는다. 당사자 진술, 실무자 관찰, 과거 상태, AI 관찰을 구분한다.
- 승인시간, 수정량, 기록량을 직원 성과나 당사자 위험 등급으로 전용하지 않는 원칙을 논의한다.
- 배포기관의 사이트, 기관 코드 안내, 업데이트 서비스가 중단돼도 기관이 자료를 읽고 회수, 종료할 수 있어야 한다.
- 기사나 심사자료에는 지원 조건, 미측정 영역, 실패 시 수기 경로를 함께 적는다.

## 8. 회의 기록과 실행으로 넘기는 규칙

먼저 12개 우선 묶음에서 결정 책임자와 필요한 자료를 정한다. 각 카드의 "회의 답변"에 아래 7항목을 남긴다. 검증 질문은 추측으로 닫지 말고 시험과 통과 조건을 남긴다. 새 기능이 필요하다는 결론은 별도 승인 후 기존 실행 티켓에 연결한다.

| 기록할 항목 | 작성 방법 |
|---|---|
| 카드 ID와 선택 | 예: A01 / 유지, 노출 조정, 중단 중 실제 선택 |
| 이유와 달라지는 사용자 경험 | 왜 택했고 무엇을 포기하고 보존했는지 |
| 담당자, 결정일, 기한 | 역할명이 아니라 실제 담당자와 날짜 |
| 적용 범위와 조건 | 모드, 사업, 자료, 사용자, 버전 |
| 필요한 검증과 증거 링크 | 무엇을 하면 통과와 실패인지, 결과를 어디서 보는지 |
| 정본과 티켓 연결 | 제품 결정은 ADR, 계약, 가이드에. 실행은 기존 티켓에 |
| 보류 시 재개 조건 | "나중에" 대신 대상 발생, 환경 변경, 시험 완료 같은 재개 사건 |
