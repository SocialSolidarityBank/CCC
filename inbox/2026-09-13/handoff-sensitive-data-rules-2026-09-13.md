## 1. 음성 인식(STT)

### 정한 것

- 처음 설치하면 음성 인식은 **꺼져 있다**. 손으로 쓴 기록이 바로 공식 기록이라 일은 멈추지 않는다.
- **기관 PC에서 돌리는 음성 인식**(로컬, Qwen3-ASR)은 이미 만들어져 있다. 녹음 파일이 기관 밖으로 안 나가는 유일한 방법이다.
- **Azure 음성 인식**은 코드에 서울 서버로 고정되어 있다. 다른 지역으로 바꾸면 서버가 막는다. 녹음 파일을 남기지 않는다.
- Azure는 "국외"가 아니라 "**외부 회사에 맡김, 처리는 국내**"라고 쓴다.
- **Azure를 앞으로 어떻게 둘지 (확정)**: 처음 설치하면 음성 인식은 꺼져 있다. 품질 확인을 통과하면 Azure(서울)를 기본으로 권한다. 녹음 파일을 기관 밖으로 내보내고 싶지 않은 기관은 기관 PC 음성 인식을 고를 수 있다.
- **Azure 켜는 순서 (확정)**: 연결 → 품질 확인을 바로 진행(모의상담 6개 파일로 정확도, 응답 시간, 비용 재기) → Q 승인 → 파일럿부터 사용. 관리자가 직접 켜고, 당사자에게 외부 음성 인식 동의를 따로 받는다.
- 녹음 파일은 다음 영업일에 처리한 뒤 바로 지운다. 7일이 넘으면 무조건 지운다(D85).
- 기관 PC 음성 인식이 안 될 때 Azure로 자동으로 바꾸지 않는다(D8).
- **동석자가 있어도 녹음할 수 있다 (확정)**. 동석자(가족, 보호자) 동의는 담당 실무자가 직접 받는다. 프로그램이 대신 받지 않는다. 동의서에 동석자 칸을 넣는다.
- **기관 PC 음성 인식 뒤 AI로 글 다듬기**: 기관 PC에서 글자로 바꾸고, 이름을 가린 뒤, AI에 보내 오타와 끊긴 문장을 고치는 방식. 녹음 파일은 안 나가고 글은 읽기 좋아진다. 설명서의 "계획" 칸에 적는다(확정). 구현은 제출 후.

### 안 정한 것

- (법률, MS 문의) Azure 계약 상대가 국내 법인인지, 해외 직원이 원격으로 볼 수 있는지, 학습에 안 쓴다는 조항이 어디 있는지, 말한 사람 구분이 생체정보인지
- (측정) 기관 PC 음성 인식의 노인, 사투리 정확도. 필요한 PC 사양
- (확인) 동석자까지 3명 이상일 때 Azure가 말한 사람을 잘 구분하는지(Azure는 2명으로 고정). 파일럿에서 본다

## 2. AI(글을 읽고 쓰는 AI)

### 정한 것

- 처음 설치하면 AI는 **꺼져 있다**. 설정값 5개와 동의가 다 있어야 켜진다. **하나라도 빠지면 AI가 멈춘다**.
- AI 회사는 **OpenAI 하나**. 다른 해외 AI는 안 붙인다.
- AI에 보내는 것은 **이름, 연락처, 주소를 지운 글만**. 위기도, 영역, 할 일 같은 선택값이 기본 재료다.
- OpenAI는 **국외**. 당사자에게 알리고 동의를 받는다.
- OpenAI에 "저장하지 마라"고 요청하지만, **오남용 감시 기록은 최대 30일** 남는다. "완전 무저장", "AI 무저장"이라고 쓰지 않는다.
- AI는 판단하지 않는다(R5). AI가 쓴 초안은 실무자가 승인해야 공식 기록이 된다.
- AI를 켜면 기관 PC 1대가 필요하다. 이름을 지우는 처리를 이 PC에서 한다.
- 자해, 폭력 같은 위기 발언은 지우지 않고 보낸다. 위험 신호를 잡는 것이 목적이다. 동의 문안에 적는다.
- **상담 기억은 저장만 하고 초안에는 쓰지 않는다**(9월 18일 전 설정 변경). 상담 기억 = AI가 여러 회차를 보고 자동으로 만드는 배경 메모. 지금은 실무자가 볼 수 없으므로 초안에 넣지 않는다. 넣었을 때와 뺐을 때를 따로 비교해서 도움이 되면 켠다.

### 안 정한 것

- (코드 확인) "저장하지 마라" 요청이 실제 호출 코드에 들어 있는지. 호출 주소가 고정이라 무보관 모드를 못 켜는 것은 제출 후 설정으로 뺀다
- (상담 기억) 동의 문안에 없음, 볼 수 있는 화면 없음, 비교 시험 안 함. 동의 철회와 정정 때 어떻게 하나(P08, P16)
- (없음) 편향 점검, AI가 틀린 것을 모으는 기록, 보내기 전 전화번호와 계좌번호 남았는지 검사
- (검증) 누락과 불일치 찾기 정확도

## 3. 저장소와 암호화

### 정한 것

- 저장은 **기관이 소유한 Supabase 서울 서버**. 사회연대은행은 볼 수 없다. 저장만으로는 국외 이전이 아니다.
- **암호화 두 번**: Supabase가 하는 기본 암호화(디스크) + 릴레이어가 저장 전에 스스로 잠그는 암호화.
- 지금 릴레이어가 잠그는 것은 **개인정보 금고 8칸만**(이름, 전화, 계좌, 이메일, 생년월일, 지역, 긴급연락처, 성별).
- 암호화 규칙 R1~R10 확정: 잠글 대상은 8칸 + 자유 글 전부 + 녹음 파일. 열쇠는 DB 밖에 둔다. 열쇠 번호를 기록한다. 암호문 바꿔치기를 막는다(AAD). 이름 검색은 검색용 지문으로 한다. 백업 파일도 암호문 상태를 유지한다. 로그에 원문을 남기지 않는다. 기관 PC 설치 모드도 같은 규칙.
- 설명서 문구: "기본 암호화 + 8종 앱 암호화 완료. 자유 글과 녹음 파일 앱 암호화는 구현 중. 지금은 접근 권한과 감사 기록으로 보호."
- 파기 규칙(0041)은 8칸만 지운다. 동의서와 안 맞는 부분은 9월 18일 전 **문안**으로 고친다.
- Supabase를 기관 서버에 직접 설치하지 않는다. 네이버 공공 클라우드는 제출 후 별도 결정.
- 9월 18일 전: 감사 기록 월간 집계(담당 아닌 당사자 열람 수, 암호 푼 수, 내보낸 수).

### 안 정한 것

- (구현 전) 자유 글, 요약, 전사 글, 녹음 파일 암호화. 열쇠 번호와 AAD. 지금은 전부 원문 그대로 저장
- (코드 미확인) 열쇠 위치, 검색용 지문, 로그 원문, 기관 PC 모드 적용 여부
- (없음) 회차 기록, 요약, 인테이크, 목표, 위험 신호 인용문의 파기 규칙
- (운영) 백업에서 파기한 자료가 되살아나지 않게(P09), 보존 기간 한 표(P15), 열람과 정정과 삭제 창구(P10), 사례 종결 파기 문구
- (보안) Next.js 취약점 업그레이드, 보안 응답 헤더, 미리보기 관문 무차별 대입 보호

## 4. 민감정보와 개인정보 규칙

### 정한 것

- **자료가 가는 곳 세 가지**: 기관 안 / 국내 외부 회사(Azure 서울, Supabase) / 국외(OpenAI). 동의 6영역은 그대로 두고 문구만 고친다.
- 대화를 민감/비민감으로 자동 분류하지 않는다. **설정 세 가지**(기관 설정, 메모 쓰는 규칙, 녹음 여부)로 미리 정한다.
- 권장 기본 조합: **음성 인식 끔 + AI 켬**. (Azure는 품질 확인 뒤 파일럿부터)
- **고유명사는 일반명사로 적기 (확정)**: OO병원 → 병원, OO공장 → 직장. 운영 지침과 첫 사용 안내에 넣는다. 화면 안내는 가림 v2(자동 변환) 전까지만 검토.
- 적는 방식: 이름과 연락처는 금고에만. 건강, 피해 경험 같은 법정 민감정보는 "종류만, 판단 근거만"(진단명 대신 "건강 문제로 근로 어려움"). 채무 상세는 금고와 반복표에만, 자유 글에는 안 적는다. 제3자(가족, 채권자)는 꼭 필요한 만큼만.
- 지금 가림(v1)은 **이름과 주소만** 찾는다. 기관 이름, 건강, 피해, 범죄 이력은 그대로 나간다. 동의 문안 v2에 "가린 뒤에도 건강, 피해 경험은 남아 전송될 수 있다"를 넣는다.
- 가림 v2 설계 확정(구현은 제출 후): 번호 가명 [인명1], 기관은 [의료기관]처럼 자동 변환, 나이는 5세 구간, 지역은 시도까지, 날짜는 "상담일 +N일", 보내기 전 검사.
- 화면과 등록 폼에 들어갈 문안 3줄(OpenAI, Azure, Supabase) 확정. 쓰지 않는 표현: "완전 무저장", "서울 저장이라 국외 이전 없음", "15초면 모두 파악", "CSAP 인증 지원".
- 제출 설명서는 "구현됨 / 구현 중 / 계획" 세 칸 표로 쓴다.
- 코드 이름과 ADR 용어는 안 바꾸고 문안만 바꾼다.

### 안 정한 것

- (법률) 채무, 소득, 주거의 법 적용(P04) / Azure 서울이 국외 이전인지(P05) / 가린 뒤 남는 민감정보의 전송 동의 범위 / 제3자 정보 수집 근거(P02)
- (문안 v2) 민감정보 동의 예시에서 채무와 주거를 빼고 범죄경력, 성폭력 피해 같은 법정 범주로 고치기. 상담 기억을 동의 문안에 넣기. 동석자 동의 칸 추가
- (운영) 최소 수집표(P01), 미성년자와 대리인(P03), 기관별 책임(P05), 유출 대응(P11), 지원자의 원문 접근(P12), 반출 책임(P13), 검증 자료 분리(P17)

## 6. 9월 13일 결정 기록

1. 상담 기억: 저장만 하고 초안에는 안 씀
2. 동석자 있어도 녹음 가능. 동의는 담당 실무자가 받음

5. "고유명사는 일반명사로 적기" 승인. 운영 지침에 넣음
6. Azure를 앞으로 어떻게 둘지: 설치 기본은 끔, 품질 확인 통과 뒤 Azure(서울)를 기본으로 권함, 기관 PC 음성 인식은 녹음 파일을 안 내보내려는 기관용

## 7. 바꾼 이름 (이 문서 기준)

| 전 | 후 |
|---|---|
| 그림자 모드 | 상담 기억: 저장만 하고 초안에는 안 쓰기 |
| fail-closed | 하나라도 빠지면 AI가 멈춘다 |
| 세 층 | 자료가 가는 곳 세 가지 |
| 밸브 3개 | 설정 세 가지 |
| 두 겹 원칙 | 암호화 두 번 |
| 2단계 AI 교정 | 기관 PC 음성 인식 뒤 AI로 글 다듬기 |
| 실측 | 품질 확인 |
| 기본 외부 경로 | 기본으로 권한다 |
| 로컬 STT | 기관 PC 음성 인식 |
| 종류로 적기 | 고유명사는 일반명사로 적기 |

코드 식별자(`sttMode`, `llmMode`, `ner-mask-v1`)와 ADR 번호는 그대로다. 문안과 설명에서만 위 이름을 쓴다.
