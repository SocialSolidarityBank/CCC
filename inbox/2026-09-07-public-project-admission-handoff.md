## 1. 확정된 방향

**판단은 사용기관이 하고, CCC는 정확히 고지한다**(D63). 배포기관이 계약서를 받아 심사하지 않는다. 기록지(계약서 확인표)는 만들지 않는다.

기관 가입 뒤 **사업을 등록할 때** 관리자가 두 가지를 고른다. 질문으로 결과를 계산해 주지 않고, 선택지에 설명을 붙인다.

### 사업 등록 폼, 라디오 2구획 (관리자만)

**데이터 저장 위치**
- 기본형 (Supabase 서울): 기관 자체 예산 사업이거나, 발주처가 클라우드 종류나 보안 인증을 따로 요구하지 않는 사업
- 네이버 클라우드 공공형: 정부, 지자체, 공공기관에서 위탁이나 용역으로 맡긴 사업이고, 발주처가 국내 공공 클라우드나 CSAP 인증을 요구하는 경우. **다음 구현 작업**이며 이번 범위에서 빼지 않는다
- 나중에 정하기: 사업은 만들어지되 합성·연습만 되고 실데이터는 잠긴다. 설정 화면에 `설정 필요` 배지

**녹음과 AI 정리**
- 외부 업체 처리 허용 (STT: Azure, AI 정리: OpenAI, 마스킹 후): 계약서에 외부 처리, 재위탁, 국외 이전을 막는 조항이 없는 사업
- 기관 안에서만 처리: 계약서가 외부 처리를 금지하거나 확인하지 못한 사업. STT는 `local`만, LLM `off`
- 나중에 정하기: 위와 같음

각 구획 아래 `확인하는 법` 링크 하나. 폼 아래 안내 한 줄: "발주처가 정해 준 업무 시스템이 있으면 CCC 기록은 보조 기록입니다."

마지막에 체크: **"위 선택은 우리 기관이 계약 조건을 확인하고 정한 것입니다"** → 관리자 이름, 시각, 설명 문안 버전이 `audit_log`. 선택을 바꾸거나 STT·LLM 설정이 바뀌면 다시 체크.

기본 선택 없음. 미선택은 저장 불가가 아니라 `나중에 정하기`로 둔다(억지로 고르게 하는 것이 더 위험).

### 모를 때 돕는 세 층 (셋 다 한 벌)

| 층 | 무엇 | 답하는 질문 |
| --- | --- | --- |
| 라디오 | 기본형 / 공공형 / 나중에 정하기 | 우리 사업은 어느 쪽인가 (기관이 고른다) |
| `확인하는 법` 링크 → 매뉴얼 1장 | 용어 풀이(CSAP, 처리위탁, 재위탁), 계약서에서 볼 조항 이름, 물어볼 부서 | 이 말이 무슨 뜻인가 |
| 매뉴얼 안 "AI에게 물어보기" 절 | 조언형 복붙 프롬프트 | 우리 계약서 어디를 보면 되나 |

### 조언형 프롬프트 (매뉴얼에 그대로 실을 문안)

> 아래 문서를 읽고 다음 세 가지를 찾아 표로 정리해 주세요. **어느 쪽을 고를지 판단하지 말고**, 해당 조항이 있으면 조항 번호와 원문을, 없으면 "찾지 못함"이라고만 적어 주세요.
> 1. 발주처가 특정 클라우드, 국내 공공 클라우드, 또는 CSAP 같은 보안 인증을 요구하는 조항
> 2. 개인정보를 외부 업체에 맡기는 것(처리위탁, 재위탁), 국외로 보내는 것을 제한하거나 금지하는 조항
> 3. 발주처가 정해 준 업무 시스템을 써야 한다는 조항
>
> 각 항목 끝에 "이 조항을 최종 확인할 부서"를 한 줄로 제안해 주세요(예: 발주처 사업 담당, 우리 기관 개인정보 담당).
>
> [여기에 계약서, 과업지시서, 보안 서약서 내용을 붙여 넣으세요]

출력은 사실 표이고 고르는 것은 사람이다. 계약서를 LLM에 넣는 것은 기관 안에서 기관이 하는 일이라 CCC 파이프라인(R3)과 무관하다.

## 2. 버린 것과 이유

- 8문항 심사표(법적 성격, 개인정보처리자, 법령 근거, 국외 처리 세부, 정보 종류, 보관기간): 담당자가 답할 수 없거나 결과를 바꾸지 않는다. 답하면 판단이 우리 쪽으로 넘어온다
- 4문항 질문식(2026-09-07 1차 제안): 답을 표로 계산해 결과를 내는 순간 같은 문제. 선택식이 이긴다
- 사업별 계약서 확인 기록지: 사용기관 내부 서류다
- 경기극저신용 사업의 개별 심사: 우리 기관도 사용기관으로 같은 화면에서 같은 선택을 한다. 개발상 따로 관리하지 않는다

## 3. 번호와 충돌

- 초안의 ADR-0044는 2026-09-06 #282로 머지된 ADR-0044(D86 온보딩)와 충돌한다. 이 결정은 **ADR-0045 / D87**이다
- 루트 워크트리 `main`의 미커밋 변경(`CLAUDE.md` §8 한 줄, `ADR-0041` 후속 주석, `CCC_OPEN_PILOT_PLAN.md` 절, untracked `docs/adr/0044-…`, `docs/policy/…`)은 폐기 초안이다. 새 레인에서 다시 쓰고 루트 것은 건드리지 않는다
- 기존 `program_type`(`financial_support_v1` = 상담 양식)과 이번 축(저장 위치, 처리 경로)은 별개다. 사업(program) 단위로 두 값을 갖는다
